# DCP2

Сервер DCP2 связывает сетевые команды с рабочими экземплярами сервисов.
Во FreeRTOS он получает эти экземпляры из `bvstk_runtime`, а в Нейтрино
работает внутри процесса `bvstkd`. Состав подключённых сервисов у приложений
различается. Общая схема обращений клиента приведена во
[введении в DCP2](../../reference/dcp2/01-intro.md).

## Результат операции

При записи I²C сервер декодирует адрес `0x2A`, регистр `0x10`
и значение `0x7B`, находит устройство и вызывает сервис. Политика
может запретить запись ещё до запуска master-драйвера. Ответ содержит
статус этой операции. Для разрешённой записи статус драйвера
описывает выполненный обмен в пределах контракта шины.

Потеря TCP-соединения после отправки запроса не сообщает, успела ли
операция изменить устройство. Новый `seq` не обеспечивает устранение
повторной записи. Клиент выбирает повтор с учётом побочных эффектов
команды; правила и ограничения приведены в [контракте DCP2](../../reference/dcp2/02-frame.md).

## Файлы, кэш и события

Большой файл не помещается в один кадр. FS предоставляет дескриптор
потока и чтение порциями; этот дескриптор связан с TCP-соединением.
После разрыва клиент открывает поток заново. В текущем сервере
FreeRTOS FS предоставляет чтение, а в `bvstkd` не подключён.

CACHE даёт снимок программного кэша и подписку на его изменения.
Он не начинает физическое чтение каждого регистра. Снимок и курсор
связывают начальное состояние с последующими изменениями.
Переполнение истории и смена конфигурации требуют обновить снимок.

Управляющие уведомления, наблюдения реального обмена и тестовые потоки
имеют разные источники. Тестовый поток SPI генерирует данные для проверки
доставки и не означает наличие работающего SPI-сервиса. Сопоставление
с состоянием системы дано в [главе о наблюдении](../observation/observation.md).

Расположение DCP2 внутри сетевого пакета и структура сообщения показаны
в [главе о кадре](../../reference/dcp2/02-frame.md).
Команды клиента приведены в [практике DCP2](../../operations/dcp2.md).
