# HTTP

HTTP-сервер BVSTK отдаёт статические файлы веб-интерфейса
и обрабатывает API. Запрос сначала проходит разбор метода, пути
и параметров. Далее маршрут выбирает сервис устройства, конфигурацию,
журнал или файловый слой.

Текущие маршруты `/api/ui/bus` адресуют устройства по шине и имени.
Запрос состояния читает рабочую конфигурацию, запрос кэша — уже
сохранённые значения. Явные команды чтения и записи вызывают физическую
операцию сервиса. Одинаковый адрес HTTP-сервера не делает эти действия
равнозначными по побочным эффектам.

Редактирование конфигурации использует ревизию: сервер сравнивает
состояние, которое видел редактор, с текущим. Устаревшее изменение
отклоняется. Сохранение профиля выполняется отдельной операцией,
как описано в [жизненном цикле конфигурации](../configuration/configuration.md).

Маршруты прежнего интерфейса продолжают существовать. У них собственная
форма запроса и ограничения, поэтому поля нового UI нельзя переносить
в них механически. Маршруты, поля запросов и примеры вызова описаны
в [главе HTTP](../../interfaces/http/http.md).

## Общие обработчики двух ОС

HTTP Нейтрино запускается отдельным потоком внутри `bvstkd` и использует
те же экземпляры I²C/MDIO, что DCP2 и локальный CLI. Обе сборки используют
общие обработчики устройств, снимков кэша, наблюдений, файлов и системных
операций в `src/protocols/http/`. Транспорт и доступ к сервисам предоставляет
адаптер приложения. Сетевой ввод-вывод выполняется вне блокировок состояния.

Web UI получает ОС, настоящие показатели и возможности через `/api/runtime`.
Прежний `/api/rtos` сохраняется во FreeRTOS. В Нейтрино не подставляются
показатели heap/tick FreeRTOS; показываются PID и число процессоров.
Неподключённая SD-PL явно обозначается как неподдерживаемая.

Статические ресурсы устанавливаются из общего `web/assets` в `flash:/www`
(`/flash/www` в Нейтрино). Профили и дополнительные ресурсы устройств
остаются в соответствующих каталогах `config`. Сам запуск HTTP не заменяет
пользовательские профили или содержимое томов.

Совместимые прямые URL `/flash/...`, `/sd/...` и GET/PUT `/tar/...`
работают в Нейтрино через общий файловый слой. Извлечение TAR использует
тот же проверяющий имена архиватор, что CLI, и не является транзакцией.
`/api/i2c` сохраняет прежнюю проекцию профилей и применение только в RAM.
Диагностический доступ MEM ограничивается портом памяти соответствующей ОС.
В ответах Нейтрино поля FAT `date/time` равны нулю (нет сведений):
служебный POSIX stamp используется только как признак изменения файла.
