# Драйверы SPI и SD

[Ядро](../cores/master.md#приём-блока) опубликовало ответ CMD17
и блок LBA 32. Следующий этап примера —
[проверка результата](master.md#получение-блока) общим `bvstk_sd_master`.
Он управляет `SPI_master_0`, `axi_dma_0` и буферами BRAM в рамках
одной операции. Данные становятся доступными сервису после
сопоставления аппаратных событий и проверки содержимого.

У драйвера три отображения MMIO: регистры SPI master, регистры DMA
и BRAM банка 0. Адреса берутся из конфигурации порта, сформированной
по XSA. В рассматриваемой аппаратной схеме банк 0 начинается
с `0x44000000`.

## Области BRAM

| Смещение | Назначение |
|---|---|
| `+0x0000` | Семь слов результатов инициализации |
| `+0x0034` | Ответ CMD13 |
| `+0x0038` | Ответ CMD16 |
| `+0x003C` | Ответ CMD17 |
| `+0x0044` | Ответ CMD24 |
| `+0x0400` | Дескриптор и передаваемые данные |
| `+0x1000` | Принимаемый блок с CRC16 |

Перед операцией в ответы записывается контрольное значение,
а вокруг буферов — защитные слова. Это позволяет заметить старый
ответ и выход записи за ожидаемую область. BRAM здесь служит
буфером конкретной операции; достоверность результата определяет
завершающая проверка драйвера.

[Ведущая часть](master.md) раскрывает инициализацию, CMD17 и CMD24.
[Порт ОС](ports.md) описывает IRQ, память и взаимное исключение.
[Ведомая часть](slave.md) фиксирует границу между имеющимся PL-ядром
и отсутствующим обслуживанием этой стороны в PS.

В исходниках также есть `bvstk_spi_core` для обычных передач слов
через регистровый интерфейс. Он описан [отдельно](raw.md), поскольку
профиль AX7020 не запускает его аппаратный путь. Одновременное
управление одним master двумя драйверами не предусмотрено.
