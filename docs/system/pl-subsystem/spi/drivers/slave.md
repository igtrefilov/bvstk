# Программное обслуживание SPI slave

В текущем BVSTK аппаратный `SPI_Slave_0` не обслуживается отдельным
PS-драйвером. Рабочая среда не настраивает для него `axi_dma_1`,
не подаёт ответы и не устанавливает обработчик IRQ slave.
Это относится к рассматриваемым сборкам FreeRTOS и Нейтрино.

Название `bvstk_spi_core` может создавать обратное впечатление,
но этот модуль открывает только регистры **master** и его BRAM.
Ведущий драйвер SD также использует `SPI_master_0` и `axi_dma_0`.
Ни один из них не выполняет роль ведомого драйвера.

Аппаратные направления и состав FIFO показаны в
[описании slave](../cores/slave.md). На этой границе пока заканчивается
действующий путь: нет программного разбора входящего кадра,
модели ведомого SPI-устройства, публикации ответа или применения
политики к принятой записи.

Переиспользовать схему ведомого I²C-драйвера здесь буквально
нельзя: SPI не предоставляет ожидание ответа с удержанием SCL,
а существующий поток slave требует отдельного соглашения о длине
и границах сообщения. Структура PL уже определяет два направления
данных, но законченного сервиса моста поверх них в PS ещё нет.
