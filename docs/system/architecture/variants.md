# Возможности сборок

Таблица относится к штатным сценариям текущего дерева BVSTK и аппаратному
контракту AX7020 версии `3`. Она описывает подключение реализаций, а не результаты
последнего испытания платы. Состав реально загруженного bitstream нужно
проверять отдельно.

Целевое поведение обеих ОС, допустимые различия и приёмочные сценарии
зафиксированы в [общем контракте FreeRTOS и Нейтрино](common-contract.md).

## Программные службы

| Возможность | FreeRTOS | Нейтрино |
|---|---|---|
| TCP-консоль BVSTK | Да, `8888/TCP` | Нет; используется оболочка ОС |
| SSH | Опционально, wolfSSH, `22/TCP` | OpenSSH в штатном IFS, `22/TCP` |
| HTTP API и статические страницы | Да, `80/TCP` | Не входят в `bvstkd` |
| Web UI, карты регистров, формы и пиктограммы | Подключены через HTTP и файлы пакетов | HTTP и раздача ресурсов не подключены |
| DCP2 | Да, `8889/TCP` | Да, `8889/TCP` |
| DCP2 PING и регистры I²C | Да | Да |
| DCP2 MEM | 8/16/32/64 бита; общий обработчик AUTOINC | Общий обработчик; 8/16/32/64 для BRAM, 32 для регистров управления |
| DCP2 POLICY по ID устройства и ресурса | I²C и MDIO | I²C и MDIO; явный SAVE |
| I²C master/slave, профили v2, маршруты и адресные пространства | Подключены | Общие драйверы, сервисы и снимок конфигурации; поддержаны адресные селекторы пространств |
| MDIO-мост, политика, кэш и опрос PHY | Подключены | Подключён отдельный runtime и фоновый pthread; регистры и политики доступны через DCP2 |
| Фоновая проверка присутствия I²C | Задача `i2c_health` | Фоновый поток; одна проверка каждые 250 мс по кругу устройств |
| Сбор данных по `profile.acquisition` | Подключён для I²C/MDIO | Подключён в независимых потоках I²C/MDIO через общий движок |
| Внутренний кэш I²C | Да | Да |
| Общий каталог и DCP2 CACHE | Снимки и подписки I²C/MDIO | Общий каталог, снимки и подписки I²C/MDIO; изменения доставляются без новых запросов |
| Журналы событий и телеметрии BVSTK | Общий сервис журналов, HTTP и DCP2 NOTIFY | Тот же сервис журналов; пассивный `bvstkctl observe` через `/dev/bvstk-observe` |
| DCP2 FS | Чтение томов, метаданных, файлов и деревьев, TAR | Не подключён; `ERR_UNSUPPORTED` |
| DCP2 NOTIFY и тестовые потоки | Да | Не подключены в текущем сервере |
| Файлы QSPI | `flash:/`, FatFs | `/flash`, файловый стек ОС |
| Файлы PS SD | `sd:/`, FatFs | `/sd`, файловый стек ОС |
| Файлы SD через PL | `sd-pl:/`, FatFs и SPI/DMA-сервис | Сервис и том не подключены |
| I²C-конфигурация | `flash:/config/i2c/` | `/flash/config/i2c/` |
| MDIO-конфигурация | `flash:/config/mdio/` | `/flash/config/mdio/` |
| Изменения I²C из локальной консоли | RAM; явный `save` для сохранения | RAM; явный `save` для сохранения, включая достоверные записи кэша |
| Сетевая конфигурация | `network.json`, команды `ip`, HTTP | Сценарий IFS и средства ОС |
| Автономная установка средствами проекта | `BOOT.bin`, запись QSPI и проверка | Штатного сценария автономной установки нет; IFS загружается через JTAG |

Новый сервис DCP2 POLICY и прежние команды изменения списков политики
Нейтрино меняют правила в RAM; сохранение выполняется отдельной командой.
Прежние DCP2 I²C WRITE_REG и POLICY_SET также меняют только RAM.
Явный SAVE политики сохраняет настроенные начальные значения кэша;
консольный I²C save предварительно захватывает достоверные записи.
Изменения прежнего поведения описаны в
[изменениях совместимости](common-contract.md#изменения-совместимости-нейтрино).

В Нейтрино I²C и MDIO инициализируются независимо. Неверный набор
профилей или отказ аппаратной инициализации отключает только эту
подсистему; DCP2 PING, MEM и готовая соседняя подсистема продолжают работать.
Не готовые регистровые сервисы возвращают DCP2 `ERR_BUSY`.
MDIO CLI пока не подключён; для регистров и политик используется DCP2.
Диагностика `i2c <device> info` читает состояние присутствия, число
достоверных записей кэша и счётчики фоновых операций без чтения шины.
Общий каталог подключается до IRQ и фоновых потоков. Источники `settings`,
`device` и `unknown`, присутствие и время обновления сохраняются отдельно.
Неподтверждённая телеметрия, presence probes и acquisition не засоряют
пользовательские журналы. HTTP и DCP2 NOTIFY в Нейтрино пока не подключены.

Адрес в исходной сетевой конфигурации FreeRTOS и штатном IFS Нейтрино —
`192.168.0.10`. Сохранённые параметры FreeRTOS могут его заменить. Номер
устройства UART на компьютере не фиксирован; `115200 8N1` относится к
настройке линии. JTAG-сценарий Нейтрино выбирает стабильное имя адаптера
из `/dev/serial/by-id`, а при необходимости принимает `UART_DEVICE`.

## Аппаратные возможности PL

Значения описывают аппаратный контракт. Следствия в таблице относятся
к текущему подключению FreeRTOS; наличие признака не запускает
соответствующий сервис Нейтрино.

| Признак в `bvstk_hw_config.h` | Значение | Следствие |
|---|---:|---|
| `BVSTK_PL_HAS_I2C_CORE` | `1` | Подключается ведущий и ведомый путь I²C |
| `BVSTK_PL_HAS_MDIO_CORE` | `1` | В обеих ОС запускается MDIO-worker с политиками и кэшем |
| `BVSTK_PL_HAS_SPI_CORE` | `0` | Обычный SPI-сервис не запускается |
| `BVSTK_PL_HAS_SD_CONTROLLER` | `1` | Доступен SD-видимый узел по адресу SPI master |
| `BVSTK_PL_SD_INIT_ONLY` | `1` | Узел предоставляет последовательность инициализации карты |
| `BVSTK_PL_SD_CAN_INIT` | `1` | Доступна команда FreeRTOS `sd-pl init` |
| `BVSTK_PL_SD_CAN_BLOCK_IO` | `0` | Старый register-controller I/O отключён; FatFs использует отдельный SPI/DMA-сервис |
| `BVSTK_PL_SD_CAN_FILESYSTEM` | `1` | Доступен том `sd-pl:/` через SPI/DMA-сервис |
| `BVSTK_PL_SD_AUTOSTART_FILESYSTEM` | `1` | Карта автоматически инициализируется и монтируется без форматирования |

Тестовый поток `mdio`, `spi` или `uart` не обращается к физической шине и
может работать независимо от этих признаков. Он не является заменой
отключённого драйвера. Обычные запросы SPI/UART в текущем DCP2 не реализованы;
формат передачи SPI из старых материалов не является доступной операцией.

## Различия диагностического доступа

HTTP разрешает MMIO только в окнах включённых узлов. В текущем FreeRTOS
`BVSTK_DCP2_ALLOW_ANY_MEM_ACCESS=1`: DCP2 MEM проверяет формат, ширину,
выравнивание и границы 32-битного адресного пространства, но не существование
аппаратного узла. Неверный адрес способен вызвать аппаратное исключение
или зависание. Нейтрино использует таблицу PL-регионов; в ней есть также
имена выключенных узлов. Список регионов нельзя использовать как результат
обнаружения оборудования.

TCP-консоль, HTTP и DCP2 не аутентифицируют клиента. FreeRTOS SSH проверяет
заданный при сборке пароль; штатный IFS Нейтрино использует ключи и допускает
отдельную настройку локального пароля. Файлы `inetd.conf` с примерами Telnet
и FTP присутствуют в BSP, но их наличие не означает запуска `inetd` в
выбранном IFS. Доступные службы проверяют по его сценарию и на устройстве.
