# Общий контракт FreeRTOS и Нейтрино

Целевой контракт версии 1 задаёт одинаковое поведение BVSTK под FreeRTOS
и Нейтрино: профили устройств, операции сервисов, команды, API и Web UI.
Его исходная точка — ревизия `01e7c34` от 27 октября 2026 года,
AX7020 и аппаратный контракт PL версии `3`.

Действующее подключение функций и текущие исключения перечислены
в [возможностях сборок](variants.md). Наличие общего исходника в списке
компиляции подтверждает возможность повторного использования кода;
работающая функция также требует подключения сервиса и его адаптеров.

## Общая модель системы

У каждой подсистемы один владелец рабочего состояния. Во FreeRTOS
экземпляры создаёт рабочая среда приложения. В Нейтрино I²C, MDIO,
их политики, кэш, фоновые работники и журнал принадлежат `bvstkd`.
HTTP, DCP2 и локальные клиенты используют эти экземпляры через общий
API управления. Новое соединение не создаёт отдельную политику устройства.

Разбор команд, правила доступа, представление профиля и формирование
ответов размещаются в общих модулях. Порты предоставляют MMIO, IRQ,
время, блокировки, транспорт и доступ к носителю. Имена процессов,
потоков и системных устройств могут различаться между ОС.

Один набор `configs` задаёт ID устройств и ресурсов, топологию,
параметры обмена, политики, карты регистров и дополнительные скрипты.
Обе сборки используют один набор `web/assets`. Готовность сервиса,
присутствие устройства и достоверность кэша сообщаются раздельно.

## Целевые возможности

Приёмочные сценарии из последнего столбца определены в разделе
[проверки контракта](#проверки-контракта). Полный аппаратный паритет
проверяется на согласованном комплекте bitstream и программ.

| Возможность | Требование к обеим сборкам | Проверки |
|---|---|---|
| Профили | Одинаковые ID, формат v2, маршруты, адресные пространства, проверка ограничений и восстановление настроек | CFG-LOAD, CFG-SAVE |
| I²C | Ведущий и ведомый тракт, общая политика, кэш и маршрутизация | BUS |
| MDIO | Мост Clause 22, политика с масками, кэш и обработчик обменов | BUS |
| Присутствие и acquisition | Фоновая проверка ответов и чтение групп ресурсов по профилю | POLL |
| Кэш | Общий каталог, источники значений, снимки и история изменений | CACHE |
| Наблюдения | Журналы событий и телеметрии, курсоры, фильтры и учёт потери истории | OBS |
| DCP2 | PING, MEM, I²C, MDIO, POLICY, CACHE, FS, NOTIFY и тестовые потоки | MEM, POLICY, DCP, STREAM |
| Команды BVSTK | Общая грамматика операций с устройствами и одинаковое применение и сохранение | CLI, CFG-RAM, CFG-SEED |
| HTTP | Общие маршруты устройств, файлов, наблюдений, сети и обслуживания | HTTP |
| Web UI | Общие страницы, дерево устройств, формы, карты, пиктограммы и сообщения о состоянии | UI |
| QSPI и PS SD | Общие логические тома с адаптацией FatFs или файловых средств ОС | FS |
| Сеть и перезапуск | Действующие и сохранённые параметры, одинаковые результаты операций управления | SYSTEM |
| SD через PL | Блочные операции, монтирование существующего тома и общий файловый доступ | SD-PL |
| Установка | Воспроизводимый комплект, JTAG и выбранный способ автономной загрузки | BOOT |

Обычные шинные команды SPI и UART в этот объём не входят: текущая
FreeRTOS их не предоставляет через DCP2. Тестовые потоки остаются
отдельной возможностью с явно указанным искусственным источником данных.
MQTT и SNTP не входят в обязательный паритет штатного запуска.

## Настройки и физические операции

Работа с устройством разделяется на четыре действия:

| Действие | Рабочая конфигурация | Файл профиля | Физическое устройство |
|---|---|---|---|
| Редактирование черновика | Прежняя | Прежний | Без обращения |
| Применение настроек устройства | Новая после проверки | Прежний | Без записи разрешённых значений |
| Явное сохранение | Действующая | Запись действующей конфигурации | Без нового чтения или записи |
| Чтение или запись регистра | Проверка по действующей конфигурации; обновление состояния по результату | Без автоматического сохранения | Обмен по правилам сервиса |

Изменение политики не выполняет разрешённую ею физическую запись.
Отказ политики происходит до запуска аппаратного обмена. Изменение
топологии, адресных пространств и параметров передачи требует перезапуска;
команда изменения адреса действует только там, где её допускает сервис.

Ошибка сохранения не отменяет уже применённые настройки RAM.
Пользователь получает результат записи файла отдельно от результата
применения. `saved:true` означает подтверждённое соответствие рабочей
конфигурации сохранённой; при невозможности прочитать сохранённое состояние
HTTP может вернуть `saved:null` по действующему контракту маршрута.
Запись физического регистра сама по себе не подтверждает сохранение.

Сохранение сохраняет ID, маршруты, ресурсы, оба списка политики
и имена дополнительных файлов. Содержимое `settings.cache_seed`
зависит от выбранной операции, одинаково для обеих ОС:

| Операция сохранения | Начальные значения кэша |
|---|---|
| Консольное `i2c <device> save` | Предварительно захватывает достоверные записи кэша по существующим правилам I²C |
| Консольное `mdio <device> save` | Сохраняет настроенный список начальных значений |
| DCP2 POLICY SAVE и прежний POLICY_SAVE | Сохраняют правила без захвата текущего кэша |
| HTTP save | Сохраняет подготовленную рабочую модель без дополнительного захвата |

Форматы и ограничения сохранения определяются
[жизненным циклом профиля](../../configuration/lifecycle.md) и
[примером изменения политики](../../configuration/examples/editing.md).
Сохранённые пользовательские файлы имеют приоритет над встроенными
значениями. Ошибочный найденный профиль останавливает загрузку набора
подсистемы; её ошибка не должна останавливать остальные интерфейсы BVSTK.

Сетевые команды сохраняют собственный контракт. Консольные команды
`ip ... set` включают попытку сохранения. `PUT /api/net` обновляет модель,
пытается сохранить её и при `apply:true` применяет параметры. Поля
`saved` и `applied` независимы; `apply:false` сохраняет параметры
для следующего запуска. Правило отдельного `save` для устройств
не меняет эти операции сети.

## Команды BVSTK

Общая грамматика I²C и MDIO берётся из
[справочника консоли](../../interfaces/console.md).
Она включает список устройств, сведения об устройстве, чтение и запись,
просмотр и изменение политик, явное сохранение, историю и дополнение
строки. ID устройства служит устойчивым селектором. Выбор по адресу
допускается при однозначном разрешении; для нескольких пространств
поддерживаются имя устройства с `<space>:<reg>` и адресный селектор
чтения или записи по правилам FreeRTOS.

Успешные данные, классы ошибок и указание несохранённых изменений
одинаковы. Допустимы разные окончания строк, приглашения и оформление
терминала. Файловые, сетевые и PL-команды BVSTK имеют совместимые
пользовательские операции; системные утилиты Нейтрино остаются доступны
через её оболочку. Новый разбор команды не создаёт экземпляр драйвера
устройства в клиентском процессе.

## API и протоколы

### DCP2

Сохраняются [формат кадра](../../interfaces/dcp2/reference/frame.md),
коды сервисов и операций, порядок байтов и размеры действующих полей.
Подключаются общие обработчики
[регистровых команд](../../interfaces/dcp2/reference/commands.md),
[POLICY](../../interfaces/dcp2/reference/policies.md),
[CACHE](../../interfaces/dcp2/reference/cache.md),
[FS](../../interfaces/dcp2/reference/fs.md) и
[событий](../../interfaces/dcp2/reference/events.md).
Прежние команды политики сохраняются вместе с адресацией по ID.
DCP2 FS остаётся интерфейсом чтения файлов, каталогов и TAR.

Для MEM при `AUTOINC=0` каждый элемент обращается к исходному адресу;
при `AUTOINC=1` адрес увеличивается на `width / 8` байт. Целевые
разрядности — 8, 16, 32 и 64 в разрешённых для них областях.
Неподдерживаемая разрядность возвращает `ERR_UNSUPPORTED` до обращения
к памяти. Границы, выравнивание и размер проверяются до аппаратного
доступа. Набор разрешённых областей задаёт порт; произвольный доступ
FreeRTOS к 32-битному адресному пространству не является требованием
к Нейтрино. Передача 64-битного значения не обещает атомарную
64-битную аппаратную операцию.

Сессии снимков, подписок и файлов имеют согласованные правила
истечения, повторного запроса и освобождения после разрыва соединения.
Числовые ID сессий и курсоры относятся к конкретному экземпляру
сервера и не сравниваются между ОС или после перезапуска.

### HTTP

Общий набор включает существующие `/api/ui/bus`, `/api/ui/observe`,
`/api/ui/volumes`, `/api/ui/files`, `/api/ui/file`, `/api/ui/sd-pl`,
`/api/net`, `/api/version`, `/api/reboot`, совместимые маршруты I²C
и диагностического доступа. Сохраняются GET и PUT, форматы успешных
ответов, ревизии конфигурации и подтверждения действий, заданные
[справочником HTTP](../../interfaces/http/http.md).
Новые общие обработчики проверяют формат запроса до изменения состояния.

Для устройства `apply` и `save` остаются отдельными действиями.
Проверка ревизии предшествует изменению; устаревший снимок возвращает
HTTP 409 и оставляет рабочее состояние прежним. Ошибки прежних маршрутов
не получают новый формат без сохранения совместимости клиента.

Для общей страницы системы вводится целевой `GET /api/runtime`.
Он отсутствует в базовой ревизии. Его обязательные поля:

| Поле | Тип и смысл |
|---|---|
| `schema_version` | Целое `1`, версия этого ответа |
| `os` | Строка `freertos` или `neutrino` |
| `uptime_ms` | Целое, время работы системы в миллисекундах по часам порта |
| `capabilities` | Объект логических признаков подключённых функций |
| `os_details` | Объект показателей, имеющих смысл для указанной ОС |

Обязательные ключи `capabilities`: `i2c`, `mdio`, `presence_poll`,
`acquisition`, `cache`, `observe`, `dcp2_fs`, `dcp2_notify`,
`dcp2_stream`, `http`, `sd_pl`, `network_config`, `reboot`.
Значение `true` означает, что функция подключена и её запуск предусмотрен
сборкой. Её текущая готовность сообщается соответствующим сервисом.
Неподключённый сервис MDIO не получает `true` только из-за компиляции
его исходника; отсутствие карты SD не превращает поддержку SD в `false`.

Действующий `/api/rtos` сохраняется во FreeRTOS для прежних клиентов.
Общий Web UI получает сведения о среде через `/api/runtime`.
В `os_details` FreeRTOS сохраняются `tick_rate_hz`, `heap_free`
и `heap_min_ever`. Нейтрино предоставляет собственные показатели;
неприменимые показатели отсутствуют и не заменяются вымышленными нулями.

## Готовность и ошибки

Состояния в таблице задают смысл результата. Их представление на проводе
сохраняется по справочнику соответствующего маршрута или сервиса.

| Состояние | Общее поведение |
|---|---|
| Функция не подключена | Признак возможности `false`; DCP2 возвращает `ERR_UNSUPPORTED` |
| Сервис подключён, но не готов | Признак возможности остаётся `true`; HTTP 503, DCP2 `ERR_BUSY` для команд управления |
| Ресурс занят | HTTP 423, DCP2 `ERR_BUSY`; успех не подтверждается |
| Неизвестный объект | HTTP 404; DCP2 использует код своего сервиса: например, FS NOT_FOUND или CACHE NOT_FOUND |
| Неверный формат или диапазон | Отказ до обращения к устройству; HTTP 400, DCP2 MALFORMED или RANGE по формату команды |
| Отказ политики | HTTP 403 или DCP2 `ERR_DENIED`, физическая запись не запускается |
| Таймаут | HTTP 504 или DCP2 `ERR_TIMEOUT`; прежнее значение кэша не выдаётся за новое измерение |
| Устаревший снимок | HTTP 409 для редактирования; DCP2 сохраняет отдельные статусы CACHE и POLICY |
| Носитель недоступен или запись файла не удалась | Ошибка файловой операции; уже применённая конфигурация RAM сохраняется |
| Присутствие устройства не проверено | Отдельное состояние присутствия; профиль или начальные значения не подтверждают ответ |

Статусы FS, CACHE и POLICY имеют собственные коды по
[справочнику DCP2](../../interfaces/dcp2/reference/statuses.md).
HTTP-ошибки определяются
[общими правилами](../../interfaces/http/reference/common.md).
Отказ или разрыв соединения не гарантирует откат уже выполненной
физической записи. Повтор операции после потери ответа должен учитывать
её возможное выполнение.

## Общий вид и допустимые различия

Общие страницы используют одинаковые названия разделов, порядок
операций, карточки устройств, пиктограммы, формы, сообщения об ошибках
и различение RAM и сохранённого состояния. Кнопки и показатели
соответствуют подключённым возможностям. Имя ОС и её показатели
поступают из API. Начальные значения кэша, подтверждённые измерения
и устаревшие данные оформляются по одинаковым правилам.

| Область | Допустимое различие |
|---|---|
| Владение и запуск | Задачи FreeRTOS либо процессы и потоки Нейтрино |
| Локальное управление | Прямой вызов в приложении либо IPC и `devctl` к владельцу состояния |
| Транспорт консоли | UART, TCP и wolfSSH во FreeRTOS; UART, OpenSSH и оболочка Нейтрино; отдельная консоль TCP 8888 для Нейтрино необязательна |
| Файловые пути ОС | `flash:/`, `sd:/`, `sd-pl:/` либо `/flash`, `/sd` и точка монтирования PL SD; в API сохраняются логические имена томов `flash`, `sd`, `sd-pl` |
| MMIO | Список разрешённых областей и требования аппаратного порта |
| Метрики | Собственные показатели ОС в `os_details`; время и числовые счётчики зависят от запуска |
| SSH и криптография | wolfSSH либо OpenSSH/SFTP и OpenSSL с ГОСТ; одинаковая реализация этих средств не требуется |
| Системные утилиты | Нейтрино сохраняет свою оболочку и инструменты диагностики |
| Автономная загрузка | Разные состав и размещение загрузочных компонентов при сохранении пользовательских данных |

## Изменения совместимости Нейтрино

Таблица сопоставляет поведение базовой ревизии и требования контракта.
Действующее подключение функций перечислено в [возможностях сборок](variants.md).

| Поведение базовой ревизии | Целевое поведение | Изменение для клиента |
|---|---|---|
| Локальные изменения политики, адреса и запись I²C сразу вызывают сохранение | Настройки устройства остаются в RAM до явного `save` | После обновления сценарий должен явно сохранять нужные изменения |
| Прежние DCP2 WRITE_REG и POLICY_SET сохраняют I²C | Физическая запись и смена режима не записывают профиль | Для постоянных настроек требуется POLICY_SAVE или POLICY SAVE |
| MEM с `flags=0` всегда продвигает адрес | Адрес неизменен; продвижение включает AUTOINC | Сценарии последовательного доступа должны передавать AUTOINC |
| MEM принимает только 32 бита и нулевые флаги | Поддерживаемые разрядности используют общую семантику флагов | Проверить разрядность и разрешённую область перед переносом сценария |
| Для многопространственного I²C консоль требует имя устройства | Общие адресные селекторы чтения и записи по правилам FreeRTOS | Сохраняется выбор по имени; добавляется совместимый выбор пространства по адресу |
| Ошибка инициализации I²C останавливает `bvstkd` до запуска DCP2 | Остальные интерфейсы запускаются, I²C сообщает неготовность | Клиент различает недоступность подсистемы и отсутствие сервера |
| Сеть задаёт сценарий IFS | Сохранённый `network.json` задаёт параметры BVSTK после запуска | Перенос действующих настроек выполняется до смены источника конфигурации |
| Общего HTTP-состояния ОС нет | Добавляется `/api/runtime`; прежний `/api/rtos` остаётся совместимым маршрутом FreeRTOS | Общая версия Web UI использует новый маршрут |

Выпуск с изменением сохранения или MEM должен включать обновлённые
примеры и список изменённых сценариев. Миграция сохраняет пользовательские
профили и их резервные копии. Расширение состава профилей или обновление
Web UI не должно подменять настроенные файлы исходным набором.

## Проверки контракта

Следующие сценарии проверяют выполнение контракта. Условия, входные
данные и ожидаемые результаты одинаковы для обеих ОС с учётом
допустимых различий. Наличие сценария в таблице не означает,
что соответствующая функция уже подключена в Нейтрино.

| Сценарий | Действия и ожидаемый результат | Способ проверки |
|---|---|---|
| CFG-LOAD | Загрузить v2 и поддерживаемый прежний формат; сверить ID, пространства, маршруты и оба списка. Ошибочный профиль отклоняется; остальные службы доступны | Общие тесты кодека и загрузчиков; запуск целевых программ |

Общие тесты уже находятся в [tests/host](../../../tests/host)
и [tests/web](../../../tests/web). Они дают основу проверки конкретных
кодеков, сервисов и интерфейсов; аппаратный результат подтверждается
целевым испытанием. При переносе сценарий выполняется для обеих целей,
а результат связывается с ревизиями BVSTK, аппаратного проекта,
параметрами сборки и контрольными суммами образов.

Изменение считается закрытым после проверки его общих тестов,
сборки затронутых целей и предусмотренной сценарием целевой приёмки.
Неподключённая функция остаётся в матрице как отсутствующая или частичная.

## Основания и сопровождение

- [Возможности сборок](variants.md) фиксируют действующий состав.
- [Рабочая среда](../runtime/runtime.md) описывает владение состоянием.
- [API управления](../../../src/services/control/bvstk_control_api.h),
  [файловый интерфейс](../../../src/services/fs/bvstk_fs_reader.h),
  [каталог кэша](../../../src/services/cache/bvstk_cache.h) и
  [журнал](../../../src/shared/events/bvstk_journal.h) задают существующие общие границы.
- [FreeRTOS runtime](../../../src/apps/freertos/runtime/bvstk_runtime.c),
  [сервер Нейтрино](../../../src/apps/neutrino/bvstkd/main.c) и
  [его I²C runtime](../../../src/apps/neutrino/runtime/bvstk_i2c_runtime.c)
  служат исходной точкой подключения подсистем.
- [Сборка и запуск](../../build/build.md) определяют получение и установку образов.

При подключении функции обновляются её состояние в матрице,
справочник затронутого интерфейса и результат приёмочного сценария.
Изменение общего внешнего контракта требует отдельного описания
совместимости и проверки существующих клиентов обеих целей.
