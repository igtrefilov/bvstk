# Форматы управления политиками

Сервисы: I2C `0x02`, MDIO `0x03`. [Доступность](commands.md#сервисы).
Числа передаются [старшим байтом вперёд](frame.md#заголовок-и-граница-кадра).

## Форматы запросов

`target` в таблице обозначает `addr7:u8` для I²C или `phy:u8` для MDIO.
Поля перечислены в порядке передачи.

| `opcode` | Команда | Поля `body` | Действие |
|---|---|---|---|
| `0x02` | `POLICY_SET` | `target`, `mode:u8` | Переключить режим; оба списка сохраняются |
| `0x03` | `POLICY_GET` | `target` | Получить режим и оба списка |
| `0x04` | `POLICY_RULE_ADD` | `target`, `list:u8`, `rule` | Добавить правило в список |
| `0x05` | `POLICY_RULE_DELETE` | `target`, `list:u8`, `rule` | Удалить правило из списка |
| `0x06` | `POLICY_CLEAR` | `target`, `list:u8` | Очистить список; режим сохраняется |
| `0x07` | `POLICY_SAVE` | `target` | Сохранить текущий профиль устройства с режимом и обоими списками политики |

| Поле или условие | Значение |
|---|---|
| `target` | Адрес существующего устройства; создание и переадресация не предусмотрены |
| `mode` | 0 — WHITELIST, 1 — BLACKLIST |
| `list` | 0 — белый список, 1 — чёрный список |
| Лишние поля запроса | Отклоняются |
| Успешные SET, ADD, DELETE, CLEAR, SAVE | Только общий `status=0` |
| Ошибочный ответ | Ненулевой статус без данных |
| Совместимость I2C_POLICY_SET | Код и формат сохранены; прежнее имя `policy` обозначает `mode` |

### I²C-устройство с несколькими адресами

`addr7` выбирает пространство из `transport.address_spaces` профиля.
`reg` во всех правилах — локальный адрес внутри выбранного пространства.
GET возвращает только его правила; ADD, DELETE и CLEAR изменяют только
его списки. Общие ограничения ёмкости списков действуют на весь профиль.

Режим SET общий для логического устройства. SAVE с любым из его адресов
сохраняет весь профиль, включая правила всех пространств.
Формат и коды кадров остаются прежними.

## Ответ POLICY_GET и правила

Поля успешного ответа после общего `status:u16`:

| Поле | Тип | Значение |
|---|---|---|
| `mode` | `u8` | Действующий режим |
| `whitelist_count` | `u16` | Число правил белого списка |
| `blacklist_count` | `u16` | Число правил чёрного списка |
| `whitelist` | `whitelist_count` правил | Белый список |
| `blacklist` | `blacklist_count` правил | Чёрный список |

| Сервис | Поля одного правила в порядке передачи | Предел одного списка |
|---|---|---:|
| I2C | `reg:u8`, `val:u8` | 256 |
| MDIO | `reg:u8`, `val:u16`, `mask:u16` | 64 |

| Условие | Правило |
|---|---|
| I²C | `reg` ограничен числом регистров, `val` — `max_value_code` профиля |
| MDIO | Регистр входит в настроенный диапазон, не более 32 регистров Clause 22 |
| Формат `rule` | Одинаков в GET, ADD и DELETE |
| Совпадение I²C | Равны регистр и значение |
| Совпадение MDIO | Равны регистр и маска; совпадают значимые биты значения |
| ADD для MDIO | Сохраняется `val & mask` |
| Повтор ADD | Успех без дубликата |
| DELETE | Только выбранный список; у MDIO удаляются все эквивалентные записи |
| GET | Согласованная копия обоих списков без нормализации существующих записей |
| Размер GET | Оба списка в одном ответе; после объявленных записей лишних данных нет |
| Несколько команд | Не атомарны; ревизия для защиты изменений отсутствует |
| Чтение регистра | Политикой записи не ограничивается |

## Рабочая конфигурация и сохранение

| Команда | Рабочее состояние | Запись на носитель |
|---|---|---|
| GET | Чтение сервиса | Нет |
| I²C ADD, DELETE, CLEAR | Политика сервиса и её копия в рабочей конфигурации; значения кэша не переносятся в настройки | Нет |
| MDIO ADD, DELETE, CLEAR | Политика сервиса | Нет |
| I²C SET во FreeRTOS | Режим; синхронизация рабочей конфигурации с переносом `valid`-значений кэша в настройки | Нет |
| I²C SET в `bvstkd` | То же | Попытка сохранения; успешный статус подтверждает смену режима, не запись файла |
| MDIO SET | Только режим | Нет |
| I²C SAVE во FreeRTOS и `bvstkd` | Снимок текущего профиля и действующей политики; значения кэша не переносятся в настройки | Да; успешный ответ подтверждает завершение сохранения |
| MDIO SAVE во FreeRTOS | Снимок текущего профиля, включая политику и параметры устройства | Да; успешный ответ подтверждает завершение сохранения |

| Свойство | Значение |
|---|---|
| Тело POLICY_SAVE | Ровно один байт адреса устройства; без списка, режима и имени файла |
| Ответ POLICY_SAVE | `op=0x87`, исходный `seq`, только `status:u16` |
| Место сохранения FreeRTOS | `flash:/config/<bus>/<device>/<device>.json`; путь выбирается по зарегистрированному профилю |
| Место сохранения `bvstkd` | Каталог конфигурации I²C; по умолчанию `/flash/config/i2c/<device>/<device>.json` |
| Область сохранения | Весь текущий профиль выбранного устройства: политика, настройки и метаданные |
| Дополнительные действия SAVE | Кэш, физические регистры и рабочий режим сервиса сохраняют своё состояние |
| Конкурентное редактирование | Сохраняется согласованный снимок на момент SAVE; более поздние правки требуют следующего сохранения |
| Совместимость | Версия кадра остаётся 2; сервер без поддержки SAVE возвращает `ERR_UNSUPPORTED` |
| Консольное сохранение I²C | Использует обновлённую рабочую копию политики |
| Консольное редактирование в Нейтрино | Сохраняет конфигурацию |
| Кэш, адрес устройства, опрос MDIO | Не перестраиваются этими командами |
| Отдельные события политики DCP2 | Не предусмотрены |

## Ошибки

| Статус | Причина |
|---|---|
| `ERR_MALFORMED` | Неверное тело, режим или номер списка |
| `ERR_UNSUPPORTED` | Неизвестная команда или подсистема отсутствует в сборке |
| `ERR_BUSY` | Сервис ещё не готов или не подключён к приложению |
| `ERR_TIMEOUT` | Истекло ожидание блокировки сервиса |
| `ERR_RANGE` | Устройство или правило не найдены, регистр или значение вне диапазона, список заполнен |
| `ERR_INTERNAL` | Внутренняя ошибка, включая сбой обновления рабочей конфигурации, сериализации или записи файла |

| Случай | Результат |
|---|---|
| Неизвестный режим в прежнем FreeRTOS I²C SET | `ERR_UNSUPPORTED`; в общем обработчике — `ERR_MALFORMED` |
| Ошибка проверки параметров | Политика не меняется |
| `ERR_INTERNAL` | Изменение могло примениться; фактическое состояние определяется GET |
| DELETE отсутствующего правила | `ERR_RANGE` |
| ADD существующего правила, CLEAR пустого списка | Успех |
| Таймаут или обрыв при SAVE | Результат сохранения неизвестен; автоматический повтор не выполняется |

GET читает рабочую политику из RAM. Для проверки сохранения после потерянного
ответа нужно прочитать файл профиля, например через сервис FS. SAVE не образует
единую транзакцию с предшествующими командами редактирования.

Числовые коды: [статусы ответа](statuses.md#статус-ответа).
