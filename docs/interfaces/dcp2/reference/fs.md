# Форматы файлового сервиса

| Параметр | Значение |
|---|---|
| Сервис | `srv=0x07` |
| Версия FS | 1 |
| Сервер | FreeRTOS и `bvstkd` Нейтрино (общая сессия DCP2) |
| Тома | `sd`, `flash`, `sd-pl`; требуется готовый том |
| Чтение | FILE, TREE, TAR |
| Изменение | Создание каталога, удаление, переименование, потоковая загрузка файла с явным подтверждением |
| Доступность | Каждая возможность изменения имеет собственный бит в `FS_INFO` |

## Пути и готовность томов

| Параметр | Ограничение |
|---|---|
| Форма пути | Абсолютный путь `volume:/path` |
| `path_len` | Число байтов UTF-8; NUL не передаётся |
| Имя тома | 1–15 строчных ASCII-букв, цифр или дефисов; числовые обозначения FatFs не используются |
| Конечный `/` каталога | Нормализуется |
| Компоненты | `.` и `..`, пустые промежуточные компоненты, конечные пробелы и точки запрещены |
| Запрещённые символы | U+0000–U+001F, U+007F, `\`, `:`, `*`, `?`, `"`, `<`, `>`, `\|` |
| Неверный UTF-8 или превышение длины | Запрос отклоняется; усечения нет |
| Имя не представимо в кодировке носителя | `ERR_RANGE` |
| Монтирование и форматирование | Запросами FS не запускаются |
| Имя тома в FS_INFO | Не подтверждает его готовность; состояние передаётся отдельно |

## Виды потока

| `kind` | Представление |
|---:|---|
| 1 | FILE: последовательные байты файла, без произвольного смещения |
| 2 | TREE: записи файлов и каталогов |
| 3 | TAR: рекурсивный несжатый архив |

| TREE | Правило |
|---|---|
| Без RECURSIVE | Непосредственные дети каталога |
| С RECURSIVE | Обход в глубину; каталог перед потомками |
| Порядок соседей | Определяется файловой системой |
| Корень | Не включается |
| Пустые каталоги | Включаются |

### Запись TREE

Поля FS_TREE_ENTRY в порядке передачи:

| Поле | Тип | Значение |
|---|---|---|
| `entry_len` | `u16` | Полная длина записи: `14 + path_len` |
| `type` | `u8` | 1 — файл, 2 — каталог |
| `reserved` | `u8` | Ноль |
| `size` | `u64` | Размер файла; для каталога ноль |
| `path_len` | `u16` | Длина относительного пути в байтах UTF-8 |
| `path` | `path_len` байт | Путь относительно корня обхода |

| Условие | Требование |
|---|---|
| Граница записи | Определяется `entry_len`; может пересекать блоки FS |
| EOF внутри записи | Ошибка потока |

### Формат TAR

| Свойство | Значение |
|---|---|
| Формат | Несжатый ustar; локальные PAX-заголовки `path` и `size` для длинных, не-ASCII имён и больших размеров |
| Обход | Всегда рекурсивный |
| Пути | Относительные |
| Пустые каталоги | Включаются |
| UID, GID, mtime | 0 |
| Режим файла | `0644` |
| Режим каталога | `0755` |
| Конец архива | Два нулевых блока по 512 байт |
| Границы блоков FS | Не обязаны совпадать с блоками TAR |

## Форматы команд

Поля таблиц расположены в порядке передачи. Данные ответа следуют
за общим `status:u16`; при ошибке дополнительных данных нет.

| `opcode` | Команда |
|---|---|
| `0x00` | FS_INFO |
| `0x01` | FS_STAT |
| `0x02` | FS_OPEN |
| `0x03` | FS_READ |
| `0x04` | FS_CLOSE |
| `0x05` | FS_WRITE_INFO |
| `0x06` | FS_MKDIR |
| `0x07` | FS_REMOVE |
| `0x08` | FS_RENAME |
| `0x09` | FS_WRITE_BEGIN |
| `0x0A` | FS_WRITE_BLOCK |
| `0x0B` | FS_WRITE_COMMIT |
| `0x0C` | FS_WRITE_ABORT |

### FS_INFO: возможности сервиса

Запрос: пустое тело. Данные ответа:

| Поле | Тип | Содержание |
|---|---|---|
| `fs_version` | `u16` | Версия FS, сейчас 1 |
| `capabilities` | `u32` | Поддерживаемые возможности |
| `max_block_size` | `u16` | Максимум `data_len`, сейчас 3072 |
| `max_path_bytes` | `u16` | Предел абсолютного пути, сейчас 511 |
| `max_depth` | `u16` | Глубина стека каталогов с учётом корня, сейчас 16 |
| `max_handles` | `u16` | Число потоков чтения на соединение, сейчас 2 |
| `idle_timeout_ms` | `u32` | Таймаут неактивного потока, сейчас 30000 мс |
| `volume_count` | `u16` | Число следующих записей томов |
| `volume[]` | Переменный массив | Записи `FS_VOLUME` |

Запись FS_VOLUME:

| Поле | Тип | Значение |
|---|---|---|
| `state` | `u8` | 0 — неготовый, 1 — готовый, 2 — не поддержан сборкой |
| `name_len` | `u8` | Длина имени |
| `name` | `name_len` байт | Без NUL и без `:/` |

| Бит `capabilities` | Возможность |
|---:|---|
| 0 | FILE |
| 1 | TREE |
| 2 | TREE_RECURSIVE |
| 3 | TAR |
| 4 | UTF8_PATHS |
| 5 | LIVE_READ: чтение текущей файловой системы без атомарного снимка |

Для расширения записи определены следующие биты.

| Бит `capabilities` | Маска | Команды |
|---:|---:|---|
| 6 | `0x0040` | MKDIR |
| 7 | `0x0080` | REMOVE |
| 8 | `0x0100` | RENAME |
| 9 | `0x0200` | WRITE_BEGIN, WRITE_BLOCK, WRITE_COMMIT, WRITE_ABORT |

При наличии любого из битов 6–9 сервер поддерживает `FS_WRITE_INFO`.
Адаптер с базовым чтением сообщает `0x003F`, с полным набором операций
обеих ОС — `0x03FF`. Клиент проверяет бит каждой нужной возможности и
игнорирует неизвестные биты. Версия FS остаётся равной 1, набор и порядок
полей `FS_INFO` совместимы с клиентами до появления записи.

### FS_STAT: сведения об объекте

| Поле запроса | Тип | Значение |
|---|---|---|
| `path_len` | `u16` | Длина пути |
| `path` | `path_len` байт | Абсолютный путь |

| Поле ответа | Тип | Значение |
|---|---|---|
| `type` | `u8` | 1 — файл, 2 — каталог |
| `attributes` | `u8` | Биты 0–3: readonly, hidden, system, archive; остальные нулевые |
| `size` | `u64` | Размер файла; для каталога 0 |

Время изменения в FS v1 не передаётся.

### FS_OPEN: создание потока

| Поле запроса | Тип | Значение |
|---|---|---|
| `open_id` | `u32` | Ненулевой номер попытки открытия |
| `kind` | `u8` | FILE, TREE или TAR |
| `flags` | `u8` | Бит 0 — `RECURSIVE` для TREE |
| `requested_block_size` | `u16` | 0 — максимум сервера, иначе размер от 1 до максимума |
| `path_len` | `u16` | Длина пути |
| `path` | `path_len` байт | Файл для FILE, каталог для TREE или TAR |

Для FILE и TAR флаги нулевые; для TREE допустим только бит 0.

| Поле ответа | Тип | Значение |
|---|---|---|
| `handle` | `u32` | Дескриптор потока |
| `block_size` | `u16` | Согласованный предел размера блока |
| `total_size` | `u64` | Размер FILE; для TREE и TAR `0xFFFFFFFFFFFFFFFF` |

### FS_READ: очередной блок

| Поле запроса | Тип | Значение |
|---|---|---|
| `handle` | `u32` | Дескриптор OPEN |
| `block_no` | `u32` | Номер блока, начиная с 0 |

| Поле ответа | Тип | Значение |
|---|---|---|
| `handle` | `u32` | Дескриптор из запроса |
| `block_no` | `u32` | Номер из запроса |
| `flags` | `u8` | Бит 0 — EOF, остальные нулевые |
| `reserved` | `u8` | Ноль |
| `data_len` | `u16` | Число байтов данных, не больше `block_size` |
| `data` | `data_len` байт | Фрагмент потока |

| Условие | Требование |
|---|---|
| Формат `data` | Определяется `kind` из OPEN |
| Пустой FILE или TREE | Блок 0, `data_len=0`, EOF |
| Пустой успешный блок без EOF | Недопустим |
| Последний блок | Может содержать данные; повторяется до закрытия или таймаута |
| Полнота FILE после EOF | Сумма `data_len` равна `total_size` |

### FS_CLOSE: освобождение потока

| Параметр | Значение |
|---|---|
| Запрос | `handle:u32` |
| Успешный ответ | Только общий статус |
| `handle=0` | `ERR_FS_BAD_HANDLE` |
| Отсутствующий ненулевой `handle` | Успех; повтор CLOSE допустим |

## Ошибки чтения и восстановление

| Условие | Результат или требование |
|---|---|
| Неактивность 30 секунд или закрытие TCP | Поток освобождается |
| Запрос к прежнему дескриптору | `ERR_FS_BAD_HANDLE` |
| Повторное открытие | Новый поток начинается с блока 0 |
| Ошибка формирования блока | Терминальная для дескриптора; последующие READ возвращают ту же ошибку |
| Обнаружены смена размера, отметки изменения, удаление или досрочный конец файла | `ERR_FS_CHANGED` |
| Изменение содержимого при прежнем размере и отметке | Может остаться незамеченным |
| Параллельное изменение дерева | Согласованный снимок не гарантируется |
| Таймаут приёма | Частичный кадр сохраняется; поздние ответы отделяются по `seq` |
| Ошибка с возможной частичной отправкой запроса | Требуется новое соединение |

Коды: [статусы ответа](statuses.md#статус-ответа).

### Повтор OPEN и READ

| Операция | Условие | Результат |
|---|---|---|
| Повтор OPEN | Прежние ненулевой `open_id` и параметры; поток существует | Тот же дескриптор |
| Повтор OPEN | Прежний `open_id`, другие параметры | `ERR_MALFORMED` |
| READ | Очередной номер блока | Продвижение потока |
| Повтор READ | Последний успешно выданный блок | Те же данные без продвижения |
| READ | Пропуск номера или более старый блок | `ERR_RANGE` |
| Повторная отправка | Новый `seq`; идентификаторы FS сохранены | Отдельный запрос DCP2 |
| Повторное использование `handle` | В том же соединении | Не допускается сервером |

## Форматы команд изменения

Целые числа передаются старшим байтом вперёд. В таблице `path`, `from`
и `to` обозначают каждое по два поля — `length:u16` и ровно `length`
байт абсолютного пути UTF-8. Терминатор и выравнивание отсутствуют.
Прочерк в ответе обозначает успех с одним общим `status:u16`. При ошибке
все команды возвращают только статус.

| Команда | Тело запроса в порядке передачи | Данные успешного ответа после статуса |
|---|---|---|
| `FS_WRITE_INFO` | Пустое | `max_file_size:u64`, `max_block:u16`, `max_uploads:u16`, `idle_ms:u32` |
| `FS_MKDIR` | `id:u32`, `path` | — |
| `FS_REMOVE` | `id:u32`, `path` | — |
| `FS_RENAME` | `id:u32`, `from`, `to` | — |
| `FS_WRITE_BEGIN` | `id:u32`, `size:u64`, `flags:u8`, `path` | `handle:u32` |
| `FS_WRITE_BLOCK` | `id:u32`, `handle:u32`, `offset:u64`, `data` до конца тела | `next_offset:u64` |
| `FS_WRITE_COMMIT` | `id:u32`, `handle:u32` | — |
| `FS_WRITE_ABORT` | `id:u32`, `handle:u32` | — |

Штатные пределы `FS_WRITE_INFO` — до 4 294 967 295 байт в файле,
3072 байт данных в блоке, одна активная загрузка в соединении, таймаут
неактивности 30 000 мс. Два дескриптора чтения учитываются отдельно.
Перед командой клиент проверяет соответствующий бит в `FS_INFO`.

### Каталоги и имена файлов

- `MKDIR` создаёт один каталог в существующем родительском каталоге.
- `REMOVE` удаляет обычный файл или пустой каталог. Непустой каталог нужно предварительно освободить.
- `RENAME` перемещает файл или каталог внутри одного тома. Путь назначения должен быть свободен.
- Каждая команда работает на уже готовом томе. Корень тома и служебные имена загрузки защищены от изменения.
- При создании или переименовании занятый путь назначения может вернуть `ERR_FS_EXISTS`. Попытка загрузить файл вместо каталога возвращает `ERR_FS_TYPE`. Отказ файлового адаптера в доступе возвращает `ERR_DENIED`.

### Загрузка файла

1. В `WRITE_BEGIN` клиент передаёт полный размер файла в байтах. При `flags=0` новый файл создаётся по свободному пути. Бит 0 разрешает замену существующего обычного файла. Остальные биты должны быть нулевыми.
2. Сервер создаёт временный файл на том же томе и выдаёт дескриптор. Первый `WRITE_BLOCK` передаёт смещение 0. Каждый следующий использует `next_offset` из ответа. Длина блока выводится из длины тела, допустимо от 1 до `max_block` байт. Сумма данных ограничена заявленным `size`.
3. При подтверждении всех байтов клиент передаёт `WRITE_COMMIT`. Пустой файл подтверждается сразу после `WRITE_BEGIN`. Сервер проверяет длину, синхронизирует и закрывает временный файл, затем публикует его. При создании требование свободного пути проверяется при публикации, в том числе если назначение появилось после `BEGIN`.
4. Неверное смещение блока возвращает `ERR_RANGE`. Ошибка ввода-вывода при записи блока становится терминальной для загрузки. Преждевременный COMMIT возвращает `ERR_RANGE` и закрывает дескриптор. Обычный COMMIT также закрывает дескриптор при успехе и при ошибке установки.
5. Для отмены клиент передаёт `WRITE_ABORT`. Сервер освобождает дескриптор и удаляет временный файл. При истечении таймаута или закрытии TCP активная загрузка освобождается тем же способом. Новое соединение начинает передачу заново.

До публикации клиент по целевому пути может читать прежнее содержимое.
Для редактирования отдельных байтов или строк клиент читает файл,
редактирует локальную копию и передаёт её полностью. `overwrite` разрешает
замену версии, существующей на момент публикации. Если файл редактируют
несколько клиентов, согласование изменений остаётся за ними.

### Повтор команды изменения

`id` — ненулевой идентификатор операции, общий для всех команд изменения
в одном TCP-соединении. Клиент завершает одну операцию, прежде чем отправить
следующую. Для следующей операции он выбирает больший `id`. При исчерпании
`u32` клиент открывает новое соединение после завершения текущей загрузки.

| Условие | Действие клиента или результат |
|---|---|
| Потерян ответ | Повторить последнюю команду с новым `seq`, прежним `id` и побайтно тем же телом |
| Повтор последней команды | Сервер возвращает сохранённый результат, в том числе ошибку файловой операции. Побочное действие выполняется один раз |
| Такой же `id`, другой код команды или тело | `ERR_MALFORMED` |
| Более старый `id` | `ERR_RANGE` |
| Между попытками выполнялись INFO или другие команды чтения | Результат последней команды изменения сохраняется |
| Повтор успешного BEGIN или BLOCK после истечения срока загрузки | `ERR_FS_BAD_HANDLE` |
| Повтор успешного COMMIT после закрытия дескриптора | Сохранённый успех доступен до следующей команды изменения либо разрыва TCP |
| Соединение потеряно во время COMMIT | Результат неизвестен. В новом соединении клиент проверяет назначение с помощью STAT и чтения |

### Ошибки изменения и восстановление

| Ситуация | Статус и дальнейшие действия |
|---|---|
| Назначение занято при создании или переименовании | `ERR_FS_EXISTS`. Прочитать существующий объект и выбрать свободное имя либо явно разрешить замену файла |
| Открытый файл или каталог мешает изменению на FatFs | `ERR_BUSY`. Закрыть использующие объект потоки. Для новой попытки назначить новый `id` |
| Ошибка записи, синхронизации или установки | `ERR_FS_IO` либо статус адаптера. После ошибки записи завершить загрузку через ABORT. После ошибки COMMIT проверить назначение чтением |
| На томе закончилось место | FatFs может вернуть `ERR_FS_IO` при короткой записи или `ERR_DENIED`, POSIX возвращает `ERR_FS_IO`. Освободить место и начать новую загрузку |
| Истёк срок загрузки или использован чужой дескриптор | `ERR_FS_BAD_HANDLE`. Начать с нового BEGIN |
| Превышен предел размера или нарушен порядок смещений | `ERR_RANGE`. Сверить размер и `next_offset`. COMMIT при неполной длине завершает загрузку с ошибкой |
| Том недоступен | `ERR_FS_NOT_READY`. Проверить носитель и готовность тома, затем начать новую операцию |

Повтор с прежним `id` возвращает сохранённую ошибку. Решение о новой
попытке после устранения причины принимает клиент. Ошибка, возвращённая
адаптером при WRITE_BLOCK, сохраняется в дескрипторе до завершения загрузки.
Для новой загрузки после такой ошибки выполните ABORT, затем BEGIN.
Ошибки проверки смещения и длины блока допускают исправленный запрос
с новым `id`. При ошибке уборки временного файла ABORT тоже может вернуть
ошибку, а служебный файл остаётся на томе для последующей проверки.

### Публикация на носителе

В Нейтрино адаптер POSIX заменяет файл через `rename`. Он сохраняет владельца,
группу и обычные биты прав `rwx` существующего файла. Новый файл создаётся
с правами `0600` с учётом umask и возможностей тома. Для создания по
свободному пути адаптер использует `link`, если файловая система его поддерживает.
На томах без жёстких ссылок он сначала занимает имя через `O_CREAT | O_EXCL`,
затем переименовывает подготовленный файл. Аналогично команда `FS_RENAME`
резервирует свободное имя файлом или каталогом нужного типа.
Во время переименования пустой объект может быть кратковременно виден
напрямую из ОС. После аварийного отключения питания он может остаться на диске.
При прямом доступе к тому через ОС или SFTP учитывайте занятые служебные имена.

Во FreeRTOS адаптер FatFs под блокировкой тома переименовывает прежний
файл во временную резервную копию, устанавливает новый и при отказе
установки пытается вернуть прежнее имя. Если уборка после публикации
завершилась ошибкой ввода-вывода, новое содержимое уже может быть доступно.
В этом случае проверьте целевой файл чтением. Отключение питания или
отказ носителя может прервать публикацию на обеих платформах.

На каждом томе для загрузки зарезервированы 16 пар имён в корне —
от `BVU00000.TMP` и `BVU00000.OLD` до `BVU00015.TMP` и `BVU00015.OLD`.
Обходы TREE и TAR пропускают эти имена, прямой OPEN возвращает `ERR_DENIED`.
При обычном завершении служебные файлы удаляются. После сбоя на носителе
могут остаться временный файл или резервная копия. Сервер пропускает занятые
пары. Проверку назначения и восстановление после такого сбоя выполняют отдельно.

Загрузка файла профиля изменяет сохранённый JSON. Работающие сервисы
продолжают использовать данные в RAM. Изменения топологии вступают
в силу при следующей загрузке профиля во время запуска.
