# Формат кадра DCP2

## Заголовок и граница кадра

Поля таблиц расположены в порядке передачи.

| Поле | Тип | Значение |
|---|---|---|
| `magic` | 4 байта | ASCII `DCP2`: `44 43 50 32` |
| `ver` | `u16` | 2 |
| `dcp_len` | `u16` | Длина остатка кадра: `srv`, `op`, `seq`, `body` |

| Правило | Требование |
|---|---|
| `u8`, `u16`, `u32`, `u64` | Беззнаковые целые соответствующей разрядности |
| Порядок байтов чисел | Старший байт первым |
| Выравнивание полей | Отсутствует |
| Строки и содержимое файлов | Последовательности байтов без перестановки |
| Длина заголовка | 8 байт |
| `dcp_len` | От 4 до 4096 включительно |
| Длина полного кадра | `8 + dcp_len`, от 12 до 4104 байт |
| Граница сегмента TCP | Не определяет границу кадра DCP2 |

## Сервис, операция и номер запроса

| Поле | Тип | Значение |
|---|---|---|
| `srv` | `u8` | [Идентификатор сервиса](commands.md#сервисы) |
| `op` | `u8` | Код операции и признаки сообщения |
| `seq` | `u16` | Номер запроса; ноль для события |
| `body` | `dcp_len - 4` байта | Тело операции |

| Тип сообщения | `RESP`, бит 7 | `EVENT`, бит 6 | `op` |
|---|---:|---:|---|
| Запрос | 0 | 0 | `opcode` |
| Ответ | 1 | 0 | `0x80 \| opcode` |
| Событие | 0 | 1 | `0x40 \| opcode` |

| Поле | Ограничение |
|---|---|
| `opcode` | `op & 0x3F`; значение определяется сервисом |
| `RESP=1`, `EVENT=1` | Не используется |
| `seq` запроса | 1–65535; уникален среди ожидающих запросов соединения |
| `seq` ответа | Совпадает с запросом |
| `seq` события | 0 |

## Тело запроса, ответа и события

| Сообщение | Поля `body` в порядке передачи |
|---|---|
| Запрос | Параметры команды; пустое тело, если параметры не предусмотрены |
| Ответ | `status:u16`, затем данные результата по формату команды |
| Событие | Данные события по формату сервиса; общего статуса ответа нет |

| Параметр | Значение |
|---|---|
| Успешный ответ без данных | Только `status=0` |
| Максимум данных результата | 4090 байт |
| Коды `status` | [Статусы ответа](statuses.md#статус-ответа) |
| `status` внутри события | Поле данных сервиса; [отдельные коды](statuses.md#статус-в-notify-и-bvt1) |

## Сопоставление сообщений

| Условие | Правило |
|---|---|
| Ответ на запрос | Совпадают `srv`, `opcode` и `seq` |
| Событие | Не завершает ожидание ответа |
| Поздний ответ | Отделяется по `seq`; номер нельзя повторно назначать ожидающему запросу |
| Повтор команды | Может выполнить операцию заново; `seq` не устраняет повторы |
| Повторы FS | Дополнительно определяются [идентификаторами FS](fs.md#повтор-open-и-read) |
| Новое TCP-соединение | Новое пространство номеров и состояние сервисов |

## Проверка кадра

| Условие | Результат или требование |
|---|---|
| Неверные `magic`, `ver` или `dcp_len` | Сервер закрывает соединение без поиска следующей сигнатуры |
| Неподдерживаемая операция в допустимом кадре | Ответ с ненулевым статусом |
| Таймаут приёма | Частично полученный кадр должен сохраняться |
| Потеря состояния приёмника | Требуется новое соединение |
| Потеря ответа или ошибка операции | Отсутствие побочных эффектов не гарантируется |

## Версия и доступность сервисов

| Параметр | Текущее значение |
|---|---|
| Версия DCP2 | 2 |
| Внутренняя версия FS | 1, передаётся в `FS_INFO` |
| Внутренняя версия CACHE | 1, передаётся в теле CACHE |
| Команда `CAPABILITIES` | Отсутствует |
| Возможности FS | `FS_INFO` |
| Доступность CACHE | Запрос к известному устройству |
| Состав сервисов | [Зависит от приложения и сборки](commands.md#сервисы) |
