# Форматы подписок и событий

Поля таблиц расположены в порядке передачи. Успешные ответы команд содержат
только `status:u16`; события имеют `seq=0` и не содержат общего статуса ответа.
Числа: [формат кадра](frame.md). CACHE: [отдельный формат](cache.md).

## NOTIFY: отбор уведомлений

Сервис `srv=0x06`.

| `opcode` | Команда | Поля запроса в порядке передачи |
|---|---|---|
| `0x10` | NOTIFY_SUBSCRIBE | `class_mask:u32`, `source_mask:u32`, `bus_mask:u32`, `flags:u8` |
| `0x11` | NOTIFY_UNSUBSCRIBE | Пустое тело |

| Бит | `class_mask` | `source_mask` | `bus_mask` |
|---:|---|---|---|
| 0 | `REG_ATTEMPT` | `TELNET` | `I2C` |
| 1 | `REG_COMMIT` | `HOST` | `MDIO` |
| 2 | `REG_DENIED` | `DCP` | `SPI` |
| 3 | `STATE_CHANGED` | `INTERNAL` | `UART` |
| 4 | `FAULT` | `WEB` | `SYS` |

| Условие | Требование |
|---|---|
| Маски | Каждая ненулевая; биты выше 4 нулевые, иначе `ERR_RANGE` |
| Отбор обычного события | Совпадают класс, источник и шина |
| Несколько битов одной маски | Любое из выбранных значений |
| Бит шины в формате | Не гарантирует источник событий этой шины |

| Бит `flags` | Имя | Поведение |
|---:|---|---|
| 0 | `WITH_TIMESTAMP` | Добавить `time_us` в начало каждого события |
| 1 | `SNAPSHOT_ON_SUBSCRIBE` | Принимается текущим сервером, но отдельный снимок состояния не формируется |

Биты `flags` выше 1 должны быть нулевыми; иначе `ERR_MALFORMED`.

## Формат события NOTIFY

`srv=0x06`, `op=0x50`.

| Поле | Тип | Содержание |
|---|---|---|
| `time_us` | `u64`, необязательное | Время регистрации события PS, в микросекундах |
| `ev_type` | `u16` | Тип действия или состояния |
| `status` | `u16` | Результат наблюдаемого действия |
| `source` | `u8` | Источник действия |
| `bus` | `u8` | Подсистема |
| `op_kind` | `u8` | Вид операции |
| `reserved` | `u8` | Ноль |
| `arg0`, `arg1`, `arg2` | `u32` каждый | Аргументы действия |

| Поле | Значение или ограничение |
|---|---|
| `time_us` | Присутствует при WITH_TIMESTAMP; разрешение определяется тиком PS |
| `status` | [Статус переносимого сервиса](statuses.md#статус-в-notify-и-bvt1) |
| `source`, `bus` | Номер бита соответствующей маски |
| `op_kind` | 0 READ, 1 WRITE, 2 POLICY_CHANGE, 3 CONFIG_APPLY, 4 STATE_TOGGLE |
| `arg0`, `arg1`, `arg2` при записи регистра | Адрес устройства, регистр, значение |
| `arg0` при SOFTWARE_LOSS | Число перезаписанных записей журнала выбранной шины; насыщение до UINT32_MAX |
| Отбор SOFTWARE_LOSS | Только маска шин; маски классов и источников игнорируются |
| Учёт потерь | До фильтрации; не равен числу утраченных событий выбранного класса |

| `ev_type` | Событие |
|---|---|
| `0x0001` | `REG_ATTEMPT`: попытка операции |
| `0x0002` | `REG_COMMIT`: выполненная операция |
| `0x0003` | `REG_DENIED`: отказ по политике |
| `0x0004` | `STATE_CHANGED`: изменение состояния |
| `0x0005` | `FAULT`: ошибка |
| `0x0006` | `SOFTWARE_LOSS`: потеря записей журнала |

## STREAM: наблюдения и тестовые данные

Сервис шины: I²C `0x02`, MDIO `0x03`, SPI `0x04`, UART `0x05`.

| `opcode` | Команда | Тело запроса | Данные после `status` |
|---|---|---|---|
| `0x10` | `PL_SUBSCRIBE_STREAM` | `flags:u8` | — |
| `0x11` | `PL_UNSUBSCRIBE_STREAM` | Пусто | — |

| Бит | Имя | Значение |
|---:|---|---|
| 0 | `RAW_WORDS` | Данные трактуются как 32-битные слова; размер кратен четырём |
| 1 | `WITH_TIMESTAMP` | Добавить метку времени в тело события |
| 2 | `RESET_LOST_COUNTERS` | Сбросить счётчик потерь тестового генератора |

Биты `flags` выше 2 должны быть нулевыми. RESET_LOST_COUNTERS
сбрасывает счётчик генератора; утраченные наблюдения не восстанавливает.

### Событие STREAM

`op=0x50`, `srv` — сервис шины.

| Поле | Тип | Содержание |
|---|---|---|
| `time_us` | `u64`, необязательное | Метка времени |
| `ev_flags` | `u8` | Происхождение данных и признак потери |
| `lost_delta` | `u32` | Число потерянных единиц данных |
| `data_len` | `u16` | Длина следующего массива в байтах |
| `data` | Массив из `data_len` байт | Данные наблюдения или генератора |

| Бит `ev_flags` | Имя | Содержание `data` или состояние |
|---:|---|---|
| 0 | `OVERFLOW` | Обнаружена потеря данных |
| 1 | `OBSERVATION` | Запись наблюдения PS в формате `BVT1` |
| 2 | `SYNTHETIC` | Данные тестового генератора |

| Условие | Требование |
|---|---|
| Наличие `time_us` | Определяется WITH_TIMESTAMP подписки, не `ev_flags` |
| OBSERVATION и SYNTHETIC | Не устанавливаются вместе |
| Реальные наблюдения | Журналы PS для I²C и MDIO |
| OBSERVATION | В `data` одна запись BVT1, 32 байта |
| RAW_WORDS при BVT1 | Вся запись сохраняется вместе с заголовком |
| `lost_delta` наблюдения | Перезаписанные записи журнала шины; насыщение до UINT32_MAX |

### Запись BVT1

| Поле | Тип | Содержание |
|---|---|---|
| `magic` | 4 байта | ASCII `BVT1` |
| `sequence` | `u64` | Номер наблюдения в журнале шины |
| `type` | `u16` | Тип наблюдаемого действия |
| `status` | `u16` | Результат действия |
| `source`, `bus`, `operation` | `u8` каждое | Источник, шина и вид операции |
| `width` | `u8` | 8 для I²C и 16 для MDIO |
| `address`, `reg`, `value` | `u32` каждое | Устройство, регистр и значение |

`sequence` нумерует наблюдения отдельно для каждой шины. Типы соответствуют
[HTTP-журналу](../../http/reference/observation.md#журналы-наблюдений), статусы —
[переносимому сервису](statuses.md#статус-в-notify-и-bvt1).

## Состояние подписок

| Свойство | NOTIFY | STREAM |
|---|---|---|
| Количество | Один фильтр на соединение | Одна подписка на сервис шины |
| Начальная позиция | Текущий конец журналов | Текущий конец журнала |
| Повтор подписки | Замена фильтра; курсоры в текущем конце | Новая начальная позиция |
| Отфильтрованные записи | Курсор продвигается | — |
| Закрытие TCP | Состояние утрачивается | Состояние утрачивается |
| Воспроизведение истории после переподключения | Нет | Нет |
| Сервер FreeRTOS | Поддерживается | Поддерживается |
| Текущий `bvstkd` | Не поддерживается | Не поддерживается |
