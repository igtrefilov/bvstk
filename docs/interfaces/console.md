# Консоль

Во FreeRTOS команды устройства доступны через UART, TCP-консоль и SSH
при включении его в сборке. В Нейтрино пользователь работает в оболочке
ОС, а команды управления обращаются к службе `bvstkd`.

## Подключение

### TCP и SSH FreeRTOS

Команды подключения выполняются на компьютере. Замените `192.168.0.10`
фактическим адресом платы.

```sh
nc 192.168.0.10 8888
```

Для интерактивного подключения также используется `telnet` к порту `8888`.
Это не обещание полного сервера Telnet со всеми расширениями. TCP-сеанс
не шифруется и не требует входа. Не передавайте через него секреты.

При сборке с SSH:

```sh
ssh root@192.168.0.10
ssh root@192.168.0.10 'i2c list'
```

Имя пользователя и порт могут быть заданы при сборке. SSH использует тот
же набор команд; Unix-конвейеры, перенаправления, запуск произвольных
программ и подстановка команд здесь не подразумеваются. Завершение сеанса —
`quit` или `exit`.

### Ключ устройства

При первом SSH-подключении сверяйте отпечаток по доверенному каналу. Если
после пересборки FreeRTOS ключ изменился, сначала подтвердите ожидаемую
смену. Лишь после этого удалите конкретную устаревшую запись:

```sh
ssh-keygen -R 192.168.0.10
```

Не отключайте проверку ключей для всех устройств. Чтобы пересборка не
меняла идентичность платы, используйте постоянный ключ устройства в
[параметрах сборки FreeRTOS](../build/freertos.md).

### Оболочка Нейтрино

```sh
ssh -i build/neutrino/ax7020_ssh_client root@192.168.0.10
```

Интерактивный `bvstk-shell` добавляет редактор и контекстные подсказки I²C/MDIO,
а команды исполняет `ksh`. Здесь действуют системные пути, перенаправления
и программы ОС. Команды `i2c`, `mdio`, `fs`, `tar`, `mem`, `pl` и
`<bus> stream` передают запросы через `/dev/bvstk-control` в `bvstkd`.
Они используют рабочие сервисы демона. Прежний `/dev/bvstk-i2c` сохранён
для совместимости со старыми клиентами. `bvstkctl <command> ...` доступен
для всех перечисленных команд.

Стандартный PS-драйвер I²C из SDK не заменяет этот путь. Если
`/dev/bvstk-control` отсутствует, диагностируйте `bvstkd` и аппаратную
инициализацию, не запускайте параллельного владельца того же PL.

## Синтаксис и ответы

В записи команд ниже `<аргумент>` обязателен, `[аргумент]` необязателен; скобки
не вводятся. Числа обычно принимаются десятичными или с префиксом `0x`.
Для IPv4, MAC и именованных режимов действуют отдельные форматы.
Общие `fs` и `tar` понимают одинарные/двойные кавычки и экранирование
обратной косой чертой. В Нейтрино их сначала обрабатывает `ksh`, клиент
передаёт границы аргументов демону. Старые самостоятельные файловые команды
FreeRTOS используют прежний разбор по пробелам. У `fs write/append`
FreeRTOS строка без кавычек сохраняет прежний буквальный остаток текста.

`help` выводит общую справку; `fs` — справку файлового слоя.
`quit` и `exit` закрывают TCP/SSH-сеанс; UART после сообщения `Bye!`
остаётся доступен и печатает новое приглашение. Строка редактора и диспетчера FreeRTOS ограничена 511 байтами.
Команда, выводящая данные,
не обязана заканчиваться отдельным `OK`; текстовый интерфейс не предназначен
для побайтово стабильного машинного разбора.

После подключения к FreeRTOS можно начать со справки и списка устройств:

```text
help
i2c list
mdio list
```

В следующих разделах команды вводятся в консоли платы. Для каждой группы
указано, в какой ОС она доступна. Для автоматизации используются также
[HTTP](http/http.md) и [клиент DCP2](dcp2/client.md).

UART, TCP и SSH используют редактор строки. Стрелки и `Home`/`End` меняют
позицию курсора, `Up`/`Down` листают историю, `Backspace`/`Delete` удаляют
символы, а `Tab` дополняет команды, параметры и пути файловой системы.
Доступны также привычные `Ctrl-A`/`Ctrl-E`, `Ctrl-U`, `Ctrl-W`, `Ctrl-K`,
`Ctrl-Y` и `Ctrl-C`.

| Маркер | Значение |
|---|---|
| `OK` | Основная операция выполнена |
| `ERR` | Ошибка аргументов или выполнения; уточнение может следовать в той же строке |
| `ERR DENIED`, `DENIED` | Отказ по диапазону или политике |
| `FS not ready`, `I2C not ready` | Нужная подсистема не готова |
| `WARN` | Вспомогательное действие, например сохранение, не завершилось |

## Общие файловые команды

Одинаковый интерфейс обеих ОС:

```text
fs volumes
fs ls [path]
fs stat <path>
fs cat <path>
fs mkdir <path>
fs touch <path>
fs write <path> <text>
fs append <path> <text>
fs cp [-r] <src> <dst>
fs mv <src> <dst>
fs rm [-r] <path>
```

Пути: `flash:/`, `sd:/`, `sd-pl:/`; без имени тома используется текущий том.
Относительные пути отсчитываются от каталога сеанса FreeRTOS или от native
`/flash`/`/sd` в Нейтрино (из прочих каталогов — `flash:/`). `.` и `..`
нормализуются до обращения к общему backend; выйти выше корня тома нельзя.
Имена с пробелами заключайте в кавычки. `fs touch` сохраняет существующий
файл; `fs write` заменяет его, `append` дописывает. `cp` требует свободное
имя назначения, `mv` работает внутри тома и не заменяет цель. Рекурсивные
операции ограничены глубиной 16; копирование внутрь своего дерева запрещено.
Ошибка выводится как `ERR fs <STATUS>`; частично созданные данные могут остаться.
`fs cat` передаёт двоичные байты; локальный транспорт Нейтрино выдаёт до
256 КиБ результата порциями и сообщает ошибку при превышении лимита.
Успех записи возвращается после sync и close.

## Файлы и каталоги FreeRTOS

Только диспетчер FreeRTOS. Рабочий каталог принадлежит сеансу. Префиксы
`sd:/` и `0:/` выбирают PS SD, `flash:/` и `1:/` — QSPI. Формы
`sd/`, `flash/` также распознаются маршрутизатором; для скриптов лучше
полные имена с двоеточием. `cd flash` и `cd sd` переключают том.
Абсолютный путь без имени тома относится к текущему тому.

| Синтаксис | Результат и побочные действия |
|---|---|
| `pwd` | Текущий каталог сеанса |
| `ls [path]` | Непосредственное содержимое каталога; без пути — текущего |
| `cd <path>` | Проверяет каталог и меняет состояние сеанса |
| `mkdir <path>` | Создаёт каталог |
| `touch <path>` | Создаёт файл; существующий усекает до нуля |
| `fs write <path> <text>` | Создаёт/заменяет текстовый файл; остаток строки пишется буквально, без автоматического перевода строки |
| `fs append <path> <text>` | Дописывает текст в конец файла; создаёт отсутствующий файл |
| `cat <path>` | Передаёт содержимое файла в консоль |
| `rm <path>` | Удаляет файл или пустой каталог |
| `rm -r <path>` | Рекурсивно удаляет дерево без корзины |
| `cp <src> <dst>` | Копирует файл; совпадающая цель может быть заменена |
| `cp -r <src> <dst>` | Копирует дерево |
| `mv <src> <dst>` | Переименовывает или переносит объект |

Если `dst` — существующий каталог, `cp` и `mv` добавляют к нему базовое
имя источника. Между томами используются операции копирования/переноса
файлового слоя, а не атомарное переименование. Ошибка может оставить
частичную цель; до удаления исходника проверьте результат. Сбой файловой
операции не гарантирует откат.

`sd-pl:/` (внутреннее имя `2:/`) — существующий FAT-том внешней карты через
PL SPI/DMA. Инициализация и монтирование автоматические при старте.
`cd sd-pl` переключает текущий том. `fs format sd-pl confirm` запрещена,
как и скрытое автоматическое форматирование при отсутствии файловой системы.
При ошибке монтирования проверьте UART-журнал и используйте уже подготовленную
карту FAT12/16/32. Для QSPI и PS SD эта команда форматирования не предоставляет.

## Архивы

Обе ОС используют общий обработчик и логические пути:

| Синтаксис | Действие |
|---|---|
| `tar c <src_dir> <dst_tar>` | Создаёт TAR каталога в файле |
| `tar t <src_tar>` | Перечисляет архив |
| `tar x <src_tar> <dst_dir>` | Извлекает файлы в каталог, может заменить существующие |

Создание и извлечение не образуют транзакцию. Не размещайте создаваемый
архив внутри копируемого дерева. Для резервной копии на компьютере
используйте [DCP2 FS](dcp2/client.md). Поддержаны ustar и PAX `path`,
обычные файлы и каталоги. Ссылки, абсолютные пути, выход через `..`,
неверная контрольная сумма и незавершённые данные возвращают ошибку.
Метаданные PAX ограничены 2047 байтами; прочие расширения не поддерживаются.

## Сеть

Только FreeRTOS; команды показывают или изменяют работающий `netif`.

| Синтаксис | Действие |
|---|---|
| `ip addr show` | IP, префикс, маска и шлюз |
| `ip addr set <IPv4>/<prefix>` | Применяет IP/маску и пытается сохранить набор |
| `ip link show` | MAC-адрес |
| `ip link set address <mac>` | Обновляет MAC в программной конфигурации интерфейса и сохраняет |
| `ip route show` | Шлюз по умолчанию |
| `ip route set default via <IPv4>` | Применяет и сохраняет шлюз |
| `ip save` | Сохраняет текущие параметры интерфейса |

IPv4 задают четырьмя октетами, префикс — `0..32`, MAC — шестью
шестнадцатеричными октетами через двоеточие. Сохранение может завершиться
ошибкой независимо от применения. Смена адреса способна прервать сеанс;
[порядок переподключения](../network.md) обязателен для удалённой настройки.

## Общие правила I²C и MDIO

Обе ОС используют одни обработчики; во FreeRTOS доступны UART, TCP и SSH. Команды имеют
одинаковый синтаксис и формат результата:

| Команда после `<bus> <sel>` | Вывод |
|---|---|
| `policy`, `policy show` | Только режим: `policy=whitelist` или `policy=blacklist` |
| `policy show rules` | Режим и оба списка правил |
| `policy show whitelist`, `policy whitelist` | Только белый список |
| `policy show blacklist`, `policy blacklist` | Только чёрный список |
| `save` | Явное сохранение текущей конфигурации выбранного устройства |

Названия полей и режимов строчные. Правила выводятся как `reg=0xNN val=0xNN`
для I²C и `reg=0xNN val=0xNNNN mask=0xNNNN` для MDIO. Чтение возвращает
`OK reg=0xNN val=0xNN dec=N` с четырьмя hex-цифрами значения для MDIO.
Ошибка имеет вид `ERR <bus> <причина>`, например `ERR i2c denied` или
`ERR mdio timeout`. Некорректные и лишние аргументы не применяются.

Изменения конфигурации вступают в силу в RAM и возвращают
`OK (RAM; use save to persist)`. Только `save` записывает JSON во flash
и возвращает `OK saved flash:/config/<bus>/<файл>.json`. До успешного
сохранения перезапуск возвращает последнюю сохранённую конфигурацию.
Обычная запись регистра отвечает `OK`: это не подтверждение сохранения
конфига и не обещание отмены физической записи после перезапуска.

Tab дополняет `policy show/set`, имена списков, `add/del/delete/clear`
и `save`. Дополнительные команды зависят от возможностей подсистемы.

## I²C

`<sel>` — имя устройства или 7-битный адрес; форма `@0xNN` явно выбирает
адрес. Это не порядковый номер строки `i2c list`. Число регистра меньше
`reg_count`, значение записи не превышает `max_value_code`.
Для текущих конфигурационных загрузчиков верхний предел последнего — 64.

| Синтаксис | Действие |
|---|---|
| `i2c list` | Перечень устройств |
| `i2c <sel> [info]` | Описание выбранного устройства |
| `i2c <sel> r <reg>` | Физическое чтение через ведущий сервис |
| `i2c <sel> w <reg> <val>` | Запись с проверкой диапазона и политики |
| `i2c <sel> addr <addr_7b>` | Меняет адрес конфигурации в RAM; это не перепрограммирование адреса внешнего чипа |
| `i2c <sel> policy` | Показывает режим |
| `i2c <sel> policy show [rules\|whitelist\|blacklist]` | Без аргумента показывает режим; с аргументом — выбранные правила |
| `i2c <sel> policy set <whitelist\|blacklist>` | Меняет активный режим |
| `i2c <sel> policy whitelist add <reg> <val>` | Добавляет разрешённую пару |
| `i2c <sel> policy whitelist del <reg> <val>` | Удаляет разрешённую пару |
| `i2c <sel> policy whitelist clear` | Очищает белый список |
| `i2c <sel> policy blacklist add <reg> <val>` | Добавляет запрещённую пару |
| `i2c <sel> policy blacklist del <reg> <val>` | Удаляет запрещённую пару |
| `i2c <sel> policy blacklist clear` | Очищает чёрный список |
| `i2c <sel> save` | Сохраняет текущую конфигурацию: `flash:/config/i2c/<файл>.json` во FreeRTOS, `/flash/config/i2c/<файл>.json` в Нейтрино |

Вертикальная черта в таблице означает выбор одного слова. Форма
`policy whitelist` или `policy blacklist` без `set` показывает список,
а не меняет режим. Пустой белый список запрещает запись, пустой чёрный
список разрешает её в пределах диапазона. Ошибки записи различают отказ
политики и отказ аппаратной операции.

Изменения I²C из shell и DCP2 в обеих ОС не сохраняются автоматически.
HTTP FreeRTOS также разделяет применение и сохранение.
Для сохранения используется `i2c <sel> save`; ошибка сохранения не отменяет
уже применённые изменения RAM. Снимок включает адрес, политики, правила и
значения действительных записей кэша в `settings`.

В Нейтрино отдельная команда работает через `/dev/bvstk-control`; изменения
отмечаются как RAM, явный `save` сохраняет профиль. Для многопространственных
устройств чтение и запись поддерживают как имя с `<space>:<reg>`, так и
однозначный адресный селектор с локальным номером регистра.

## MDIO

Общий обработчик обеих ОС; во FreeRTOS доступен в UART/TCP/SSH, в Нейтрино — через `mdio` или `bvstkctl mdio`.
Селектор — имя, PHY или @PHY. Числа принимаются десятичные и 0xHEX,
регистр 0..31 (также меньше reg_count), значение/маска 0..65535.
Tab дополняет имена устройств, операции и вложенные команды.

    mdio list
    mdio status
    mdio <sel> info
    mdio <sel> r <reg>
    mdio <sel> w <reg> <value>
    mdio <sel> cache show [reg]
    mdio <sel> cache refresh
    mdio <sel> cache invalidate
    mdio <sel> policy
    mdio <sel> policy show [rules|whitelist|blacklist]
    mdio <sel> policy set <whitelist|blacklist>
    mdio <sel> policy <whitelist|blacklist> add|del <reg> <value|*> [mask]
    mdio <sel> policy <whitelist|blacklist> clear
    mdio <sel> autopoll [show|on|off|reg_delay <ms>|cycle_delay <ms>|regs <r0> ...]
    mdio <sel> settings [show|set <reg> <value>|del <reg>|clear]
    mdio <sel> phy <0..31>
    mdio <sel> save

Также поддерживаются прямые формы mdio r <phy> <reg> и mdio w <phy> <reg> <value>.
Старого имени команды smi и старых allow/deny/clear нет.
Тестовый stream fake сохранён как средство проверки DCP2-транспорта,
не как монитор реального провода.

Правило сравнивает reg и (value & mask). Без mask — точное значение,
звёздочка вместо value разрешает/запрещает любые значения регистра.
Пустой whitelist запрещает всё, пустой blacklist разрешает запись
в пределах устройства. Для изменения режима нужен policy set.

Настройки изменяются в RAM; save сохраняет их в flash:/config/mdio/.
Settings — начальные значения кэша, не физические записи. Cache refresh
читает только список autopoll_regs; invalidate удаляет достоверность,
после чего фоновые чтения снова заполняют кэш. При autopoll off
проверка ID PHY продолжается примерно раз в секунду.

Успех write означает отправку кадра, а не подтверждение PHY. Самоочищающиеся
команды в кэш не подставляются: после записи выполняется реальное чтение.
Счётчики status относятся к обработанным ячейкам/операциям, а не ко всем
кадрам на проводе. PL может терять и объединять записи; запрет политики
не имеет аппаратного ответа ESP32.

[Устройство подсистемы и ограничения](../system/pl-subsystem/mdio/drivers/drivers.md).

## SPI

Обычный SPI выключен в текущем профиле. Сохранённый интерфейс FreeRTOS:

| Синтаксис | Параметры |
|---|---|
| `spi info` | Текущая конфигурация |
| `spi cfg mode <single\|multi\|fallthrough>` | Режим пакетов |
| `spi cfg timeout <ticks>` | Аппаратный параметр ожидания, не миллисекунды ОС |
| `spi cfg div <even>` | Чётный делитель `2..65535`, наибольшее допустимое чётное — 65534 |
| `spi cfg read <on\|off>` | Чтение ответа из BRAM |
| `spi xfer <w0> [w1 ...]` | До 64 слов по 32 бита |

Настройки SPI не имеют собственного сохраняемого JSON. Эти команды не
описывают DCP2 SPI transfer: обычная операция передачи через DCP2 в
текущем сервере не предоставляется.

## PL SD

Служба FreeRTOS использует внешнюю SDHC/SDXC через PL SPI и DMA:

В обычной сборке используйте `sd-pl info` и файловые команды с путями
`sd-pl:/`. Карта монтируется автоматически. Следующие сырые диагностические
команды (кроме `info`) сохраняются для режима без файловой системы и
**блокируются в штатной сборке**, включая случай неудачного монтирования.

```text
sd-pl init [timeout_ms]
sd-pl info
sd-pl status
sd-pl blocklen
sd-pl read <lba>
sd-pl write <lba> <seed>
sd-pl test <lba> [count] [seed]
```

`init`: 1..120000 мс, умолчание 20000; `info`: кэшированное состояние;
`status`: CMD13; `blocklen`: диагностическая CMD16(512). `read` возвращает
512 байт только после проверки CRC16. **`write` и `test` перезаписывают
сектора без восстановления** и проверяют результат чтением. `write`
использует шаблон от seed и LBA; `test` записывает 1..8 секторов (умолчание 2),
затем проверяет весь диапазон. Числа — десятичные или `0xHEX`.

Физическая ёмкость не определяется: LBA должен существовать. В сыром режиме
ошибка I/O требует повторной явной `init`; в файловом — перезапуска системы.
Записи автоматически не повторяются. Текущий
профиль переинициализирует карту перед каждой следующей командой для
совместимости с неизменённым ядром; файловый слой использует тот же путь.
Работа SD-сервиса описана в
[разделе подсистемы SPI](../system/pl-subsystem/spi/services/services.md).

## Тестовые потоки

Обе ОС. Вместо `<bus>` выберите `i2c`, `mdio`, `spi` или `uart`.

```text
<bus> stream fake enable [period_ms] [pattern] [words]
<bus> stream fake status
<bus> stream fake disable
```

`period_ms` — `10..60000` мс, умолчание 100; `words` — `1..64`,
умолчание 4; `pattern` — `counter` (умолчание), `ramp` или `toggle`.
Источник не обращается к MMIO, выключен после запуска и не сохраняется.
Подписчик DCP2 запускается [отдельной командой](dcp2/client.md).
Реальные наблюдения I²C и MDIO постоянно собираются в RAM. Формы
`stream enable` и `stream disable` их не переключают: клиент управляет
доставкой через DCP2 subscribe/unsubscribe. `stream status` сообщает об
этом и отдельно показывает состояние тестового генератора. Для SPI и
UART реальный источник пока отсутствует.

## Память и перезапуск

`mem` доступен в обеих ОС; `reboot` из этой таблицы — только во FreeRTOS.

| Синтаксис | Действие |
|---|---|
| `mem r <addr>` | Выровненный адрес читается как 32 бита, иначе как 8 бит |
| `mem w <addr> <value>` | 32-битная запись по выровненному адресу; иначе значение должно помещаться в байт |
| `reboot -y [delay_ms]` | Перезапуск с подтверждением |
| `reboot confirm [delay_ms]` | Альтернативное подтверждение |

Доступ к памяти обходит сервисные правила. Не применяйте его к произвольному
адресу: возможны аппаратное исключение, зависание и изменение состояния.
Перезапуск прерывает сеансы и файловые операции. Подробности конкретных
проверок адреса нельзя переносить между MEM-консолью, HTTP и DCP2.

## Утилита Нейтрино bvstkctl

| Синтаксис | Действие |
|---|---|
| `bvstkctl version` | Версия программы и платформы |
| `bvstkctl pl list` | Программная таблица регионов, не обнаружение IP |
| `bvstkctl pl probe` | Диагностический доступ к регионам; не безопасная проверка всех выключенных узлов |
| `bvstkctl pl read <region> <offset> [word-count]` | Чтение слов региона |
| `bvstkctl pl write <region> <offset> <value>` | Прямая запись слова |
| `bvstkctl <command> ...` | Общие обработчики внутри `bvstkd` |
| `bvstkctl observe <i2c|mdio> <events|telemetry> [after|history] [device]` | Пассивная порция журнала `bvstkd`, JSON с курсорами и потерями |

Для наблюдений `after` — десятичный курсор `next` предыдущего ответа.
По умолчанию используется `history`: сохранившаяся история без учёта
более старых потерь. Последний аргумент задаёт имя устройства.
Команда не читает регистры; общий каталог доступен через
[DCP2 CACHE](dcp2/client.md#кэш-устройства-и-показатели).

Смещение задаётся в байтах, для слов требуется выравнивание на 4 и
попадание в регион. Диагностические операции PL не синхронизируют
изменения с кэшем и политикой `bvstkd`. Не выполняйте их одновременно
с обслуживанием того же IP. [Карта платы](../system/platform/board.md) различает активные
узлы и сохранённые константы.

## Общие системные команды

В обеих ОС `system runtime` выдаёт JSON версии 1: `os`, `uptime_ms`,
`capabilities`, `readiness` и `os_details`. Возможности описывают состав
сборки, готовность шин — текущее состояние. Показатели FreeRTOS включают
тик и heap; Нейтрино сообщает PID и число процессоров.

`system network` разделяет `current` и `configured`, признак сохранения
`saved` и состояние линии. `saved:null` означает, что сохранение не
подтверждено. `system network set <ip> <mask> <gateway> <mac> [save-only]`
проверяет все параметры, обновляет RAM, пытается сохранить и при отсутствии
`save-only` применяет настройки. `saved` и `applied` независимы; ошибка
одной операции не отменяет выполненную другую. Параметры статические IPv4.

Поддержаны `ip addr show`, `ip addr set <IPv4>/<prefix>`, `ip link show`,
`ip link set address <MAC>`, `ip route show`,
`ip route set default via <gateway>`, `ip save`.
Смена IP может разорвать текущее соединение. Смена MAC через общий сервис
сохраняется в профиле; немедленное применение возвращает
`unsupported`, `saved=true`, `applied=false`. На текущем GEM-драйвере
Нейтрино восстановление MAC также не поддержано; это отражено в os_details.
Нейтрино восстанавливает `flash:/config/network.json` после запуска сетевого
драйвера; ошибочный файл не перезаписывается значениями по умолчанию.

`reboot -y [delay_ms]` требует явного подтверждения; задержка 0–5000 мс.
Нейтрино использует `shutdown -S reboot -q`; последующий образ определяется режимом
загрузки платы. Автономная установка Нейтрино остаётся отдельным этапом.
