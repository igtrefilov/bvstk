# HTTP API

HTTP-сервер FreeRTOS позволяет внешней программе получать состояние
BVSTK, менять настройки устройств и работать с файлами. Веб-интерфейс
пользуется теми же операциями. Сервер принимает запрос, вызывает
соответствующий сервис и формирует ответ с результатом.

## Подключение

Запросы выполняются на компьютере, имеющем сетевой доступ к плате.
В примере используется адрес `192.168.0.10`; замените его адресом BVSTK.

```sh
curl -fsS http://192.168.0.10/api/version
```

Ответ со сведениями о сборке подтверждает доступность HTTP-сервера.
Готовность устройств и томов проверяется отдельно. Настройка адреса
описана в [главе о сети](../../network.md).
Сервер работает без аутентификации и TLS и рассчитан на доверенную сеть.

## Запрос и состояние системы

Одинаковый метод GET может возвращать разные виды данных. Снимок устройства
показывает конфигурацию и значения, уже находящиеся в памяти PS. Чтение
файла возвращает содержимое носителя. Получение журнала отдаёт сохранённые
наблюдения. Сам запрос кэша или журнала не начинает физический обмен
с устройством.

Для физического чтения или записи используется отдельное действие сервиса.
Оно проходит проверки параметров и политики. Изменение конфигурации
и запись файла тоже являются отдельными операциями. Поэтому клиенту
нужно выбирать запрос по тому состоянию, которое он намерен получить
или изменить.

## Результат операции

Сначала клиент проверяет завершение передачи и HTTP-код, затем разбирает
тело. Успешный HTTP-ответ может сообщать о неготовом томе или содержать
`saved:false`. Поле `ok` есть у результатов действий, но не обязательно
присутствует у списков и снимков. Значение ответа определяется маршрутом.

При сетевом обрыве действие уже могло выполниться. Например, файл мог
быть записан частично или настройки могли примениться до потери ответа.
Клиент получает текущее состояние и сверяет результат перед повтором.
Для большого файла нужно проверить полноту полученного содержимого:
отправленные заголовки уже нельзя изменить при поздней ошибке чтения.
