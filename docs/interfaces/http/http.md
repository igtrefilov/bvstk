# HTTP API

HTTP-сервер FreeRTOS предоставляет состояние системы, настройки устройств
и доступ к файлам. В примерах используется адрес `192.168.0.10`;
замените его адресом платы. Сервер работает без аутентификации и TLS,
поэтому подключение рассчитано на доверенную сеть.

## Обращение к серверу

Запросы выполняются на компьютере. Для проверки доступности сервера
прочитайте сведения о сборке:

```sh
curl -fsS http://192.168.0.10/api/version
```

Ответ содержит дату и время сборки, а также порт HTTP. Поля этого
ответа и запросы состояния ОС описаны в [главе о системе](system.md).

Ключ `-f` позволяет отличить HTTP-ошибку по коду завершения `curl`,
но содержимое ответа нужно проверять отдельно. Например, успешный
HTTP-ответ может содержать признак неготового тома или ошибку сохранения.

## Общие правила

Поддерживаются GET и PUT. Каждый запрос обслуживается с закрытием
соединения; ответы формируются как HTTP/1.0 с `Connection: close`.
Не рассчитывайте на постоянное HTTP-соединение, конвейер запросов,
Range. Для PUT требуется `Content-Length`
либо `Transfer-Encoding: chunked`; без обоих возвращается 411.

JSON-ответы имеют `Content-Type: application/json`, в прежних маршрутах
также указывается `charset=utf-8`; ошибки прежних маршрутов обычно
передаются текстом. Клиент должен проверять HTTP-код,
полноту тела, корректность JSON и содержимое результата. HTTP 200
не всегда означает успешное сохранение или пригодный JSON.

Тела API должны быть обычными JSON-объектами с уникальными ключами,
десятичными целыми числами, строками и `true`/`false` согласно таблицам.
В прежних маршрутах разбор реализован поиском полей, а не полной проверкой JSON-схемы.
Не полагайтесь на приём некорректных документов, неизвестных полей или
на одинаковую обработку неверного типа и отсутствующего поля.

| PUT-маршрут | Максимум тела, помещающийся в буфер обработчика |
|---|---:|
| `/api/net` | 1023 байта |
| `/api/i2c` | 2047 байт |
| `/api/diag/i2c/read`, `/api/diag/i2c/write` | 511 байт |
| MEM, reboot | 255 байт |

Более длинное тело может быть разобрано частично: общего гарантированного
ответа 413 нет. Не превышайте эти пределы. Они не относятся к потоковым
файловым PUT и новым маршрутам `/api/ui/`, у которых тело проверяется отдельно.

Повторный `Content-Length`, неверное число, неподдерживаемое
`Transfer-Encoding` и сочетание `chunked` с `Content-Length` отклоняются.
Ожидание входных данных заголовка ограничено пятью секундами бездействия;
чтение тела и отправка ответа — 30 секундами без прогресса. Это сетевые
пределы, не тайм-аут FAT или всего запроса. Одновременно исполняется один
запрос; передача большого файла задерживает остальные операции.
