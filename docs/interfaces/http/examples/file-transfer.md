# Загрузка и проверка файла

Пример создаёт на томе Flash новый файл `device-note.txt`, затем читает
его обратно и сравнивает с исходным. Нужны HTTP-сервер BVSTK,
готовый том и свободное имя в его корне. Команды выполняются
в отдельном рабочем каталоге компьютера.

```sh
bvstk_url='http://192.168.0.10'
curl -fsS "$bvstk_url/api/ui/volumes"
```

Перед продолжением убедитесь, что у записи `flash` установлено
`ready:true`. Получение списка не подготавливает неготовый носитель.

## Передача

Подготовьте небольшой файл:

```sh
printf '%s
' 'Описание условного устройства device_a' > device-note.txt
curl -sS -X PUT --data-binary @device-note.txt   -o upload-result.json -w '%{http_code}
'   "$bvstk_url/api/ui/file?volume=flash&path=%2Fdevice-note.txt&confirm=true"
cat upload-result.json
```

При успехе ответ имеет HTTP 200, `ok:true` и число записанных байтов
`bytes`. HTTP 409 означает, что имя уже занято. В этом примере перезапись
не разрешена: выберите другое свободное имя и измените его в обоих запросах.

Если передача оборвалась, файл мог остаться частичным. До повтора получите
его состояние через `action=stat` файлового API и при необходимости
прочитайте содержимое. Сам факт существования файла не подтверждает
успешную загрузку.

## Проверочное чтение

После успешного ответа прочитайте файл и сравните байты:

```sh
curl -fS -o received-note.txt   "$bvstk_url/api/ui/file?volume=flash&path=%2Fdevice-note.txt"
cmp device-note.txt received-note.txt
```

Сначала проверьте успешное завершение `curl`. Затем код завершения `cmp`,
равный нулю, подтвердит совпадение содержимого. Ошибка GET может оставить
частичный локальный файл; использовать его как завершённый результат нельзя.

Так же можно проверить загруженный профиль. Однако совпадение JSON
на носителе не означает применения настроек работающим сервисом.
Эти действия разделены в [жизненном цикле конфигурации](../../../configuration/lifecycle.md).

## Копия каталога

Для получения каталога `flash:/config` предусмотрен TAR:

```sh
curl -fS -o config.tar "$bvstk_url/tar/flash/config"
tar -tf config.tar
```

Обход выполняется по текущей файловой системе. На время получения копии
исключите изменения исходных файлов. Проверьте завершение передачи
и читаемость архива перед использованием его как резервной копии.

Принцип потоковой передачи описан в [основной главе](../file-transfer.md),
форматы запросов и ответы — в [справочнике](../reference/files.md).
