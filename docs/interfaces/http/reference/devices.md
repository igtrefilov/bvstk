# Маршруты устройств и политик

[Общие требования](common.md#правила-api-устройств).

## Подсистемы

Маршрут `/api/ui/bus`; query `bus=i2c` или `bus=mdio`.

| GET-запрос | Ответ |
|---|---|
| Без `name` | `ready`, массив `devices` |
| Запись `devices` | `name`, числовой `address`, логический `available`, строки `presence`, `policy` |
| С `name` | Снимок устройства по таблице ниже |
| С `name` и `action=cache` | `cache`, `presence`, `uptime_ms`; для MDIO также `stats`; без физического обмена |

| Поле | Смысл |
|---|---|
| `config` | Совместимая проекция настроек RAM в прежнем формате API, не документ профиля v2 |
| `revision` | Восемь hex-символов, FNV-1a 32 бит от канонического JSON |
| `saved` | `true`, если снимок совпадает с сохранённым конфигом; `false`, если нет; `null`, если прочитать состояние не удалось |
| `file_name` | Относительный путь в `flash:/config/i2c/` либо `flash:/config/mdio/`: `<id>/<id>.json`; старые `<id>/profile.json` и `<id>.json` принимаются для миграции |
| `register_map` | Имя карты рядом с профилем, пустая строка при отсутствии |
| `view` | Имя JS-формы рядом с профилем, пустая строка при отсутствии |
| `available` | `true` только при `presence=responding`; не просто наличие профиля |
| `presence` | `unknown`, `responding` или `unavailable`; то же поле есть в списке устройств |
| `cache` | Кэш I²C или MDIO: массив `reg`, `val`, `valid`, `source`, `updated_ms` |
| `uptime_ms` | Время с запуска PS, миллисекунды; позволяет оценить возраст записей кэша |
| `address_spaces` | Для многопространственного I²C-профиля: массив `id`, числовых `address`, `first`, `register_count`; также возвращается в списке устройств |
| `stats` | Только MDIO: общие счётчики `reads`, `writes`, `denied`, `errors`, `observed` |

| Свойство снимка | Правило |
|---|---|
| Источник | Рабочее состояние сервиса; файл читается [отдельно](files.md#содержимое-файла) |
| `register_map`, `view` | Метаданные пакета, вне `config`; сохраняются при apply и save |
| Файлы карты и формы | GET `/api/ui/file` из Flash; PS не исполняет JS и не расшифровывает битовые поля |
| `config` | Прежние поля API: `name`, `reg_count`, `policy`, `whitelist`, `blacklist`, `settings`, параметры шины |
| `apply` | Сохраняет метаданные и ID ресурсов v2 |
| `save` | Записывает v2 через ConfigStore; для старого несовместимого имени — прежний формат |
| Сравнение `saved` | Нормализованные настройки проекции; не байты файла и не метаданные `device` |
| Атомарность снимка | Кэш, счётчики и конфигурация читаются независимо |

При нескольких пространствах `config.addr_7b` содержит первый адрес,
`config.reg_count` — суммарное число ресурсов. Все поля `reg` в кэше,
списках правил и настройках — индексы внутри этого общего диапазона.
Локальный адрес регистра равен `reg - address_spaces[].first`.
Проекция `config` сохраняет параметры пространств при `apply` и `save`.
Изменение адресов, размеров, порядка пространств и маршрута требует перезапуска.

### Кэш и присутствие устройства

| Поле или условие | Значение |
|---|---|
| `source=settings` | Начальное значение |
| `source=I2C` | Успешный физический обмен I²C |
| `source=PHY` | Обмен с PHY по MDIO |
| `valid=false` | Достоверного значения нет; `val` — незначащий заполнитель |
| `updated_ms` | Время обновления с запуска PS, миллисекунды; 0 для недостоверной записи |
| `stats.errors` | Ошибки реального чтения, записи, аппаратного подтверждения; фоновые проверки отсутствующего PHY исключены |
| `stats.observed` | Обработанные входные ячейки; не число всех кадров на проводах |

| Присутствие | Условие |
|---|---|
| I²C `unknown` | Нет подтверждённого обмена после старта или смены адреса |
| I²C `responding` | Успешное физическое чтение |
| I²C `unavailable` | Ошибка обмена, включая NACK и таймаут |
| I²C: кэш, settings, отказ политики, успешная запись без чтения | Не подтверждают присутствие |
| GET списка | Не сканирует шину |
| I²C: фоновое обнаружение отключения | Безопасный ресурс опрашивается при `presence_check_enabled`; план `acquisition` поддерживает актуальность выбранных диапазонов |
| MDIO `responding` | Достоверные ID PHY в регистрах 2 и 3, прочитанные менее 3 секунд назад |
| MDIO иначе | `unavailable` |
| Старый ответ I²C без `presence` | `available` означал готовность сервиса; новым интерфейсом считается непроверенным |

Для устройства с несколькими пространствами общая `presence` относится
к первому адресу. Ошибка дополнительного адреса не сбрасывает её.

### Действия PUT

Query: `bus`, `name`, `action`.

| `action` | Дополнительные параметры | Действие |
|---|---|---|
| `apply` | `revision` | Полная конфигурация JSON в теле; применение только в RAM |
| `save` | `revision` | Явное сохранение текущего снимка через ConfigStore |
| `read` | `reg` | Физическое чтение; ответ `ok`, `reg`, `val` |
| `write` | `reg`, `val`, `confirm=true` | Запись с проверкой политики; без сохранения во Flash |
| `invalidate` | Нет | Только MDIO: сброс достоверности кэша |

| Условие | Требование |
|---|---|
| Действие без конфигурационного тела | Пустое тело; Content-Length: 0 допустим; `{}` не передаётся |
| Тело apply | До 32767 байт, без NUL; превышение — 413, неполное или неверное тело — 400 |
| I²C apply | Обязательны `name`, `addr_7b`, `reg_count`, `max_value_code`, `policy`, `whitelist`, `blacklist`, `settings` |
| Неизвестные корневые поля, дубликаты ключей, неверная грамматика | Отклоняются; MDIO использует свой строгий кодек |
| Имя и число регистров | Неизменны |
| I²C `max_value_code`, начальные `settings` | Через этот API не изменяются |
| Занятый адрес I²C | 409 |
| Проверка `revision` | Перед apply и save; для apply повторно после чтения тела |
| Несовпадение `revision` | 409 без применения черновика |
| Защита ревизией | 32-битный хеш; не криптографический идентификатор и не атомарный compare-and-swap с shell или DCP2 |
| Параллельное редактирование | Между проверкой и применением возможно изменение; требуется один писатель |
| Изменение политики | Не выполняет физические записи настроечных регистров |
| Запись I²C | Синхронизирует RAM-модель; Flash меняется по save |
| Успешная запись MDIO | Подтверждает передачу кадра, не приём PHY |
| Физическое чтение | Возможны эффекты latch и read-clear |

В `read` и `write` допустим дополнительный query `space=<id>`. Тогда
`reg` — локальный адрес в этом пространстве; ответ содержит общий индекс.
Без `space` параметр `reg` сохраняет смысл индекса кэша. Неизвестное
пространство, неверный регистр или `space` для MDIO возвращают HTTP 400.

## Совместимые маршруты прежнего интерфейса

Форматы отличаются от `/api/ui/bus`.

## GET /api/i2c

Без `name`: логический `ready`, числовой `count`, массив `devices`.
Поля записи устройства:

| Поле | Тип и смысл |
|---|---|
| `name` | Строка, имя устройства |
| `addr_7b` | Целое, 7-битный адрес |
| `file_name` | Строка, имя конфигурационного файла |
| `policy` | Строка `whitelist` или `blacklist` |
| `settings_len`, `whitelist_len`, `blacklist_len` | Целые, длины соответствующих массивов |

| Условие | Ответ |
|---|---|
| С `name` | `ready`, объект `device`: `name`, `addr_7b`, `file_name`, `policy`, `whitelist`, `blacklist` |
| Элемент списка правил | `reg`, `val` |
| `settings`, `reg_count`, `max_value_code` | Не возвращаются |
| Неизвестное имя | HTTP 200, `ready`, `error:"unknown device"` |

## PUT /api/i2c

| Поле | Тип | Условие |
|---|---|---|
| `name` | Строка | Обязательно, существующее устройство |
| `policy` | Строка | Необязательно; `whitelist` или `blacklist` |
| `whitelist` | Массив `{reg,val}` | Необязательно; заменяет целиком соответствующий список |
| `blacklist` | Массив `{reg,val}` | Необязательно; заменяет целиком соответствующий список |

| Условие | Результат |
|---|---|
| Поле отсутствует | Прежнее значение сохраняется |
| Пустой массив | Список очищается |
| Адрес, имя, число регистров, settings | Не редактируются |
| Предел тела | 2047 байт |
| Успех | HTTP 200, `ok:true`, `saved:false`; сервис и RAM-модель изменены, файл не записан |
| 503 | `config_store not ready` |
| 400 | Пустое тело, отсутствующее имя, неверные политика или массив |
| 404 | `unknown device` |
| 500 | `set failed`; частичные изменения не исключены |

## Диагностические операции I²C

| Маршрут | Дополнительное обязательное поле | Ответ HTTP 200 |
|---|---|---|
| `PUT /api/diag/i2c/read` | — | `ok:true`, строка `name`, целые `reg`, `val` |
| `PUT /api/diag/i2c/write` | `val`: целое 0–255, ограниченное max_value_code и политикой | `ok:true` |

| Общее поле | Требование |
|---|---|
| `name` или `addr_7b` | Непустое имя либо целый адрес 0–127; имя имеет приоритет |
| `reg` | Обязательное целое 0–255, дополнительно ограничено моделью |

| Условие | Результат |
|---|---|
| Успешная запись | Синхронизация RAM-модели без сохранения файла |
| 400 | Отсутствующее или неверное поле |
| 404 `device not found` | Устройство не найдено; возможно также при неготовом сервисе |
| 500 `i2c read failed` | Ошибка чтения |
| 403 `DENIED` | Любой неуспех сервисной записи, не только отказ политики |
| Таймаут вызова сервиса | 100 мс; не предел общего времени HTTP-запроса |

В совместимых диагностических маршрутах выбор по `name` использует общий
индекс `reg`. При выборе по `addr_7b` номер `reg` относится к выбранному
адресному пространству. Выход за его диапазон возвращает HTTP 400.

## MDIO

Файлы конфигурации: `flash:/config/mdio/`.
