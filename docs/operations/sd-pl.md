# PL SD через SPI Master

FreeRTOS-приложение BVSTK работает с внешней SD-картой через существующее
ядро SPI Master и AXI DMA. Драйвер и сервис PL SD входят
в обычную сборку `app_bvstk.elf`. Поверх проверенных операций с секторами подключена FatFs:
том `sd-pl:/` (внутри `2:/`). Это не штатный PS SD-слот AX7020 (`sd:/`).

Текущий режим предназначен для SDHC/SDXC с секторной адресацией. Карта
инициализируется и монтируется автоматически при каждом старте программы.
При монтировании носитель только читается. Используется существующая
FAT12/16/32; форматирование и восстановление разметки не выполняются.
Поддерживается superfloppy либо первый подходящий первичный раздел MBR.
exFAT, GPT и расширенные разделы не поддерживаются. При отсутствии подходящей
ФС том остаётся недоступен, остальные службы продолжают работать.

## Подключение

| J10 | Контакт FPGA | Сигнал модуля |
|---:|---|---|
| 2 | питание 5 В | VCC внешнего модуля с соответствующим питанием |
| 4 | W18 | MOSI |
| 6 | P14 | MISO |
| 8 | Y16 | CS |
| 10 | V15 | SCK |

Обязательна общая земля. Сигналы FPGA — LVCMOS33; 5 В относятся к питанию
подходящего модуля, а не к уровням его SPI. Рабочий UART стенда:
`/dev/ttyUSB0`, CP2102N, 115200 8N1, без аппаратного управления потоком.
Имя устройства проверяется через `/dev/serial/by-id/`.

## Сборка и загрузка

Используйте штатную [сборку FreeRTOS](../build/freertos.md)
и [JTAG-загрузку](../build/jtag.md) согласованного комплекта PS и PL.
После загрузки перейдите к проверке тома ниже.

## Команды

После загрузки в UART должно появиться:

```text
SD-PL: mounted sd-pl:/ (read/write, existing filesystem)
```

Для работы с уже имеющимися данными:

```text
sd-pl info
ls sd-pl:/
cd sd-pl:/
ls
cat roundtrip.json
```

Имя существующего файла в примере замените на нужное. `sd-pl info` должен
показать `mounted=1`. Приглашение может первоначально оставаться `bvstk/sd>`:
оно указывает текущий том консоли, а не единственный смонтированный том.
После `cd sd-pl:/` приглашение становится `bvstk/sd-pl>`; `pwd` выводит
внутренний путь `2:/`.

Пример записи в **новый выбранный вами** каталог:

```text
mkdir sd-pl:/demo
fs write sd-pl:/demo/hello.txt Hello
fs append sd-pl:/demo/hello.txt , world!
cat sd-pl:/demo/hello.txt
cp sd-pl:/demo/hello.txt sd-pl:/demo/copy.txt
mv sd-pl:/demo/copy.txt sd-pl:/demo/renamed.txt
ls sd-pl:/demo
```

`fs write` заменяет содержимое существующего файла, `fs append` дописывает.
Текст — остаток командной строки, без обработки кавычек/escape и без
автоматического перевода строки. UART имеет редактор строки с историей,
стрелками и `Tab`; редактор хранит до 511 символов, но общий диспетчер
разбирает первые 255 символов команды. Для длинных/двоичных файлов
используйте HTTP-загрузку или копирование с другого тома (SSH/SCP — при
включённой SSH-сборке). При вставке длинной команды в minicom задайте
задержку символов: консоль опрашивает UART без управления потоком. Тестовый
скрипт ниже уже дозирует передачу.
`rm` удаляет файл/пустой каталог, `rm -r` — дерево. `touch` усекает файл.

Сырые `sd-pl init/read/write/test/status/blocklen` запрещены, пока картой
владеет файловая подсистема, включая случай неудачного монтирования.
Это защита ФС от прямой записи в её сектора. `sd-pl info` доступна.
`fs format sd-pl confirm` всегда отклоняется в данном профиле.
После ошибки I/O/CRC/тайм-аута том недоступен до перезапуска системы;
повторная запись и скрытое перемонтирование не выполняются. Извлекать и
заменять карту следует только при выключенном устройстве.

## Ограничения работы

Запись сектора сопровождается полным чтением и сравнением данных.
Текущий порт также выполняет повторную инициализацию карты между
командами. Поэтому файловые записи могут быть медленными; повторять
их по предположению о зависании нельзя.

FAT не журналируется. Потеря питания при изменении метаданных может
повредить файловую систему. Горячая замена карты и одновременное
изменение одного файла разными клиентами не поддерживаются.
Порядок DMA, проверки CRC и особенности ответа CMD17 разобраны
в [главе драйвера](../system/pl-subsystem/spi/drivers/master.md).

## Автоматическая проверка с компьютера

Закройте minicom/другие читатели UART. Нужны Python 3 (только стандартная
библиотека) и доступ к последовательному порту. Проверка без записи:

```sh
python3 tools/sd_pl_smoke.py --port /dev/ttyUSB0
```

Файловая проверка создаёт отдельный каталог `sd-pl:/bvstk-fs-<дата-время-pid>`
и записывает тестовые файлы только туда. Она не форматирует карту:

```sh
python3 tools/sd_pl_smoke.py --port /dev/ttyUSB0 --load \
  --fs-test --quiet --log build/sd-pl/fs-smoke.log
```

Проверяются создание каталогов и файла 4800 байт (дополнение, переход через
границы секторов/4-КиБ кластера), точное содержимое при чтении, копирование,
переименование, усечение, пустой файл/удаление, запрет raw-команд и формата.
`--load` загружает полный ELF с существующим bitstream до теста и повторно
после записи, затем проверяет сохранность файлов. Без этого флага тест
работает с уже запущенной системой, без проверки перезапуска.
Тестовые файлы остаются в указанном в `HOST PASS` каталоге.
`--command '...'` только записывает ответы консоли, не оценивая успех команды;
код 0 в этом режиме не означает успешность файловых операций.
Старый `--write-test` предназначен для raw-профиля и не допускается в
обычной сборке с автоматически монтируемой ФС.
