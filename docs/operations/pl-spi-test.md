# Программный тест PL SPI под FreeRTOS

Ветка `diag/pl-spi-blackbox` содержит самостоятельную диагностическую
задачу. Ожидания взяты из сохранённой страницы SPI и материалов страницы
«Взаимодействие с SPI-Master». Объект теста — неизменённая PL; наблюдения
ограничены регистрами, BRAM, DMA, mailbox и обработчиком GIC в PS.

Исходники находятся в `src/apps/freertos/diagnostics/pl_spi_test/`.
`main.c` запускает только эту задачу и FreeRTOS. UART — 115200 8N1.
Сборка использует штатный сценарий BVSTK; другие службы приложения при
запуске теста не создаются. Тест должен быть единственным владельцем SPI,
его DMA и BRAM, включая доступ из другого CPU и JTAG AXI master.

## Аппаратный набор

`driver.c` берёт адреса и IRQ из `xparameters.h` выбранного XSA. Нет
поиска MMIO по неизвестным адресам или подстановки старого адреса BVSTK.
В проверенном при разработке экспорте:

| Ресурс | Значение |
|---|---|
| SPI Master | `0x43C40000` |
| AXI DMA Master | `0x40400000`, simple mode, DRE обоих каналов |
| SPI BRAM | `0x44000000..0x44001FFF` |
| IRQ Master | GIC ID `64` |
| Параметры IP | mode 0, FIFO ratio 4, активный низкий CS |

SHA-256 исходного XSA:
`5647badc88745a5340c86a9047960031738a142abd10e30fe9722f46ba3d9f49`.
SHA-256 исходного bitstream:
`57ea65c278af5a51f1ab9ef3b74e63344c7629f2e4e87a66ba271557a54a60d9`.
Вложенный в этот XSA `design.bit` имеет ту же сумму, что и отдельный файл.
Это идентификация входных файлов, а не доказательство того, что именно они
сейчас загружены в плату. Доступного регистра версии ядра спецификация
не задаёт; соответствие работающей PL аппаратному экспорту — условие запуска.

`ACCESS.CORE` записывает и читает два разных значения разрешённого регистра
задержки. `ACCESS.BRAM` проверяет два шаблона. Если предварительная проверка
не прошла, команды SD не выдаются. Программный тайм-аут ограничивает опрос
статуса, но не может прервать зависшую AXI-транзакцию или обработать неверную
аппаратную адресацию как обычную ошибку функции.

## Сборка

Из корня репозитория, с доступным Vitis 2021.2:

```sh
command -v xsct
test -s artifacts/fpga/design.xsa
CLEAN=0 ./build.sh freertos
test -s vitis_ws/app_bvstk/Debug/app_bvstk.elf
```

При смене XSA нужна согласованная пересборка BSP; `CLEAN=0` предназначен
для повторной сборки с тем же аппаратным набором. Полная штатная сборка
`./build.sh freertos` пересоздаёт производный `vitis_ws`.
Vivado и сборка PL для теста не требуются.

## Запуск с сохранением загруженной PL

На плате с уже настроенным PS/DDR и проверенной соответствующей PL можно
загрузить только ELF. Откройте UART до запуска. В интерактивном XSCT:

```tcl
connect
targets
targets -set -nocase -filter {name =~ "*Cortex-A9*#0*"}
stop
rst -processor
dow /home/ilya/Zynq/bvstk/vitis_ws/app_bvstk/Debug/app_bvstk.elf
con
```

Здесь нет команды `fpga`. Для платы без настроенного PS сначала нужна
инициализация PS из того же аппаратного набора. Штатный
`./run.sh freertos jtag` дополнительно сбрасывает систему и загружает
`design.bit`; его поведение описано в [руководстве JTAG](../build/jtag.md).

Прогон однократный. После `END PL_SPI_TEST` задача удаляется. Повторный
прогон выполняется повторной загрузкой ELF. Логи и SHA-256 ELF/XSA/bitstream
сохраняйте в `artifacts/pl-spi-test/`; этот каталог производный и не входит
в Git. Аппаратный прогон требуется отдельно от успешной сборки.

## Параметры и работа с картой

Все параметры находятся в
[config.h](../../src/apps/freertos/diagnostics/pl_spi_test/config.h).
По умолчанию выполняются программные сбросы, FIFO-векторы, инициализация
карты, CMD13/CMD16 и чтения CMD17. Данные на SD не записываются и не стираются.
Содержимое SPI BRAM при этом используется и перезаписывается тестом.

`READ_LBA` выбирает сектор для чтения; нужен также следующий существующий
сектор для A/B/A-проверки. `HAVE_GOLDEN=1` и `GOLDEN_CRC32` задают независимый
эталон CRC32/IEEE первых 512 байт этого сектора, полученный через другой
проверенный путь. Равенство повторных чтений не заменяет этот эталон.
Профиль инициализации рассчитан на карту SD v2, отвечающую на CMD8 с `0x1AA`.
CCS из OCR определяет блочную либо байтовую адресацию последующих команд.

Для записи задайте `ENABLE_WRITE=1`, `SCRATCH_LBA` и
`SCRATCH_SECTORS` от 2 до 8. Диапазон должен существовать на выделенной
тестовой карте; предыдущий и следующий сектор должны быть доступны для
контроля границ. Нужные данные заранее сохраните вне этой карты. Тест
пишет разные шаблоны во весь диапазон, затем читает все сектора и сравнивает
каждый байт. Исходные данные диапазона не восстанавливаются. Ёмкость карты
автоматически не определяется; её проверка относится к подготовке стенда.

Стирание дополнительно требует `ENABLE_ERASE=1` и `ERASED_BYTE`, равного
документированному для карты значению `0` или `255`. Диапазон должен быть
согласован с единицей стирания конкретной карты. CMD32, CMD33 и CMD38
выполняются последовательно, каждый с ожиданием своего завершения. Перед
стиранием проверяется запись шаблонов, после — содержимое всего диапазона,
CMD13 и соседние сектора. Неудачная запись автоматически не повторяется.

## Что считается результатом

Каждая строка `RESULT <ID> <VERDICT> <reason>` относится к отдельной проверке.
Перед ней печатаются ожидаемые/фактические значения и снимки состояния.

- `PASS` — выполнен критерий конкретной программной проверки.
- `FAIL` — наблюдение противоречит критерию либо операция не завершилась.
- `SKIP` — проверка отключена или относится к другой конфигурации/наблюдению.
- `BLOCKED` — отсутствует необходимый результат, эталон или однозначный контракт.

Итог `SUMMARY` содержит все четыре счётчика. При наличии `FAIL` общий
результат `FAIL`; при пропущенных/заблокированных пунктах — `INCOMPLETE`.
Успешный `PASS` отдельной проверки не доказывает работу всего ядра.

DMA проверяется по свежему IOC после сброса/очистки, Idle и отсутствию
ошибок. Команды дополнительно требуют свежий mailbox и `irq_sd_cmd_done`.
Для CMD17 проверяются ровно 514 принятых байт, CRC16 512 байт данных и
защитные значения, включая два неиспользуемых байта последнего AXI-слова.
GIC проверяется отдельными результатами; опрос регистра IRQ не подменяет
фактическое выполнение обработчика прерывания.

DMA-источник размещается в BRAM со смещения `0x400`, приёмник — с `0x1000`.
Mailbox расположен отдельно. Доступ к BRAM некэшируемый; DDR-буферы задачи
DMA не использует. Новый SD-запрос не сбрасывает SPI и не запускает SD-init
повторно; DMA сбрасывается между запросами согласно примерам разработчика.

Подробности неоднозначностей спецификации, интерпретации упаковки данных и
границ покрытия приведены в [матрице проверок](../development/pl-spi-test-matrix.md).
