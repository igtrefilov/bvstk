# Веб-интерфейс bvstk

FreeRTOS раздаёт статические файлы из `flash:/www/`; исходники находятся
в `web/assets/`. Отдельная сборка клиентского приложения сейчас не нужна.
Запрос `/` читает `index.html`, а данные интерфейс получает через `/api/*`.
В штатном Нейтрино этот HTTP-сервер не запускается.

## Разделы

Интерфейс использует светлую рабочую область, компактные таблицы и
графитовое дерево объектов. Логотип Росатома и название bvstk расположены
в шапке. Небольшая светло-серая птица находится внизу навигации;
псевдоволны под ней занимают всю ширину графитовой панели и доходят до
её нижнего края. Декор остаётся внизу при прокрутке дерева, без отдельной
подложки и фонового рисунка под данными.
Навигация состоит из четырёх групп:

- **Состояние**: начинается с таблицы **Состояние подсистем** с кнопкой
  обновления в её заголовке. Далее расположены хранилища, сеть и среда
  исполнения, справа — сведения о выбранной подсистеме. Отдельной верхней
  сводки нет; показатели памяти и времени работы доступны в разделе
  **Система** → **FreeRTOS**.
- **Подсистемы**: I²C, MDIO и SD-PL. I²C и MDIO используют общий порядок
  редактирования политик; кэш обеих шин объединён с регистровыми операциями
  и отображается в режиме реального времени.
- **Файлы**: тома `flash:/`, `sd:/`, `sd-pl:/`, каталоги, загрузка,
  скачивание, переименование, копирование файлов и удаление.
- **Система**: сеть, сведения о FreeRTOS и сборке, подтверждаемый перезапуск.

Дерево показывает загруженные системные профили из API, в том числе
профили неподключённых устройств, и позволяет перейти прямо к микросхеме,
тому или странице системы. I²C и MDIO используют общий значок шины
из двух линий с ответвлениями; устройства — значок микросхемы с выводами.
Внутри его правого верхнего угла находится точка: зелёная при подтверждённом
ответе, серая при отсутствии ответа или непроверенном состоянии.
Значки микросхем в дереве увеличены до 25 пикселей, точки — примерно
до 4 пикселей; цвет подтверждённого ответа сделан ярче.
Название профиля само по себе не подтверждает наличие оборудования.
Адреса обеих шин показываются одинаково, например `0x01`, без префикса PHY.
Значок **Система** — симметричная шестерёнка с восемью одинаковыми зубьями.
Значки хранилищ сохранены. Заголовки групп
**Подсистемы**, **Файлы** и **Система** сворачивают и разворачивают дерево
по нажатию мышью, Enter или пробелом, без перехода на другую страницу.
Переход выполняется через дочерний пункт; выбранным отмечается один объект.
Обновление данных не раскрывает свёрнутую группу, переход к новому объекту
раскрывает её при необходимости. На узком экране дерево
открывается кнопкой меню, а панель свойств переносится под таблицу.
Переходы и вкладки сохраняются в URL. Выбор строк таблиц доступен также
клавишами стрелок, Home, End, Enter и пробелом.

Статусы поступают от API. Недоступные размеры и статистика не заменяются
фиктивными значениями. Автообновление обзора выполняется раз в 15 секунд
при открытой вкладке; таблица кэша регистров обновляется примерно раз в 500 мс.
Проверка связи не заменяет актуальность снимка конфигурации.
Список устройств для точек в дереве обновляется раз в 15 секунд даже
при наличии черновика; это не перечитывает его настройки и не создаёт
физических чтений регистров. При потере связи точки становятся серыми.
У MDIO ответ подтверждают свежие ID из аппаратного кэша. У I²C нужен
успешный физический обмен чтения: до него точка серая, успешная запись
или начальное заполнение кэша её не зажигают. Автоматического сканирования
I²C нет; отключение обнаруживается только при следующем обмене.
При ошибке обновления последняя сводка остаётся видимой с отметкой
«Данные устарели». Снимок конфигурации в правой панели имеет собственное
время получения и не перечитывает Flash на каждом автоматическом опросе.

В шапке нет IP-адреса: зелёный индикатор и **Онлайн** означают доступность
платы из браузера, серый индикатор и **Оффлайн** — отсутствие связи.
Это не проверка доступа платы в Интернет. Проверка связи не зависит от
страницы, открытого диалога или черновика. В простое лёгкий запрос
`GET /api/version` выполняется примерно раз в секунду с таймаутом 2 секунды;
обычные ответы API также подтверждают связь. Ошибка операции HTTP не равна
потере сети. Событие отключения сети в браузере меняет статус сразу,
возврат сети или открытие вкладки запускает проверку без перезагрузки.

HTTP-сервер обслуживает одно соединение за раз, поэтому проверка не
добавляется в очередь поверх активной операции и приостанавливается
на время скачивания файла. В эти периоды статус обновляется по результату
операции и сетевым событиям браузера, а не с гарантированным периодом.
В скрытой вкладке частые проверки приостановлены; таймеры браузера не
являются механизмом жёсткого реального времени.

## Регистры

Таблица I²C и MDIO показывает регистр, **Значение в кэше** и **Последнее
обновление**. Последнее обновление — метка `T+HH:MM:SS.mmm` от запуска PS,
а не возраст строки на момент запроса. Кэш PS общий для shell, DCP2 и Web:
начальные значения профиля помечаются источником `settings`, успешный
физический обмен — источником шины. После ошибки обмена запись становится
недостоверной и в таблице показывается «—».

Страница **Регистры** получает лёгкий снимок кэша примерно раз в 500 мс
при открытой вкладке. Этот запрос не выполняет физического чтения регистра;
он только отображает изменения, которые уже записал сервис после реального
обмена. Справа находятся HEX, десятичное и битовое представления выбранного
регистра, поля и команды чтения и записи. **Прочитать** выполняет явное
физическое чтение, а его результат автоматически попадает в кэш.

Предварительная проверка по текущему снимку политики блокирует кнопку
записи с объяснением причины. Окончательное решение принимает сервис
при обработке запроса. Физическая запись требует подтверждения, не
повторяется автоматически и не сохраняет конфигурацию во Flash.
На наблюдательной вкладке регистров нет панели сохранения, если черновик
конфигурации не изменён. Фоновое обновление кэша приостанавливается, если
вкладка браузера скрыта или выполняется другая операция.

## Телеметрия и события

У каждого профиля I²C и MDIO доступны вкладки **Телеметрия** и **События**.
Телеметрия показывает наблюдения существующего PL и физические операции PS:
адрес, регистр, значение, инициатор и результат. Ошибочное чтение не выдаёт
нулевое или старое значение как реальные данные. Время — регистрация в PS
с разрешением системного тика, не аппаратная метка фронта на проводе.
В журнал попадают только подтверждённые взаимодействия: успешные операции PS
и физически перехваченные кадры PL.
Периодические проверки присутствия MDIO, неуспешные пробы неизвестного I²C
адреса и подготовка ответа I²C, не подтверждающая выдачу байтов, скрываются. Ошибка
обмена с устройством, которое ранее отвечало, остаётся телеметрией: она
показывает потерю связи, а не новую попытку зондирования. Если обменов ещё
не было, выводится «Нет подтверждённых взаимодействий».

В столбце **Результат** используются только два значения: «Успешно» и «Ошибка».
Нулевой код состояния отображается как «Успешно» зелёным цветом, любой ненулевой
код — как «Ошибка» красным цветом. Наблюдения без подтверждённого результата в
таблицу не выводятся.

События показывают попытки записи до проверки политики, отказы,
завершения и ошибки. Попытка и её результат — отдельные строки; запрещённая
операция остаётся видимой, но не передаётся устройству. Успех MDIO означает
переданный кадр, а не гарантированное применение значения PHY.
Источники: внешний мастер, консоль, DCP2, система и Web.

Новые данные запрашиваются примерно раз в 500 мс, при накопившейся очереди
чаще. Это не жёсткая гарантия задержки. Просмотр не включает автоопрос
регистров. **Пауза** прекращает опрос журнала и не добавляет новые строки в окно;
**Очистить экран** очищает только локальные строки браузера. Фильтры
по источнику, операции и регистру не влияют на работу устройства и DCP2.
При уходе со вкладки её запросы прекращаются, при возвращении продолжаются
с сохранённого курсора. В скрытой вкладке браузера и во время скачивания
файла опрос приостанавливается; накопленная история ограничена. После нажатия **Продолжить**
журнал дочитывается с сохранённого курсора, поэтому записи, накопившиеся на плате
за время паузы, могут появиться сразу.

В RAM платы хранятся отдельные кольцевые журналы по 256 подтверждённых записей
для каждой шины и каждого канала; в браузере — последние 512 строк.
Переполнение RAM и вытеснение старых строк браузера обозначаются отдельно.
Счётчик потерь RAM относится к подтверждённому журналу всей шины до фильтра
по адресу. Служебные пробы отбрасываются до записи в журнал и не считаются
потерянными телеметрическими строками.
Потери в PL не вычисляются: MDIO содержит последние записи по регистрам,
не FIFO кадров; чтения внешнего мастера из его slave-кэша PS не наблюдает.
Для I²C подготовка окна ответа не подтверждает чтение всех байтов мастером;
профиль не создаёт дополнительного аппаратного slave-перехватчика.
Журналы не сохраняются во Flash. Web и DCP2 читают один источник независимо.

## Изменение настроек подсистемы

В разделе **Политика** списки **Whitelist** и **Blacklist** представлены
двумя равными вкладками на всю ширину блока правил, со счётчиками записей.
Кнопка **Добавить правило** расположена отдельно под вкладками. Переключение
списка не меняет действующий режим политики: он выбирается в строке
**Политика записи** и применяется отдельно.

1. Откройте устройство в группе **Подсистемы**.
2. Измените политику, списки правил или другие доступные настройки.
   На этом этапе меняется только черновик в браузере.
3. Нажмите **Применить в RAM**. Работающий сервис начинает использовать
   новые значения, но файл конфигурации ещё не записан.
4. Нажмите **Сохранить во Flash**, чтобы сохранить снимок после перезапуска.
   Это соответствует явной команде `save` в shell.

При обнаружении изменившейся версии сервер возвращает конфликт и оставляет
черновик в браузере. Контроль версии является предварительной проверкой,
а не транзакцией с параллельными командами shell или DCP2. Во время
редактирования лучше использовать один клиент управления устройством.
Отбрасывание черновика не отменяет уже применённые настройки RAM.

Редактор политики показывает таблицу правил и поля выбранного правила
справа. Рядом сравниваются значения в рабочем снимке RAM и черновике;
отдельные сводка совпадения правил, подсказка режима и блок проверки правила
не дублируют эту информацию.
Добавленные и изменённые строки отмечаются; удалённые перечисляются
отдельно. Удаление строки не помечает следующие строки как изменённые.
Сравнение относится к текущему сеансу редактирования, не является
долговременным журналом и не заменяет проверку версии на сервере.

У I²C правило содержит регистр и точное значение. У MDIO есть маска:
`0x0000` соответствует любому значению, `0xFFFF` — точному совпадению.
Пустой whitelist запрещает записи. Регистровые операции проходят через
штатные сервисы и их политики; запись в регистр требует подтверждения.
Чтение регистров с latch или read-clear поведением может иметь побочные
эффекты. Успех записи MDIO подтверждает передачу кадра, не ответ PHY.

## Работа с файлами

Файловый менеджер работает только с уже смонтированными томами и не
форматирует носители. Для SD-PL не запускается полный подсчёт свободных
кластеров: показывается размер FAT-тома, а свободное место не определяется.

Том выбирается в дереве, путь — в строке каталога. Основные действия
расположены над таблицей и относятся к выбранному объекту. Справа
открываются свойства и предпросмотр подходящего текстового файла.
Выделение строки каталога показывает свойства; нажатие на имя каталога
либо **Открыть каталог** выполняет переход. Для текстового редактора
служит отдельная кнопка **Редактировать текст**.

Каталог загружается порциями по 64 записи. Фильтр применяется только к
загруженным именам; кнопка **Показать ещё** читает следующую порцию.
Копирование поддерживается между томами, переименование — внутри тома.
Копирование дерева и удаление непустого каталога не выполняются.
Предел пути — 120 байт UTF-8, компонента имени — 63 байта UTF-8.

Текстовые файлы до 32 КиБ можно просматривать и редактировать. Перед
записью повторно проверяется исходное содержимое; это не блокирует
изменения другими клиентами между проверкой и записью. Редактирование
JSON на диске не применяет его к работающей подсистеме.

Загрузка нового файла не перезаписывает существующий без подтверждения.
Успешный ответ отправляется после `f_sync` и `f_close`. При обрыве может
остаться частичный файл, а прежнее содержимое при перезаписи может быть
утрачено. Автоматических повторов записи нет: сначала проверьте результат.
После запуска скачивания фоновый опрос приостанавливается на две минуты;
для длительной передачи не запускайте другие операции одновременно.

HTTP не предоставляет аутентификацию или TLS. Используйте доверенную сеть;
подтверждение в диалоге не является контролем доступа на сервере.

## Совместимость с прошивкой

Эта версия использует [API веб-интерфейса](../reference/http-ui-api.md)
с префиксом `/api/ui/`. Если эти маршруты уже поддерживаются установленной
прошивкой, для оформления достаточно обновить `web/assets/`
на томе `flash:/www/`. Для подтверждения присутствия I²C нужна PS-версия
с полем `presence`; в старой версии этот ответ остаётся непроверенным.
Добавление обычных профилей описано в [наборе конфигурации](../../configs/README.md).
Изменения исходников PL не нужны.
Модули `js/registers.js`, `js/policy.js`, `js/observe.js` и `js/connection.js` входят в тот же
набор ресурсов и обновляются вместе с остальным интерфейсом.

Если `/api/ui/` ещё не поддерживается, сначала соберите обновлённую
PS-программу и загрузите её на устройство. Изменения PL не требуются.

```sh
./build.sh freertos
./run.sh freertos jtag
```

Первая сборка после добавления HTTP-исходников должна быть полной;
последующие сборки допускают `CLEAN=0`. JTAG сбрасывает систему и загружает
ELF в DDR, не обновляя постоянный загрузочный образ. Перед запуском
прочитайте [процедуру JTAG](../build/jtag.md) и остановите записи на носители.
После обновления PS загрузите веб-ресурсы способом ниже.

## Обновление загрузчиком

Проверьте готовность QSPI и доступность HTTP и TCP-консоли. Затем посмотрите
план загрузки без записи:

```sh
python3 web/upload_flash_www.py 192.168.0.10 --dry-run
```

Обычное обновление:

```sh
./web/upload_flash_www.sh 192.168.0.10
```

Загрузчик сравнивает локальные файлы с удалённым `manifest.json` по размеру
и SHA-256, создаёт каталоги через TCP-консоль, отправляет изменившиеся файлы
HTTP-запросами PUT и обновляет манифест. Это не атомарная замена всего
интерфейса: при прерывании возможен смешанный набор старых и новых файлов.
Сравнение с манифестом не заменяет чтение реального файла, если тот меняли
в обход загрузчика.

`--force` отправляет все файлы; `--no-mkdir` требует заранее подготовленных
каталогов. Источник, целевой каталог и порты настраиваются в
[параметрах загрузчика](../reference/build-options.md#загрузчик-веб-ресурсов).

## Полное дерево и отдельный файл

Для полного переноса можно создать TAR и загрузить его в существующий
целевой каталог:

```sh
tar -C web/assets -cf www.tar .
curl -fS -T www.tar http://192.168.0.10/tar/flash/www
```

Архив перезаписывает совпадающие имена, не создаёт атомарного снимка и
не гарантирует удаления файлов, которых больше нет в локальном наборе.
Для одного файла:

```sh
curl -fS --upload-file web/assets/index.html \
  http://192.168.0.10/flash/www/index.html
```

HTTP PUT не создаёт промежуточные каталоги. При ручной загрузке создайте их
заранее файловыми командами и сохраните копию заменяемого набора.

## Проверка

```sh
curl -fsS http://192.168.0.10/
curl -fsS http://192.168.0.10/api/version
curl -fsS http://192.168.0.10/api/ui/volumes
curl -fsS 'http://192.168.0.10/api/ui/bus?bus=mdio'
```

Если `/` возвращает 404, проверьте `flash:/www/index.html`. Если страница
открылась без данных, проверяйте API отдельно от статики. Для отсутствующих
CSS/JS сопоставьте URL из браузера с путями на томе. При старом отображении
сравните манифест и файлы, затем обновите кэш браузера; повторная отправка
всех ресурсов не должна быть первым предположением о причине.

Проверьте переходы между разделами, чтение каталогов и конфигурации.
Для пробной записи используйте отдельный новый каталог и файл. Проверку
политики и сохранения проводите с допустимыми настройками подключённого
устройства. [Автоматические проверки](../development/testing.md) используют
модели и не заменяют этот этап на плате.
