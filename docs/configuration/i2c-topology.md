# I²C со свитчами

PS использует общий обработчик `bvstk_i2c_bridge`. Его поведение задают
профили: адреса, маршруты, байтовый формат, политика, кэширование и
проверка записи. Названия моделей служат подписями. Карта регистров и
`view.js` расшифровывают кэш в разделе «Показатели».

## Пакеты и подключение

Прямое устройство: `configs/i2c/<device>/<device>.json`.
Устройство за свитчом: `configs/i2c/<switch>/<device>/<device>.json`.
Вложенный свитч оформляется таким же пакетом; глубина маршрута — до четырёх.
В каждой папке лежат собственные `register_map.json` и `view.js`.

При установке на FreeRTOS относительная структура сохраняется под
`flash:/config/i2c/`. Полная схема каталогов приведена в
[описании конфигурации](configuration.md#размещение-и-связи-файлов).

Набор в репозитории:

| Пакет | Подключение в профиле | Формат обмена | Начальная политика записи |
|---|---|---|---|
| `pca9545a` | Контроллер, `0x70` | Управляющий байт без адресного префикса | Только `0`, `1`, `2`, `4`, `8` |
| `pcf8563` | `pca9545a`, канал 0, `0x51` | 16 байтовых регистров, циклический указатель | Все записи запрещены |
| `p24c02a` | `pca9545a`, канал 0, `0x57` | 256 байт, страница 8 байт, пауза 5 мс, проверка чтением | Все записи запрещены |
| `pca9555` | `pca9545a`, канал 3, `0x20` | 8 регистров, указатель переключается внутри пары | Все записи запрещены |

Адреса, родитель и канал — параметры установки. При другом подключении
их меняют в `transport`. Идентификаторы, карты и формы не содержат
позиционных обозначений платы. PCA9555 показывает выводы `IO0_0…IO1_7`;
назначение подключённых к ним цепей определяется схемой установки.

Каналы без профилей остаются видимыми в дереве web UI. Подключение
неизвестного модуля к разъёму требует отдельного профиля этого модуля.

## Полный пример свитча

Файл `configs/i2c/pca9545a/pca9545a.json`:

```json
{
  "schema_version": 2,
  "id": "pca9545a",
  "device": {"model": "PCA9545A", "vendor": "NXP", "class": "bridge"},
  "transport": {
    "bus": "i2c", "controller": "pl_i2c_0",
    "address": "0x70", "address_bits": 7
  },
  "protocol": {
    "driver": "bvstk_i2c_bridge",
    "options": {"max_write_value": "0x0F"},
    "transfer": {
      "address_bytes": 0,
      "read_sequence": {"mode": "fixed"},
      "write_sequence": {"mode": "fixed"},
      "cache_after_write": "invalidate",
      "host_read": "fresh",
      "host_current_read": true
    },
    "switch": {
      "resource": "control",
      "select_mask": "0x0F",
      "preserve_mask": "0x00",
      "channels": [
        {"select": "0x01", "match_mask": "0x01"},
        {"select": "0x02", "match_mask": "0x02"},
        {"select": "0x04", "match_mask": "0x04"},
        {"select": "0x08", "match_mask": "0x08"}
      ]
    }
  },
  "defaults": {
    "register": {
      "width_bits": 8, "access": "rw", "write_mask": "0xFF",
      "cache": {"mode": "driver"}, "verify": {"mode": "driver"}
    }
  },
  "resources": [
    {"id": "control", "kind": "register", "address": "0x00"}
  ],
  "policy": {
    "read": {"mode": "blacklist", "rules": []},
    "write": {
      "mode": "whitelist",
      "rules": [
        {"resource": "control", "match": {"value": "0x00", "mask": "0xFF"}},
        {"resource": "control", "match": {"value": "0x01", "mask": "0xFF"}},
        {"resource": "control", "match": {"value": "0x02", "mask": "0xFF"}},
        {"resource": "control", "match": {"value": "0x04", "mask": "0xFF"}},
        {"resource": "control", "match": {"value": "0x08", "mask": "0xFF"}}
      ]
    }
  },
  "register_map": "register_map.json",
  "view": "view.js"
}
```

`0x00` здесь — логический номер управляющего байта в BVSTK.
На физическую шину при записи отправляется только значение управления.
Карта расшифровывает младшие четыре бита как каналы, старшие — как
состояния входов прерываний. Новая маска действует после STOP.

## Полный пример оконечного устройства

Файл `configs/i2c/pca9545a/pca9555/pca9555.json`:

```json
{
  "schema_version": 2,
  "id": "pca9555",
  "device": {"model": "PCA9555", "vendor": "NXP", "class": "gpio"},
  "transport": {
    "bus": "i2c", "controller": "pl_i2c_0",
    "address": "0x20", "address_bits": 7,
    "parent": "pca9545a", "channel": 3
  },
  "protocol": {
    "driver": "bvstk_i2c_bridge",
    "options": {"max_write_value": "0xFF"},
    "transfer": {
      "address_bytes": 1,
      "read_sequence": {"mode": "wrap", "span": 2},
      "write_sequence": {"mode": "wrap", "span": 2},
      "cache_after_write": "invalidate",
      "host_read": "fresh",
      "host_current_read": true
    }
  },
  "defaults": {
    "register": {
      "width_bits": 8, "access": "rw", "write_mask": "0xFF",
      "cache": {"mode": "driver"}, "verify": {"mode": "driver"}
    }
  },
  "resources": [
    {"id": "input0", "kind": "register", "address": "0x00", "access": "ro"},
    {"id": "input1", "kind": "register", "address": "0x01", "access": "ro"},
    {"id": "output0", "kind": "register", "address": "0x02"},
    {"id": "output1", "kind": "register", "address": "0x03"},
    {"id": "polarity0", "kind": "register", "address": "0x04"},
    {"id": "polarity1", "kind": "register", "address": "0x05"},
    {"id": "config0", "kind": "register", "address": "0x06"},
    {"id": "config1", "kind": "register", "address": "0x07"}
  ],
  "policy": {
    "read": {"mode": "blacklist", "rules": []},
    "write": {"mode": "whitelist", "rules": []}
  },
  "register_map": "register_map.json",
  "view": "view.js"
}
```

Пустой whitelist сохраняет безопасное исходное состояние: чтение
доступно, физические записи запрещены. Разрешения добавляются обычными
командами политики и фиксируются командой `save`. Регистры `input0`
и `input1` остаются доступными только для чтения.

Полный перечень значений: [справочник профиля](reference/device-profile-v2.md#обмен-i²c).

## Как проходит обращение

Для команды `i2c pca9555 r 0x00` PS выполняет:

```text
Заблокировать PL master
  → прочитать управление pca9545a
  → проверить политикой выбор канала 3
  → записать код 0x08
  → прочитать регистр 0x00 устройства pca9555
  → восстановить прежнюю маску каналов
Разблокировать PL master
```

Внутреннее переключение не меняет постоянно выбранный внешним хостом
канал. Для вложенных свитчей маршрут открывается от корня к устройству,
восстанавливается в обратном порядке. Ошибка обмена также запускает
восстановление. Его неуспех делает состояние маршрута неизвестным.

Внешний хост сам записывает управляющий байт свитча. После подтверждения
PS допускает обращения к профилям активного канала. До первого
подтверждённого чтения или записи управления маршрут считается
неизвестным. Одновременный выбор нескольких каналов с одинаковыми
адресами даёт неоднозначную цель — PS отклоняет обращение.

Профили и кэш различаются по ID устройства. В web UI телеметрия
фильтруется по устройству, поэтому одинаковые адреса на разных каналах
не смешиваются. Старые DCP2-команды, адресующие только I²C-адрес,
отклоняют неоднозначную цель. Для чтения снимков кэша используется
уникальный ID из каталога DCP2 CACHE.

## Совместимость и ограничения

- Старые профили без `transfer` сохраняют прежний режим обмена.
- Топология и параметры обмена загружаются при старте. Политики меняются
  во время работы; `save` сохраняет профиль в его исходной папке.
- На существующей Flash встроенный набор не дополняет имеющийся набор
  I²C-профилей. Новые пакеты устанавливаются явно. Карты и формы в ELF
  не встраиваются.
- Поддерживаются байтовые I²C-регистры: до 256 на устройство, до 32
  профилей. Добавление другого протокола, например командных пакетов,
  CRC или многобайтовых значений, требует расширения общего обработчика.
- На downstream-стороне много­байтовая запись раскладывается на отдельные
  байтовые операции с учётом `write_sequence`. Для устройств, требующих
  атомарного пакета, этот режим непригоден.
- PL slave использует существующий mailbox и ограниченное растягивание
  такта. Дополнительные операции маршрутизации увеличивают время ответа.
  Побайтовая обработка не гарантирует согласованный снимок RTC на границе
  секунды. Временные характеристики проверяются на конкретном стенде.
- Аппаратная адресная маска PL включает адреса всех настроенных устройств.
  Программный отказ маршрута не гарантирует NACK в адресной фазе:
  это ограничение существующего ядра. Внешний reset свитча тоже требует
  повторной синхронизации его состояния чтением или записью управления.
- Для EEPROM отдельно проверяется вход WP. Разрешение политикой само
  по себе не снимает аппаратную защиту. Проверка `readback` обнаруживает
  несовпадение считанного байта после записи.

В программных тестах проверяются профили, маршруты, очистка после ошибок,
политики, одинаковые адреса, указатели и сохранение пакетов.
Подтверждение физической работы требует проверки с подключёнными
устройствами и текущим bitstream.

## Документация микросхем

Карты включают все байтовые адреса описанного диапазона и все биты
каждого регистра. Зарезервированные и недопустимые коды показываются
явно. Показатели используют только имеющиеся значения кэша.

- [PCA9545A, NXP, Rev. 10](https://www.nxp.com/docs/en/data-sheet/PCA9545A_45B_45C.pdf): управляющий байт, каналы, прерывания.
- [PCF8563, NXP, Rev. 11.1](https://www.nxp.com/docs/en/data-sheet/PCF8563.pdf): календарь BCD, будильник, таймер, контроль напряжения.
- [P24C02A, Puya, V2.1](https://www.puyasemi.com/download_path/%E6%95%B0%E6%8D%AE%E6%89%8B%E5%86%8C/EEPROM/P24C02A_Datasheet_V2.1.pdf): адресация, страница, цикл записи, WP.
- [PCA9555, NXP, Rev. 10](https://www.nxp.com/docs/en/data-sheet/PCA9555.pdf): входы, выходные защёлки, инверсия, направление.

Для совместимых замен сверяют маркировку и документацию установленного
компонента. Совместимость адресов ещё не подтверждает совпадение всех
побочных эффектов.
