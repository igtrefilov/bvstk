# API пиктограммы v1

Пиктограмма помогает узнать назначение устройства в заголовке его карточки.
Её создаёт JavaScript из бандла. Например, бандл памяти содержит:

```text
p24c02a/
├── p24c02a.json
├── register_map.json
├── view.js
└── icon.js
```

В корне профиля указывается `"icon": "icon.js"`. Путь отсчитывается от
каталога профиля, включая вложенные каталоги за свитчом. Поле необязательное;
пиктограмма работает самостоятельно, в том числе без `register_map` и `view`.
Имя файла содержит латинские буквы, цифры, `_`, `-` и расширение `.js`,
всего до 63 символов. Размер скрипта — до 16384 байт UTF-8.

## Контракт скрипта

Скрипт объявляет объект `window.bvstkIcon`:

| Элемент | Назначение |
|---|---|
| `apiVersion: 1` | Версия API |
| `mount(root)` | Создать рисунок в переданном DOM-элементе; один вызов при загрузке |
| `update(snapshot)` | Обновить рисунок по очередному снимку состояния |

Оба метода обязательны. У статичной картинки `update` может только применять
цвет оформления. SVG создаётся внутри скрипта. Для него уже заданы
`width: 100%`, `height: 100%`, `fill: none`, `stroke: currentColor` и
округлённые концы линий. Область отображения — 48 × 48 пикселей.
Для рисунка удобно использовать `viewBox="0 0 64 64"`.

Полный минимальный пример `icon.js`:

```js
(() => {
  let root;
  window.bvstkIcon = {
    apiVersion: 1,
    mount(target) {
      root = target;
      root.innerHTML = `<svg viewBox="0 0 64 64" role="img">
        <title>Память</title>
        <rect x="16" y="12" width="32" height="40" rx="3"/>
        <path d="M8 22h8M8 32h8M8 42h8m32-20h8m-8 10h8m-8 10h8
                 M24 24h16M24 32h16M24 40h8"/>
      </svg>`;
    },
    update(snapshot) {
      root.style.color = snapshot.appearance.color;
    }
  };
})();
```

## Получаемые данные

| Поле `snapshot` | Значение |
|---|---|
| `api_version` | Число `1` |
| `device.id`, `device.bus` | Имя устройства и шина |
| `device.presence` | `responding`, `unavailable` или `unknown` |
| `device.model`, `vendor`, `class`, `label` | Метаданные, если HTTP API передал их в `config.device` |
| `device.address_spaces` | Пространства с полями `id`, `address`, `first`, `register_count`; пустой массив для одного адреса |
| `cache` | Последний полученный массив записей `reg`, `val`, `valid`, `source`, `updated_ms` |
| `uptime_ms` | Время работы PS из ответа API либо `null` |
| `stale` | `true`, если последнее обновление данных завершилось ошибкой связи |
| `appearance.size` | Размер области в пикселях; сейчас `48` |
| `appearance.color` | Цвет контура; сейчас `#7d8d98` |

Снимки приходят из существующих запросов карточки и кэша. Пиктограмма
не создаёт дополнительный опрос регистров. Частота обновления зависит
от открытой вкладки и доступности HTTP-сервера. Поля `map`, `fields`
и `summary` в этом API отсутствуют.

При отображении состояния по регистру проверяют `valid`, происхождение
`source`, готовность устройства, `stale` и время `updated_ms`.
Начальное значение из `settings` не подтверждает состояние оборудования.
Для отсутствующих или устаревших данных следует показывать неизвестное
состояние. Пиктограммы из штатного набора обозначают тип устройства;
готовность показывает отдельный индикатор карточки.

## Загрузка и изоляция

Скрипт исполняется в отдельном iframe с `sandbox="allow-scripts"`.
CSP блокирует сетевые запросы и внешние ресурсы. Доступа к DOM основной
страницы, API операций шины и загрузкам файлов у скрипта нет.
Внешние библиотеки и `import` не поддерживаются.

Пиктограмма сохраняется при переключении вкладок и обновлении карточки.
При переходе к другому устройству или смене имени файла её среда удаляется.
Чтобы перечитать изменённый `icon.js` с тем же именем, откройте карточку
заново или перезагрузите страницу.

Если файл отсутствует, слишком велик, не запускается за пять секунд
после загрузки или сообщает ошибку, заголовок показывает стандартный чип.
Основные разделы карточки продолжают работать. Причина доступна
в атрибуте `title` контейнера `[data-device-icon]`.

## Установка

Обновлённая PS должна поддерживать поле `icon`. Затем в каталог устройства
во Flash помещают скрипт и добавляют ссылку в сохранённый профиль, сохраняя
его остальные настройки. Профили перечитываются при запуске PS; `save`
сохраняет ссылку на пиктограмму вместе с рабочей конфигурацией.

Пиктограммы и формы хранятся во Flash отдельно от ELF. После первоначального
обновления PS менять рисунок можно заменой соответствующего `icon.js`.
