# Формат профиля устройства v2

JSON, `schema_version: 2`. Ограничения текущих обработчиков PS.

[Объяснение структуры](../device-profile.md). [Полные примеры](../examples/full-profiles.md).

## Общие требования

В таблицах «по умолчанию» означает значение при отсутствии поля.

### Типы значений

| Тип | Формат и ограничение |
|---|---|
| `ID` | Строка, 1–31 символ; `^[a-z][a-z0-9_-]{0,30}$` |
| `Text(N)` | Непустая строка UTF-8, до N байт после декодирования JSON; без управляющих символов |
| `UInt(a..b)` | Целое JSON-число от a до b; десятичные цифры без знака, дроби и экспоненты |
| `Bool` | `true` или `false` |
| `Hex` | Строка `0x` и 1–16 шестнадцатеричных цифр; максимум `0xFFFFFFFFFFFFFFFF` |
| `Duration` | Миллисекунды, целое 0–600000; смысл нуля задан полем |

| Назначение | Тип или правило |
|---|---|
| Адреса, значения, маски | `Hex` |
| Счётчики, интервалы | JSON-числа |
| Переключатели | `Bool` |
| Запись Hex | Ведущие нули и оба регистра букв допустимы |
| Сохранение Hex | Число цифр определяется разрядностью значения |

### Общие ограничения

| Что проверяется | Предел |
|---|---|
| Размер документа | 65536 байт UTF-8, без BOM |
| Вложенность JSON | До 16 уровней контейнеров; корневой объект — первый |
| Число ресурсов | I²C: 1..256; MDIO: 1..32 |
| Правил в каждом списке записи | I²C: 0..256; MDIO: 0..64 |
| Элементов `cache_seed` | I²C: 0..256; MDIO: 0..32 |
| Таблица ID ресурсов | До 2048 байт, включая завершающий ноль каждой строки и один служебный байт |

Ключи уникальны. Комментарии, завершающие запятые, `null`, неизвестные поля
и неверная кодировка отклоняются. Имена полей и перечисления регистрозависимы.

## Подключение к шине

Объяснение: [подключение к шине](../device-profile.md#подключение-к-шине).

| Поле `transport` | Назначение и тип | I²C | MDIO |
|---|---|---|---|
| `bus` | Обязательное имя шины | `"i2c"` | `"mdio"` |
| `controller` | Обязательный ID контроллера | `"pl_i2c_0"` | `"pl_mdio_0"` |
| `address` | `Hex`, адрес устройства | `"0x00".. "0x7F"`; обязателен при отсутствии `address_spaces` | Обязателен: `"0x00".. "0x1F"` |
| `address_spaces` | Несколько адресных пространств одного устройства | Массив из 1..8 объектов по таблице ниже; несовместим с `address` | Поле запрещено |
| `address_bits` | Разрядность адреса | Только `7`; по умолчанию `7` | Поле запрещено |
| `parent` | ID профиля непосредственного свитча | Необязательное поле; указывается вместе с `channel` | Поле запрещено |
| `channel` | Номер канала родительского свитча, начиная с нуля | `UInt(0..15)`, меньше числа каналов родителя | Поле запрещено |

| Условие           | Требование                             |
| ----------------- | -------------------------------------- |
| Адрес I²C         | Без бита направления                   |
| Частота линии     | Задаётся контроллером                  |
| Физическая цель   | Один профиль на уникальное подключение |
| Уникальность I²C  | Адрес в одном доступном сегменте; одинаковые адреса допустимы на разных каналах общего свитча |
| Уникальность MDIO | Контроллер, адрес PHY                  |

Без `parent` устройство подключено непосредственно к контроллеру.
Поддерживаются цепочки до четырёх свитчей. Каждый родитель должен быть
загруженным профилем с `protocol.switch`. Циклы, неизвестные родители,
несуществующие каналы и конфликты адресов блокируют запуск I²C-сервиса.
ID устройств уникальны во всей подсистеме.

Каталог дочернего пакета находится непосредственно в пакете родителя:
`config/i2c/<switch>/<device>/<device>.json`. Загрузчик проверяет
соответствие непосредственного родителя каталога полю `parent`.
При сохранении эта вложенность сохраняется.

### Несколько адресных пространств

`transport.address_spaces` объединяет несколько I²C-адресов одного устройства
в один профиль, пакет и карточку. Все пространства используют общий маршрут
`controller`, `parent`, `channel` и общие параметры `protocol.transfer`.
Для каждого ресурса требуется поле `space`.

| Поле `address_spaces[]` | Тип | Назначение |
|---|---|---|
| `id` | `ID` | Уникальное имя пространства внутри профиля |
| `address` | `Hex`, `0x00..0x7F` | Уникальный I²C-адрес внутри профиля |
| `register_count` | `UInt(1..256)` | Число ресурсов пространства; их адреса идут от нуля без пропусков |

Сумма `register_count` всех пространств равна длине `resources` и составляет
не более 256. ID ресурсов уникальны во всём профиле. Один локальный номер
регистра может встречаться в разных пространствах.

Порядок пространств задаёт внутреннюю нумерацию кэша:
сначала все ресурсы первого пространства, затем второго и так далее.
Индекс ресурса равен сумме размеров предыдущих пространств плюс его
локальный `address`. Политики и `cache_seed` ссылаются на `resources[].id`.
Метка времени и достоверность хранятся отдельно для каждого ресурса.

Первое пространство определяет общую готовность устройства. Ошибка чтения
дополнительного пространства не меняет готовность успешно прочитанного
основного пространства. Указатель регистра внешнего I²C-хоста хранится
отдельно для каждого адреса.

Требуется явный `protocol.transfer` с `address_bytes: 1` или `2`.
Сочетание с `protocol.switch` пока не поддерживается. Устройство
с несколькими пространствами может находиться за свитчом.
Ненулевой `sequence.span` должен делить размер каждого пространства.

Это дополнительная возможность формата v2. Старые профили с `address`
работают без изменений; прежняя прошивка с неизвестным полем
`address_spaces` отклонит новый профиль. Изменение списка пространств
требует перезапуска.

[Полный пример и команды](../address-spaces.md).

### Обмен I²C

`protocol.transfer` задаёт операции общего обработчика. Модель и подпись
устройства используются для отображения. Формат обмена определяется
только полями профиля.

| Поле `transfer` | Значения | По умолчанию |
|---|---|---|
| `address_bytes` | Число байтов адресного префикса: `0`, `1`, `2` | `1` |
| `address_order` | `"big"`: старший байт первым; `"little"`: младший первым | `"big"` |
| `address_base` | `Hex`, базовый адрес окна регистров, `0x0000..0xFFFF` | `"0x0000"` |
| `read_restart` | `true`: префикс и чтение через repeated START; `false`: отдельные операции с STOP между ними | `true` |
| `read_sequence` | Переход указателя при чтении внешним хостом | `{"mode":"wrap","span":0}` |
| `write_sequence` | Переход указателя в много­байтовой записи внешнего хоста | `{"mode":"linear"}` |
| `write_cycle_ms` | Пауза после подтверждённой записи, `UInt(0..1000)` | `0` |
| `verify_write` | `"none"` или `"readback"`: прочитать записанный байт и сравнить | `"none"` |
| `cache_after_write` | `"value"`: сохранить записанное значение; `"invalidate"`: ожидать следующего чтения | `"value"` |
| `host_read` | `"cache"`: использовать достоверный кэш, при промахе читать устройство; `"fresh"`: физическое чтение | `"cache"` |
| `host_current_read` | `Bool`: разрешить чтение с текущего указателя без нового адресного префикса | `false` |

Адресный префикс на проводе равен `address_base + resources[].address`.
При нескольких пространствах `resources[].address` — локальный адрес
в выбранном пространстве. Общий предел профиля — 256 байт.
Двухбайтовый префикс позволяет разместить это окно в адресном пространстве
до `0xFFFF`. Всё окно должно помещаться в выбранную разрядность.
При `address_bytes: 0` требуется один ресурс `0x00` и нулевая база.
У такого устройства чтение сразу возвращает управляющий байт.

| `read_sequence` и `write_sequence` | Поведение |
|---|---|
| `{"mode":"linear"}` | Адрес увеличивается; выход за диапазон завершает операцию ошибкой |
| `{"mode":"fixed"}` | Каждый следующий байт относится к тому же регистру |
| `{"mode":"wrap","span":0}` | Циклический переход по диапазону ресурсов текущего пространства |
| `{"mode":"wrap","span":N}` | Циклический переход внутри группы из N регистров |

Для `wrap` поле `span` необязательно, по умолчанию `0`. Ненулевой `span`
должен делить число ресурсов и `address_base` без остатка.
Пример: `span: 8`, начало записи `0x07` → `0x07`, `0x00`, `0x01`.
`span: 2`, начало `0x03` → `0x03`, `0x02`, `0x03`.

Для профилей с `transfer` начальные значения `cache_seed` не используются
как ответ внешнему хосту до реального взаимодействия с устройством.
При `readback` несовпадение означает ошибку, запись повторно не отправляется.
Чтение для проверки должно быть допустимо документацией устройства:
для регистров с самосбросом или побочным эффектом оно может быть непригодно.

Отсутствие `transfer` сохраняет прежнее поведение старых профилей:
однобайтовый адрес регистра, линейная запись и прежняя обработка кэша.
Новая модель активируется явным добавлением этого объекта.

### Свитч I²C

| Поле `protocol.switch` | Назначение |
|---|---|
| `resource` | ID доступного для записи управляющего регистра |
| `select_mask` | Ненулевая байтовая `Hex`-маска битов выбора каналов |
| `preserve_mask` | Байтовая `Hex`-маска сохраняемых управляющих битов; по умолчанию `"0x00"` |
| `channels` | Массив из 1..16 описаний каналов; индекс элемента равен `transport.channel` потомка |
| `channels[].select` | Байтовый `Hex`-код включения одного канала |
| `channels[].match_mask` | Ненулевая байтовая `Hex`-маска для проверки активности канала |

Канал активен, когда `(control & match_mask) == (select & match_mask)`.
Это поддерживает независимые биты каналов и кодированный выбор канала.
`select` и `match_mask` должны находиться внутри `select_mask`.
Маски `select_mask` и `preserve_mask` не пересекаются.
Код каждого канала должен выбирать только этот канал.

Обращение PS к потомку удерживает блокировку шины на время всей цепочки:
чтение текущего управления → выбор канала → обмен → восстановление управления.
Новый код вычисляется как `(old & preserve_mask) | select`.
При восстановлении записываются биты `old & (select_mask | preserve_mask)`.
Выбор канала проверяется политикой свитча. Восстановление прежнего состояния
является обязательной очисткой операции и выполняется независимо от текущей
политики. При ошибке восстановления состояние маршрута становится неизвестным.

Смена топологии, адреса или параметров обмена требует перезапуска.
Политики можно менять и сохранять обычными командами.

Полные JSON-примеры, структура пакетов и ограничения PL:
[I²C со свитчами](../i2c-topology.md).

| Адреса | Непрерывный диапазон от нуля в каждом пространстве; порядок массива произвольный |
| Уникальность | Пара `space`, `address`; ID уникален во всём профиле |
| Ссылки из политик, настроек, опроса | На существующий `id` ресурса |
| `access: "rw"` | Возможности моста; физические ограничения регистров не отменяются |
| `access: "ro"` | I²C-сервис отклоняет запись независимо от политики |
| `defaults.register` | Общие свойства только перечисленных ресурсов |
| Явное свойство ресурса | Заменяет общее; объекты и массивы заменяются целиком |

### Зарезервированные свойства

Объяснение: [зарезервированные свойства](../device-profile.md#зарезервированные-свойства).

| Поле | Допустимое значение при явном указании | При отсутствии |
|---|---|---|
| `read_effect` | Объект с нулевыми масками `clear_mask`, `latch_high_mask`, `latch_low_mask` | Все маски нулевые |
| `write_effect` | Объект с нулевыми `one_clear_mask`, `one_set_mask`, `self_clear_mask`, `fixed_mask`, `fixed_value` | Все значения нулевые |
| `refresh` | `{"on": [], "period_ms": 0}`; поля можно опускать | Фоновое обновление этого механизма выключено |
| `persist_mask` | Нулевая строка `Hex` | Ноль |
| `fields` | `[]` | Пустой список |

Автоопрос MDIO задаётся через `protocol.options.autopoll_*`.

## Политики доступа

Объяснение: [политики доступа](../device-profile.md#политики-доступа).

`policy.read` и `policy.write` действуют для операций через сервис PS.

### Чтение

| Поле `policy.read` | Допустимое значение |
|---|---|
| `mode` | `"blacklist"` |
| `rules` | `[]` |

Ограничивающая политика чтения отклоняется.

### Запись

| Поле `policy.write` | Назначение и тип | Обязательно | По умолчанию |
|---|---|---|---|
| `mode` | `"whitelist"` или `"blacklist"` | Да, если задан `write` | — |
| `rules` | Массив активных правил | Нет | `[]` |
| `inactive_rules` | Массив правил противоположного режима | Нет | `[]` |

Если весь раздел `write` отсутствует, записи запрещены.

| Режим | Правило совпало | Совпадений нет | Пустой список |
|---|---|---|---|
| `whitelist` | Разрешить | Запретить | Запретить все записи |
| `blacklist` | Запретить | Разрешить | Разрешить все допустимые записи |

| Условие | Правило |
|---|---|
| Разрешённая запись | Дополнительно проверяются адрес, диапазон значения, готовность и ограничения обработчика |
| `rules`, `inactive_rules` | Одинаковая проверка; оба списка сохраняются |
| Переключение режима через командный интерфейс | Списки меняются ролями |
| Правка только `mode` в JSON | Списки не переносятся; смысл текущих правил изменяется |

### Правило и маска

| Поле `policy.write.rules[]` | Назначение | Обязательно |
|---|---|---|
| `resource` | ID существующего регистра | Да |
| `match` | Условие сравнения записываемого значения | I²C: да; MDIO: можно опустить |
| `match.value` | Образец, `Hex` | Вместе с `mask` |
| `match.mask` | Биты, участвующие в сравнении, `Hex` | Вместе с `value` |

| Условие | Требование |
|---|---|
| Совпадение | `(записываемое_значение & mask) == (match.value & mask)` |
| Маска I²C | Только `0xFF` |
| MDIO без `match` или с `match: {}` | Любое допустимое значение регистра |
| Явное `value` или `mask` | Обязательна вся пара; оба значения в разрядности регистра |

`inactive_rules[]` использует тот же формат правила.

Поля, связанные со значением записи:

| Поле | Задача |
|---|---|
| `resources[].write_mask` | Определяет биты передаваемого слова; у текущих мостов охватывает всё слово |
| `policy.write.rules[].match.mask` | Выбирает биты для сравнения в правиле политики |
| `protocol.options.max_write_value` | Ограничивает числовое значение записи I²C |
| `resources[].persist_mask` | Зарезервировано; сейчас допускается только ноль |

## Кэш и настройки

Объяснение: [кэш и настройки](../device-profile.md#кэш-и-настройки).

### Режим driver

Кэшем и проверкой записи управляет обработчик шины.

| Шина | Поведение |
|---|---|
| I²C | Сохраняет прочитанные значения; действие после записи задаёт `protocol.transfer.cache_after_write` |
| MDIO | После записи читает результат и публикует прочитанное значение в BRAM; обработку сброса PHY выполняет служба MDIO |

Срок годности кэша и алгоритм проверки записи в профиле не настраиваются.

### Сохранённые настройки

| Поле `settings` | Назначение и тип | Обязательно | Текущая прошивка |
|---|---|---|---|
| `cache_seed` | Массив начальных значений кэша | Нет | По умолчанию `[]` |
| `desired` | Поле для физических настроек, зарезервировано | Нет | Только `[]` |
| `apply_on_startup` | Применять физические настройки при старте | Нет | Только `false`, также по умолчанию |

Элемент `cache_seed` содержит два обязательных поля:

| Поле | Назначение |
|---|---|
| `resource` | ID существующего регистра |
| `value` | Начальное значение, `Hex`: I²C `0x00..0xFF`, MDIO `0x0000..0xFFFF` |

Ресурс встречается в `cache_seed` не более одного раза. Источник значения в кэше — `settings`.

## Отказ загрузки

Проверяются поля, ссылки, маски и аппаратные ограничения. Отдельная JSON Schema отсутствует.

| Причина отказа | Что проверить |
|---|---|
| Неизвестный обработчик | Для текущей PS выбрать `bvstk_i2c_bridge` или `bvstk_mdio_bridge` |
| Пропуск адреса ресурса | Перечислить весь диапазон от нуля |
| Недопустимая маска I²C | Использовать `match.mask: "0xFF"` |
| Запись I²C вне диапазона | Сопоставить `match.value` с `max_write_value` |
| Ссылка на неизвестный ресурс | Проверить совпадение `resource` и `resources[].id` |
| Неподдерживаемый режим | Проверить `cache`, `verify`, `refresh`, `desired`, `observability` |

Неверный профиль отклоняется целиком.
