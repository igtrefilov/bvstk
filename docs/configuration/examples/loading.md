# Загрузка профилей на плате

Возьмём пакет `device_a` из [прямого подключения](direct-device.md).
Его профиль хранится в каталоге I²C. Относительное размещение одинаково
для обеих целей сборки, а начало пути зависит от файловой системы:

| Среда | Путь |
|---|---|
| FreeRTOS | `flash:/config/i2c/device_a/device_a.json` |
| Нейтрино | `/flash/config/i2c/device_a/device_a.json` |

Карта и форма, если добавлены, находятся рядом. Их имена в профиле
не содержат начало пути. Сам профиль попадает во встроенный набор
при сборке, если он включён в исходную конфигурацию; дополнительные
файлы устанавливаются на носитель отдельно.

## Первый запуск FreeRTOS

Пусть каталоги конфигурации I²C ещё пусты. При первой подготовке
программа устанавливает встроенные профили и создаёт `.initialized`.
Если пользовательский набор уже существует, он принимается целиком:
отсутствующие в нём устройства из встроенного набора не добавляются.

После появления маркера удаление `device_a` считается намеренным.
Следующий запуск не восстановит его автоматически. Установка новой
программы со встроенным `device_a` также не заменяет сохранённый
пользовательский профиль. Пакет устанавливают явно.

Для MDIO во FreeRTOS порядок отличается: при первой подготовке
встроенные профили могут дополнить существующие. При недоступной QSPI
загрузка MDIO отключается. I²C сохраняет резервную возможность
использовать встроенные профили в памяти.

## Запуск Нейтрино

Загрузчик I²C сначала ищет профили в основном каталоге, затем —
при отсутствии основного набора — в старом. Если не найдено ни одного,
используется встроенный набор и выполняется попытка сохранить его
в основном каталоге.

Общий кодек MDIO существует, но загрузчик профилей и служба MDIO
в текущую рабочую среду Нейтрино не подключены.
Профиль с `bus: "mdio"` сам по себе службу не создаёт.

## Поиск старых файлов

Внутри пакета `device_a.json` имеет приоритет перед прежним именем
`profile.json`. Пакет имеет приоритет перед старым плоским файлом.
Основной каталог — `config/<подсистема>`, старый — `configs/<подсистема>`.

Во FreeRTOS после основного каталога просматривается старый без
повторного включения найденных профилей. В Нейтрино старый каталог I²C
используется только при отсутствии профилей в основном.
Ошибка найденного JSON останавливает загрузку соответствующего набора:
программа не заменяет его молча копией из места с меньшим приоритетом.

В подсистему помещается до 32 устройств I²C или до 8 устройств MDIO.
Обход ограничен 128 каталогами; относительный путь, хранимый в модели,
может занимать до 223 символов. Эти ограничения учитывают и при
[вложенных пакетах](routed-devices.md).

## Замена файла

Во FreeRTOS сохранение использует временный файл и резервную копию
`.bak`. При следующей загрузке предусмотрено восстановление
прерванной замены. В Нейтрино новый файл записывается во временное
место, синхронизируется и переименовывается.

Если сохранение вернуло ошибку, рабочая политика в памяти может
оставаться уже изменённой. Последствие перезапуска рассмотрено
в [примере редактирования](editing.md).
