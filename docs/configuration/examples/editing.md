# Изменение правила и сохранение

Устройство уже загружено. В файле и в рабочей политике действует
белый список без правил: любая запись запрещена. Нужно разрешить
значение `0x10` для ресурса `reg_03` и сохранить это разрешение
после перезапуска.

## Применение

В настройках устройства добавляют правило:

```json
{
  "resource": "reg_03",
  "match": {
    "value": "0x10",
    "mask": "0xFF"
  }
}
```

После применения оно входит в действующий белый список.
Следующая запись `0x10` в регистр `0x03` проходит проверку,
если сам ресурс допускает запись. Остальные значения по-прежнему
запрещены. Применение правила не записывает `0x10` в устройство
и не меняет начальные значения кэша.

В этот момент файл ещё содержит пустой список. Если сейчас
перезапустить BVSTK, разрешение исчезнет. Разница между рабочим
состоянием и файлом показана в
[схеме применения и сохранения](../lifecycle.md#Рабочие%20и%20сохранённые%20настройки).

## Сохранение

Операция сохранения записывает текущий профиль на носитель.
В его разделе `policy.write` теперь находится:

```json
{
  "mode": "whitelist",
  "rules": [
    {
      "resource": "reg_03",
      "match": {
        "value": "0x10",
        "mask": "0xFF"
      }
    }
  ],
  "inactive_rules": []
}
```

После успешного сохранения и повторного запуска загрузчик
восстановит это правило. Если запись файла завершилась ошибкой,
правило остаётся рабочим до перезапуска, но считать его сохранённым
нельзя.

При работе по DCP2 изменение правила и `POLICY_SAVE` — отдельные
операции. Последняя сохраняет профиль и оба списка политики.
Порядок запросов описан в
[главе политик](../../interfaces/dcp2/04-policies.md).

## Начальные значения при сохранении

Пусть в сохранённом `cache_seed` у `reg_03` находится `0x00`,
а после успешного обмена в текущем кэше — `0x10`.
`POLICY_SAVE` в DCP2 сохранит новые правила, но оставит начальное
значение `0x00`. Консольное сохранение I²C предварительно переносит
достоверные записи кэша в начальные настройки: там окажется `0x10`.

Параметр I²C `capture_cache_on_save` принимает только `true`,
в том числе по умолчанию. Он не означает, что любой способ сохранения
обязан захватить кэш. HTTP сохраняет подготовленную модель без
дополнительного захвата. Сохранение MDIO сохраняет настроенный
список начальных значений. Нового чтения устройства ради записи
профиля ни одна из этих операций не выполняет.
