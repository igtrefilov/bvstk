# Примеры профилей

Здесь используются условные устройства. Их адреса, регистры и значения
выбраны для объяснения формата и не описывают готовую аппаратную сборку.
В файлах нет пропущенных ресурсов или многоточий вместо обязательных полей.

Начните с [прямого подключения](direct-device.md): это полный профиль
условного устройства `device_a` с 16 регистрами.
Затем можно рассмотреть независимые варианты:

- [Два устройства за коммутатором](routed-devices.md) — три профиля,
  вложенные каталоги и выбор канала при чтении.
- [Два адресных пространства](address-spaces.md) — один профиль,
  два адреса и нумерация общего кэша.
- [Карта и форма](device-display.md) — полный набор описаний
  для расшифровки 16 регистров прямого устройства.
- [Применение и сохранение](editing.md) — изменение одного правила
  и результат повторного запуска.
- [Загрузка на плате](loading.md) — пути файлов, первый запуск
  и различия загрузчиков.
- [Профиль MDIO](mdio-device.md) — 32 регистра, опрос и маски правил.

Прямое подключение, коммутируемое подключение и адресные пространства —
разные варианты устройства `device_a`. Их не следует загружать одновременно
под одним ID. Карта из примера отображения рассчитана на прямой вариант.

[Общее объяснение системы профилей](../configuration.md).

Основной порядок чтения начинается со [структуры профиля](../device-profile.md).
