# HTTP API

Справочник относится к серверу FreeRTOS в
[http_fs_routes.c](../../src/apps/freertos/services/http/http_fs_routes.c)
и [http_server.c](../../src/apps/freertos/services/http/http_server.c).
В штатном Нейтрино эти маршруты не предоставляются. Порт по умолчанию — 80.

## Общие правила

Поддерживаются GET и PUT. Каждый запрос обслуживается с закрытием
соединения; ответы формируются как HTTP/1.0 с `Connection: close`.
Не рассчитывайте на постоянное HTTP-соединение, конвейер запросов,
Range, TLS или аутентификацию. Для PUT требуется `Content-Length`
либо `Transfer-Encoding: chunked`; без обоих возвращается 411.

JSON-ответы имеют `Content-Type: application/json; charset=utf-8`,
ошибки обычно передаются текстом. Клиент должен проверять HTTP-код,
полноту тела, корректность JSON и содержимое результата. HTTP 200
не всегда означает успешное сохранение или пригодный JSON.

Тела API должны быть обычными JSON-объектами с уникальными ключами,
десятичными целыми числами, строками и `true`/`false` согласно таблицам.
Разбор реализован поиском полей, а не полной проверкой JSON-схемы.
Не полагайтесь на приём некорректных документов, неизвестных полей или
на одинаковую обработку неверного типа и отсутствующего поля.

| PUT-маршрут | Максимум тела, помещающийся в буфер обработчика |
|---|---:|
| `/api/net` | 1023 байта |
| `/api/i2c` | 2047 байт |
| `/api/diag/i2c/read`, `/api/diag/i2c/write` | 511 байт |
| SMI, MEM, reboot | 255 байт |

Более длинное тело может быть разобрано частично: общего гарантированного
ответа 413 нет. Не превышайте эти пределы. Они не относятся к потоковым
файловым PUT.

## Маршруты

| Метод | Путь | Результат |
|---|---|---|
| GET | `/api/version` | Дата/время сборки и порт |
| GET | `/api/rtos` | Счётчик времени и память |
| GET, PUT | `/api/net` | Состояние или изменение сети |
| GET | `/api/fs` | Состояние томов |
| GET | `/api/qspi` | Окно файловой системы QSPI |
| GET, PUT | `/api/i2c` | Список или изменение конфигурации I²C |
| GET | `/api/i2c?name=<имя>` | Описание устройства; известное ограничение JSON ниже |
| PUT | `/api/diag/i2c/read`, `/api/diag/i2c/write` | Регистровые операции I²C |
| PUT | `/api/diag/smi/read`, `/api/diag/smi/write` | Сохранённые операции SMI; сейчас недоступны |
| PUT | `/api/diag/mem/read`, `/api/diag/mem/write` | Диагностический MMIO |
| PUT | `/api/reboot` | Запрос перезапуска |
| GET, PUT | `/sd/<путь>`, `/flash/<путь>` | Бинарный файл |
| GET, PUT | `/tar/sd/<каталог>`, `/tar/flash/<каталог>` | Создание или извлечение TAR |
| GET | `/<путь>` | Статический файл из `flash:/www/` |

Для известных API применение другого поддерживаемого метода к
несуществующей паре «метод, путь» даёт 404, а не обязательно 405.
405 используется для метода, отличного от GET/PUT, в обработанных API
и файловых маршрутах. Список выше не подразумевает поддержку HEAD/POST/DELETE.

## Сведения о системе

Все перечисленные поля ответа обязательны в соответствующем обработчике.

| Маршрут | Поле | Тип и смысл |
|---|---|---|
| `/api/version` | `build_date`, `build_time` | Строки макросов даты и времени компиляции; не идентификатор Git |
| | `http_port` | Целое, порт сервера |
| `/api/rtos` | `uptime_ms` | Целое, миллисекунды из счётчика тиков FreeRTOS |
| | `tick_rate_hz` | Целое, частота тиков в Гц |
| | `heap_free` | Целое, свободная куча в байтах |
| | `heap_min_ever` | Целое, минимальная наблюдавшаяся свободная куча в байтах |

`uptime_ms` вычисляется из текущего счётчика FreeRTOS. Расширение его до
64 бит при формировании ответа не устраняет переполнение исходного
счётчика на длительно работающем устройстве.

## GET /api/net

| Поле | Тип | Смысл |
|---|---|---|
| `ip`, `netmask`, `gateway` | Строка | Параметры работающего интерфейса; могут быть пустыми до его создания |
| `mac` | Строка | Шесть октетов через двоеточие |
| `mode` | Строка | `static` или `dhcp` по состоянию сборки lwIP |
| `dhcp` | Логическое | Получен ли адрес DHCP, если эта возможность собрана |
| `up` | Логическое | Интерфейс административно поднят |
| `link_up` | Логическое | Состояние линии по данным lwIP |

Все поля присутствуют. Это не чтение `network.json`; текущий запуск
BVSTK использует статические параметры.

## PUT /api/net

| Поле запроса | Тип | Условие |
|---|---|---|
| `ip` | Строка | Обязательно: `a.b.c.d` или `a.b.c.d/prefix` |
| `netmask` | Строка | При IP без префикса задаёт маску; имеет приоритет над отдельным `prefix` |
| `prefix` | Целое | `0..32`, альтернатива `netmask` |
| `gateway` | Строка | Обязательный IPv4 |
| `mac` | Строка | Обязательные шесть октетов через двоеточие |
| `apply` | Логическое | Необязательно; по умолчанию `true` |

Если префикс включён в `ip`, маска берётся из него. Используйте только
одну форму маски. Поля IPv4 проверяются по октетам; пригодность адреса,
шлюза и MAC для конкретной сети должен обеспечить клиент.

Ответ 200: `{"ok":true,"saved":true,"applied":true}`, где все три поля
логические, а значения `saved` и `applied` зависят от результата.
`saved` подтверждает успех вызова сохранения; `applied` — выполнение
ветви обновления существующего `netif`. `apply:false` не меняет
работающий интерфейс.

Порядок: обновление модели → попытка сохранения → применение → ответ.
Ошибка сохранения не отменяет применение. При смене IP ответ может
потеряться. Не повторяйте запрос автоматически; сначала проверьте новый
адрес. [Процедура смены сети](../operations/network.md) описывает проверку.

Ошибки 400: `empty body`, `missing/bad ip`, `bad ip/prefix`,
`missing netmask/prefix`, `bad netmask`, `bad prefix`,
`missing/bad gateway`, `missing/bad mac`. Ошибка сохранения передаётся
как `saved:false`, не обязательно как HTTP-ошибка.

## GET /api/fs и GET /api/qspi

`/api/fs` возвращает объект с массивом `volumes`. Текущий обработчик
всегда формирует записи `flash` и `sd` в этом порядке:

| Поле записи | Тип | Смысл |
|---|---|---|
| `name` | Строка | `flash` или `sd` |
| `ready` | Логическое | Готовность контекста тома |
| `total_bytes` | Целое | Вместимость по статистике FAT, байты |
| `free_bytes` | Целое | Свободное место по статистике FAT, байты |

Размеры остаются нулевыми, если статистика не получена, в том числе при
ошибке блокировки или `f_getfree`. `ready:true` с нулевыми размерами
не доказывает нулевой размер носителя. PL SD в этот ответ не добавляется.

`/api/qspi` возвращает `ready` (логическое), `fs_base_bytes` и
`fs_size_bytes` (целые байты). Последние два значения — границы
программно выделенного окна, а не результат обнаружения геометрии чипа.

## GET /api/i2c

Без `name` ответ содержит `ready` (логическое), `count` (число
устройств) и `devices` (массив). Каждая запись имеет:

| Поле | Тип и смысл |
|---|---|
| `name` | Строка, имя устройства |
| `addr_7b` | Целое, 7-битный адрес |
| `file_name` | Строка, имя конфигурационного файла |
| `policy` | Строка `whitelist` или `blacklist` |
| `settings_len`, `whitelist_len`, `blacklist_len` | Целые, длины соответствующих массивов |

С `name` обработчик предназначен для ответа с полями `ready` и
`device`; вложенный объект содержит `name`, `addr_7b`, `file_name`,
`policy`, `whitelist`, `blacklist` (массивы пар `reg`/`val`).
`settings`, `reg_count` и `max_value_code` он не возвращает.

Ограничение реализации: для найденного устройства между `policy` и
`whitelist` не выводится запятая. Тело не является корректным JSON,
несмотря на HTTP 200. Для неизвестного имени возвращается 200 с
`{"ready":...,"error":"unknown device"}`, а не 404. До исправления
реализации читайте полный JSON через файловый маршрут или DCP2 FS.
Документация не объявляет ошибочное тело новым форматом интерфейса.

## PUT /api/i2c

| Поле | Тип | Условие |
|---|---|---|
| `name` | Строка | Обязательно, существующее устройство |
| `policy` | Строка | Необязательно; `whitelist` или `blacklist` |
| `whitelist` | Массив `{reg,val}` | Необязательно; заменяет целиком соответствующий список |
| `blacklist` | Массив `{reg,val}` | Необязательно; заменяет целиком соответствующий список |

Отсутствующее поле сохраняет прежнее значение, пустой массив очищает
список. Адрес, имя, число регистров и `settings` этим запросом не
редактируются. Используйте [пределы конфигурации](configuration.md);
дополнительно весь HTTP-документ должен помещаться в 2047 байт.

Ответ 200 содержит `ok:true` и `saved` (логическое). Сначала изменяется
работающий сервис, затем модель и файл. При `saved:false` изменение
не откатывается. 503 — `config_store not ready`; 400 — пустое тело,
отсутствующее имя, неверная политика или массив; 404 — `unknown device`;
500 — `set failed`. Не следует считать 500 гарантией отсутствия всех
частичных изменений предыдущих шагов.

## Диагностические операции I²C

Оба PUT-маршрута выбирают устройство непустым `name` (строка) либо
`addr_7b` (целое `0..127`). Если присутствуют оба, имя имеет приоритет.
`reg` обязателен, целое `0..255`, дополнительно ограничивается моделью
устройства. Для write обязателен `val`, целое `0..255`, дополнительно
проверяются `max_value_code` и политика.

Read возвращает 200 с `ok:true`, `name` (строка), `reg` и `val`
(целые). Write возвращает только `{"ok":true}`. После записи
синхронизируется модель без отдельного сохранения; это не подтверждение
записи JSON в QSPI.

400 — отсутствующее/неверное поле; 404 `device not found` возможен и
при неготовом сервисе; 500 `i2c read failed` — ошибка чтения.
Текущий write отображает любой неуспех сервисной записи в 403 `DENIED`,
в том числе не только отказ политики. По одному этому ответу нельзя
достоверно установить внутреннюю причину. Вызов сервиса использует 100 мс,
но это не гарантия общего времени HTTP-запроса.

## Диагностические операции SMI

Read требует `phy` и `reg`, целые `0..31`. Write дополнительно
требует `val`, целое `0..65535`. При включённой реализации read
возвращает `{"ok":true,"val":число}`, write — `{"ok":true}`.
Ошибки полей — 400, чтения — 500, записи — 403.

В текущем профиле оба маршрута возвращают 503 с текстом
`smi unavailable` до работы с телом. Наличие маршрута не включает SMI.

## Диагностические операции MEM

Read требует `addr`, целое `0..4294967295`. Write дополнительно
требует `val` того же диапазона и `confirm:true`.
По выровненному на 4 адресу выполняется 32-битная операция, иначе —
8-битная. Для невыровненной записи `val` должен быть не больше 255.

Read возвращает `ok:true`, `width` (32 или 8, биты) и `val`
(беззнаковое число). Write возвращает `{"ok":true}`. Ошибки аргументов,
отсутствие подтверждения и слишком большое байтовое значение — 400.
Адрес вне списка включённых окон — 403 `address not available`.
Этот список не совпадает с правилами DCP2 MEM.

Операция не проверяет безопасность значения конкретного регистра и
обходит политику устройства. Допустимый адрес не гарантирует отсутствия
аппаратного исключения при несовместимом bitstream.

## PUT /api/reboot

`confirm:true` обязательно. `delay_ms` — необязательное неотрицательное
целое, умолчание 1000 мс; значение выше 5000 ограничивается до 5000.
Ответ: `{"ok":true,"rebooting":true}`. Без подтверждения или с пустым
телом — 400. После ответа создаётся задача перезапуска; результат её
создания не отражается в уже отправленном ответе. Клиент должен проверить
фактический разрыв и последующее восстановление службы.

## Файлы, TAR и статика

| Путь URL | Данные устройства |
|---|---|
| `/sd/x` | Файл `sd:/x` |
| `/flash/x` | Файл `flash:/x` |
| `/tar/sd/x` | Дерево `sd:/x` |
| `/tar/flash/x` | Дерево `flash:/x` |
| `/` | `flash:/www/index.html` |
| `/css/app.css` | `flash:/www/css/app.css` |

Файловый GET возвращает двоичное тело и длину; каталог таким запросом
не перечисляется. PUT создаёт/усекает целевой файл, промежуточные каталоги
нужно создать заранее. Успех PUT — 200 с текстом `OK`; ошибка чтения
тела — 400, открытия/записи — 500, отсутствующий файл GET — 404.

TAR GET отправляет `application/x-tar` до завершения обхода. Ошибка обхода
после заголовка не меняет уже отправленный 200; целостность архива нужно
проверять отдельно. TAR PUT извлекает архив в заданный каталог:
200 `OK` либо 400 `tar extract failed`. Ни одно направление не
обеспечивает атомарного снимка или отката.

При неготовом томе или отказе блокировки отдельные файловые обработчики
могут закрыть соединение без оформленного HTTP-ответа; общего обязательного
503 для файлов здесь нет. Клиент должен обрабатывать и транспортную ошибку.

Пути декодируются из URL. Текущий фильтр запрещает любую подстроку `..`,
не только отдельный сегмент, и двоеточие; для статики также запрещён
обратный слеш. Не передавайте параметры запроса в файловые URL:
их обработка отличается от API и статики. Для каталога статики с конечным
`/` добавляется `index.html`. Неподдержанный путь может перейти к поиску
статического файла, а не дать специальную ошибку файлового сервиса.

Практические команды и предупреждения о перезаписи находятся в
[работе через HTTP](../operations/http.md). Формат DCP2 FS не дублируется
этими маршрутами и описан в [отдельной спецификации](../dcp2/dcp2.md).
