# Коды результатов

Результаты разных слоёв не имеют взаимозаменяемой числовой шкалы.
`bvstk_status_t`, результат MMIO `0/-1`, код HTTP, текст консоли и
статус DCP2 нужно интерпретировать в контексте вызванного интерфейса.

## Общий C API

Значения определены в
[bvstk_status.h](../../src/shared/base/bvstk_status.h).

| Значение | Имя | Смысл |
|---:|---|---|
| 0 | `BVSTK_OK` | Операция завершена |
| 1 | `BVSTK_ERR_MALFORMED` | Неверная форма входных данных |
| 2 | `BVSTK_ERR_UNSUPPORTED` | Возможность не предоставляется |
| 3 | `BVSTK_ERR_DENIED` | Отказ по политике |
| 4 | `BVSTK_ERR_BUSY` | Ресурс занят |
| 5 | `BVSTK_ERR_TIMEOUT` | Истекло ожидание |
| 6 | `BVSTK_ERR_RANGE` | Нарушен диапазон |
| 7 | `BVSTK_ERR_NOT_READY` | Экземпляр или ресурс не готов |
| 8 | `BVSTK_ERR_NOT_FOUND` | Объект не найден |
| 9 | `BVSTK_ERR_IO` | Ошибка ввода-вывода |
| 10 | `BVSTK_ERR_INTERNAL` | Внутренняя ошибка |

Конкретная функция определяет, какие значения она возвращает и что уже
могло измениться к моменту ошибки. Неуспех не означает автоматический
откат. Интерфейсы `bvstk_platform_init` и MMIO возвращают `0/-1`;
их отрицательное значение нельзя приводить к перечислению как готовый
статус протокола.

## DCP2

Полные коды и формат ответа находятся только в
[спецификации DCP2](../dcp2/dcp2.md). Общий адаптер отображает первые
ошибки C API в протокольные статусы, а `NOT_READY`, `NOT_FOUND`,
`IO` и `INTERNAL` для обычных сервисов сводит к общему внутреннему
отказу. FS имеет собственные различимые ошибки: отсутствующий объект,
неготовый том, неверный дескриптор, неверный тип, ошибка ввода-вывода
и изменение источника.

Нельзя выводить код FS из порядкового номера `bvstk_status_t`.
Нельзя также трактовать все ошибки FS как повторяемые: недействительный
дескриптор требует нового открытия, изменение файла — нового чтения
источника. Повторы выполняются по правилам конкретной операции.

## HTTP

| Код | Значение в BVSTK |
|---:|---|
| 200 | Ответ обработчика; отдельно проверяются тело, `saved` и полнота данных |
| 400 | Ошибка полей, подтверждения или тела |
| 403 | Отказ записи/адреса; I²C write может так отображать разные сервисные ошибки |
| 404 | Маршрут, файл или устройство не найдены; у отдельных обработчиков есть исключения |
| 405 | Метод не поддержан обработанным маршрутом |
| 411 | PUT без указания длины или chunked |
| 500 | Ошибка сервисной или файловой операции |
| 503 | Явно сообщённая неготовность/недоступность службы |

Это указатель, не исчерпывающий контракт каждого маршрута. Например,
неизвестное имя в GET I²C даёт 200 с полем `error`, а неготовый файловый
том может привести к закрытию без HTTP-ответа. Подробности и известная
ошибка JSON описаны в [HTTP API](http-api.md).

## Консоль и повторы

Текстовые маркеры `OK`, `ERR`, `DENIED`, `WARN` описаны в
[справочнике команд](console-commands.md). Предупреждение сохранения
отличается от отказа основной операции.

Перед повтором определите, могла ли изменяющая операция уже выполниться.
Тайм-аут после записи или смены адреса не доказывает её отсутствие.
Ошибочный формат исправляют, недоступную функцию сверяют с профилем,
отказ политики разбирают по правилам устройства. Ограниченные повторы
чтения допустимы там, где это предусмотрено интерфейсом; бесконечный
повтор не заменяет диагностику.
