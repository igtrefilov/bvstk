# Система и сеть


## Сведения о системе

Все перечисленные поля ответа обязательны в соответствующем обработчике.

| Маршрут | Поле | Тип и смысл |
|---|---|---|
| `/api/version` | `build_date`, `build_time` | Строки макросов даты и времени компиляции; не идентификатор Git |
| | `http_port` | Целое, порт сервера |
| `/api/rtos` | `uptime_ms` | Целое, миллисекунды из счётчика тиков FreeRTOS |
| | `tick_rate_hz` | Целое, частота тиков в Гц |
| | `heap_free` | Целое, свободная куча в байтах |
| | `heap_min_ever` | Целое, минимальная наблюдавшаяся свободная куча в байтах |

`uptime_ms` вычисляется из текущего счётчика FreeRTOS. Расширение его до
64 бит при формировании ответа не устраняет переполнение исходного
счётчика на длительно работающем устройстве.

## GET /api/net

| Поле | Тип | Смысл |
|---|---|---|
| `ip`, `netmask`, `gateway` | Строка | Параметры работающего интерфейса; могут быть пустыми до его создания |
| `mac` | Строка | Шесть октетов через двоеточие |
| `mode` | Строка | `static` или `dhcp` по состоянию сборки lwIP |
| `dhcp` | Логическое | Получен ли адрес DHCP, если эта возможность собрана |
| `up` | Логическое | Интерфейс административно поднят |
| `link_up` | Логическое | Состояние линии по данным lwIP |

Все поля присутствуют. Это не чтение `network.json`; текущий запуск
BVSTK использует статические параметры.

## PUT /api/net

| Поле запроса | Тип | Условие |
|---|---|---|
| `ip` | Строка | Обязательно: `a.b.c.d` или `a.b.c.d/prefix` |
| `netmask` | Строка | При IP без префикса задаёт маску; имеет приоритет над отдельным `prefix` |
| `prefix` | Целое | `0..32`, альтернатива `netmask` |
| `gateway` | Строка | Обязательный IPv4 |
| `mac` | Строка | Обязательные шесть октетов через двоеточие |
| `apply` | Логическое | Необязательно; по умолчанию `true` |

Если префикс включён в `ip`, маска берётся из него. Используйте только
одну форму маски. Поля IPv4 проверяются по октетам; пригодность адреса,
шлюза и MAC для конкретной сети должен обеспечить клиент.

Ответ 200: `{"ok":true,"saved":true,"applied":true}`, где все три поля
логические, а значения `saved` и `applied` зависят от результата.
`saved` подтверждает успех вызова сохранения; `applied` — выполнение
ветви обновления существующего `netif`. `apply:false` не меняет
работающий интерфейс.

Порядок: обновление модели → попытка сохранения → применение → ответ.
Ошибка сохранения не отменяет применение. При смене IP ответ может
потеряться. Не повторяйте запрос автоматически; сначала проверьте новый
адрес. [Процедура смены сети](../../operations/network.md) описывает проверку.

Ошибки 400: `empty body`, `missing/bad ip`, `bad ip/prefix`,
`missing netmask/prefix`, `bad netmask`, `bad prefix`,
`missing/bad gateway`, `missing/bad mac`. Ошибка сохранения передаётся
как `saved:false`, не обязательно как HTTP-ошибка.

## Диагностические операции MEM

Read требует `addr`, целое `0..4294967295`. Write дополнительно
требует `val` того же диапазона и `confirm:true`.
По выровненному на 4 адресу выполняется 32-битная операция, иначе —
8-битная. Для невыровненной записи `val` должен быть не больше 255.

Read возвращает `ok:true`, `width` (32 или 8, биты) и `val`
(беззнаковое число). Write возвращает `{"ok":true}`. Ошибки аргументов,
отсутствие подтверждения и слишком большое байтовое значение — 400.
Адрес вне списка включённых окон — 403 `address not available`.
Этот список не совпадает с правилами DCP2 MEM.

Операция не проверяет безопасность значения конкретного регистра и
обходит политику устройства. Допустимый адрес не гарантирует отсутствия
аппаратного исключения при несовместимом bitstream.

## PUT /api/reboot

`confirm:true` обязательно. `delay_ms` — необязательное неотрицательное
целое, умолчание 1000 мс; значение выше 5000 ограничивается до 5000.
Ответ: `{"ok":true,"rebooting":true}`. Без подтверждения или с пустым
телом — 400. После ответа создаётся задача перезапуска; результат её
создания не отражается в уже отправленном ответе. Клиент должен проверить
фактический разрыв и последующее восстановление службы.
