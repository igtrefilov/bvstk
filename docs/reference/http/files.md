# Тома и файлы


## Тома и SD-PL

`GET /api/ui/volumes` возвращает `volumes` в порядке `flash`, `sd`,
`sd-pl`. Каждая запись содержит `name`, `ready`, `fat_bits`,
`total_bytes`, `free_bytes`, `format_allowed:false`.
Неизвестные размеры равны `null`, неизвестный тип FAT — `0`.
Статистика Flash и PS SD кэшируется до 30 секунд. Для SD-PL указывается
размер FAT-тома, не полная ёмкость карты; `free_bytes` всегда `null`.
Чтение не инициирует монтирование или форматирование.

`GET /api/ui/sd-pl` возвращает `ready`, `mounted`, `filesystem_owned`,
`ocr`, `block_addressed`, `last_lba`, `last_error`, `format_allowed:false`.
Если описание тома доступно, присутствуют `fat_bits`, `volume_lba`,
`volume_sectors`. Это состояние существующего драйвера, не команда
повторной инициализации или сырого теста секторов.

## Каталоги и файловые операции

Все файловые запросы требуют `volume=flash|sd|sd-pl` и `path` —
абсолютный путь внутри тома, например `/config/mdio/lan8720.json`.
Предел пути — 120 байт UTF-8, компонента — 63 байта UTF-8. Не допускаются
компоненты `.` и `..`, пустые компоненты, завершающие пробелы или точки,
обратный слеш, двоеточие, управляющие и зарезервированные FAT-символы.
Корень `/` разрешён для чтения каталога, но не для изменяющих операций.
Том должен быть уже смонтирован; автоматического remount нет.

`GET /api/ui/files?volume=sd-pl&path=%2F` возвращает:

```json
{"entries":[{"name":"example.txt","directory":false,"size":123,"date":0,"time":0}],"ok":true,"error":0,"next":null}
```

`offset` по умолчанию 0, максимум 100000; `limit` по умолчанию 64,
диапазон 1–128. `next` — смещение следующей порции либо `null`.
Размер — байты, `date` и `time` — упакованные поля FAT, ноль означает
неизвестное время. Между страницами список не блокируется: при внешних
изменениях каталога нужно начать перечисление заново.
С `action=stat` возвращается одна запись объекта без `entries`.

PUT `/api/ui/files` требует `confirm=true` и `action`:

- `mkdir`: создать один каталог, родитель должен существовать.
- `remove`: удалить файл или пустой каталог, без рекурсии.
- `rename`: `dst_volume`, `dst`; только внутри одного тома, без перезаписи.
- `copy`: `dst_volume`, `dst`; копирование одного файла, в том числе
  между томами, без перезаписи и без создания родителей.

## Содержимое файла

`GET /api/ui/file?volume=sd-pl&path=%2Fexample.txt` передаёт бинарное
содержимое с `Content-Length`. Необязательный `max_bytes` ограничивает
размер до начала передачи; превышение возвращает 413. Браузерный редактор
использует 32768 байт. Ошибка чтения после заголовков обрывает ответ,
поэтому клиент должен проверять длину, а не только HTTP 200.

PUT по тому же пути требует `confirm=true`. По умолчанию создаётся
новый файл, существующий даёт 409. `overwrite=true` разрешает усечение
и замену существующего файла. Тело передаётся потоково, блоками 1024 байта;
предельный размер — `UINT32_MAX`, также действуют ограничения носителя.
Успех после синхронизации и закрытия: `{"ok":true,"bytes":123}`.

Файловые ошибки: 400 — неверное имя или параметры; 403 — запрет записи;
404 — отсутствующий объект; 409 — существующая цель; 423 — занятый том;
503 — том или файловая система не готовы; 500 — другие ошибки FatFs.
Число FatFs включается в описание ошибки. При сетевом обрыве ответ может
отсутствовать; частичный целевой файл сохраняется для проверки. Операции
не транзакционные и не откатывают уже записанные данные. Повторы не
выполняются автоматически. Форматирование этим API не предоставляется.

## GET /api/fs и GET /api/qspi

`/api/fs` возвращает объект с массивом `volumes`. Текущий обработчик
всегда формирует записи `flash` и `sd` в этом порядке:

| Поле записи | Тип | Смысл |
|---|---|---|
| `name` | Строка | `flash` или `sd` |
| `ready` | Логическое | Готовность контекста тома |
| `total_bytes` | Целое | Вместимость по статистике FAT, байты |
| `free_bytes` | Целое | Свободное место по статистике FAT, байты |

Размеры остаются нулевыми, если статистика не получена, в том числе при
ошибке блокировки или `f_getfree`. `ready:true` с нулевыми размерами
не доказывает нулевой размер носителя. PL SD в этот ответ не добавляется.

`/api/qspi` возвращает `ready` (логическое), `fs_base_bytes` и
`fs_size_bytes` (целые байты). Последние два значения — границы
программно выделенного окна, а не результат обнаружения геометрии чипа.

## Файлы, TAR и статика

| Путь URL | Данные устройства |
|---|---|
| `/sd/x` | Файл `sd:/x` |
| `/flash/x` | Файл `flash:/x` |
| `/tar/sd/x` | Дерево `sd:/x` |
| `/tar/flash/x` | Дерево `flash:/x` |
| `/` | `flash:/www/index.html` |
| `/css/app.css` | `flash:/www/css/app.css` |

Файловый GET возвращает двоичное тело и длину; каталог таким запросом
не перечисляется. PUT создаёт/усекает целевой файл, промежуточные каталоги
нужно создать заранее. Успех PUT — 200 с текстом `OK`; ошибка чтения
тела — 400, открытия/записи — 500, отсутствующий файл GET — 404.

TAR GET отправляет `application/x-tar` до завершения обхода. Ошибка обхода
после заголовка не меняет уже отправленный 200; целостность архива нужно
проверять отдельно. TAR PUT извлекает архив в заданный каталог:
200 `OK` либо 400 `tar extract failed`. Ни одно направление не
обеспечивает атомарного снимка или отката.

При неготовом томе или отказе блокировки отдельные файловые обработчики
могут закрыть соединение без оформленного HTTP-ответа; общего обязательного
503 для файлов здесь нет. Клиент должен обрабатывать и транспортную ошибку.

Пути декодируются из URL. Текущий фильтр запрещает любую подстроку `..`,
не только отдельный сегмент, и двоеточие; для статики также запрещён
обратный слеш. Не передавайте параметры запроса в файловые URL:
их обработка отличается от API и статики. Для каталога статики с конечным
`/` добавляется `index.html`. Неподдержанный путь может перейти к поиску
статического файла, а не дать специальную ошибку файлового сервиса.

Практические команды и предупреждения о перезаписи находятся в
[работе через HTTP](../../operations/http.md). Формат DCP2 FS не дублируется
этими маршрутами и описан в [отдельной спецификации](../dcp2/02-frame.md).
