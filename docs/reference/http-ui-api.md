# API веб-интерфейса

Маршруты `/api/ui/` обслуживаются адаптерами
[http_ui_bus.c](../../src/apps/freertos/services/http/http_ui_bus.c) и
[http_ui_files.c](../../src/apps/freertos/services/http/http_ui_files.c).
Они входят в обычную сборку FreeRTOS и используют существующие сервисы
I²C, MDIO, SD-PL и ConfigStore. PL не изменяется. Прежние маршруты
из [справочника HTTP](http-api.md) сохраняются.

## Правила запросов

Поддерживаются GET и PUT. Неподдерживаемый метод получает 405,
неизвестный маршрут — 404. Параметры передаются в query с URL-кодированием;
повторяющийся запрашиваемый ключ, неверная percent-последовательность,
NUL, управляющий символ или переполнение буфера отклоняются. Числа в query
десятичные, неотрицательные, без суффиксов.

JSON передаётся в UTF-8. Успех действия — HTTP 200 и `{"ok":true}`,
если ниже не описаны дополнительные поля. Ошибка — соответствующий
HTTP-код и `{"ok":false,"error":"описание"}`. Списки и снимки читаются
без обязательного поля `ok`. Ошибка перечисления каталога после начала
ответа указывается внутри тела; проверяйте `ok` и полноту JSON.

Сервисные ошибки: 400 — неверные данные или диапазон; 403 — отказ политики;
404 — неизвестное устройство; 423 — занято; 503 — сервис не готов;
504 — тайм-аут сервиса; 500 — прочие ошибки. Все ответы запрещают
кэширование. Аутентификации, TLS и атомарных транзакций между клиентами нет.

## Подсистемы

`GET /api/ui/bus?bus=i2c` или `bus=mdio` возвращает:

```json
{"ready":true,"devices":[{"name":"lan8720","address":1,"available":true,"presence":"responding","policy":"whitelist"}]}
```

Для конкретного устройства добавляется `name`:

```text
GET /api/ui/bus?bus=mdio&name=lan8720
```

| Поле | Смысл |
|---|---|
| `config` | Совместимая проекция настроек RAM в прежнем формате API, не документ профиля v2 |
| `revision` | Восемь hex-символов, FNV-1a 32 бит от канонического JSON |
| `saved` | `true`, если снимок совпадает с сохранённым конфигом; `false`, если нет; `null`, если прочитать состояние не удалось |
| `file_name` | Имя файла в `flash:/config/i2c/` либо `flash:/config/mdio/` |
| `available` | `true` только при `presence=responding`; не просто наличие профиля |
| `presence` | `unknown`, `responding` или `unavailable`; то же поле есть в списке устройств |
| `cache` | Только MDIO: массив `reg`, `val`, `valid`, `source`, `age_ms` |
| `stats` | Только MDIO: общие счётчики `reads`, `writes`, `denied`, `errors`, `observed` |

Источники кэша — `settings` и `PHY`; возраст фиксируется на момент чтения.

Файлы устройств используют v2, но этот API сохраняет поля `name`,
`reg_count`, `policy`, `whitelist`, `blacklist`, `settings` и параметры
соответствующей шины. `apply` принимает эту проекцию и сохраняет метаданные
и ID ресурсов v2, которые редактор не показывает. `save` записывает v2
через ConfigStore; старое несовместимое имя сохраняется в прежнем формате.
`saved` сравнивает нормализованные настройки этой проекции, а не байты
файла и не отображаемые метаданные `device`.

У I²C `unknown` означает отсутствие подтверждённого обмена после старта
или смены адреса. Успешное физическое чтение переводит состояние в
`responding`, ошибка обмена (включая NACK и тайм-аут) — в `unavailable`.
Кэш, начальные `settings`, отказ политики и успешная запись без чтения
не подтверждают присутствие. Это результат последнего обмена, не фоновое
обнаружение отключения устройства. Запрос списка сам не сканирует шину.
У MDIO `responding` требует достоверных ID PHY в регистрах 2 и 3,
прочитанных с оборудования менее трёх секунд назад; иначе `unavailable`.
В старой прошивке I²C поле `available` означало готовность сервиса:
без поля `presence` новый интерфейс считает ответ I²C непроверенным.

`observed` — обработанные входные ячейки, не доказанное число всех кадров
на проводах. Независимые снимки кэша, счётчиков и конфигурации не образуют
одного аппаратно-атомарного снимка.

PUT использует тот же путь и параметры `bus`, `name`, `action`:

| `action` | Дополнительные параметры | Действие |
|---|---|---|
| `apply` | `revision` | Полная конфигурация JSON в теле; применение только в RAM |
| `save` | `revision` | Явное сохранение текущего снимка через ConfigStore |
| `read` | `reg` | Физическое чтение; ответ `ok`, `reg`, `val` |
| `write` | `reg`, `val`, `confirm=true` | Запись с проверкой политики; без сохранения во Flash |
| `invalidate` | Нет | Только MDIO: сброс достоверности кэша |

Для действий без конфигурационного тела отправляйте PUT без тела
(допускается `Content-Length: 0`). Не добавляйте формальное `{}`:
обработчики запросов с параметрами в URL не потребляют это тело, а закрытие
lwIP-сокета с непрочитанными данными может оборвать ответ. Это относится
также к командам `/api/ui/files`; `apply` и загрузка файла требуют тела.
Тело `apply` — не более 32767 байт, без NUL. Переполнение отклоняется
с 413, неполное или некорректное тело — с 400. Для I²C обязательны все
восемь полей штатного формата: `name`, `addr_7b`, `reg_count`,
`max_value_code`, `policy`, `whitelist`, `blacklist`, `settings`.
Неизвестные корневые поля, повторные ключи и некорректная грамматика
отклоняются. MDIO использует свой строгий штатный кодек. Диапазоны и
семантика перечислены в [конфигурации](configuration.md).

Имя и число регистров устройства неизменны. У I²C через этот API также
не меняются `max_value_code` и начальные `settings`. Занятый другим
устройством адрес I²C отклоняется с 409. Изменение политики не выполняет
физические записи настроечных регистров.

Перед `apply` и `save` проверяется `revision`. Перед применением проверка
повторяется после чтения тела. Несовпадение даёт 409 без применения
переданного черновика. Это оптимистическая проверка по 32-битному хешу,
не криптографический идентификатор и не атомарный compare-and-swap с shell
или DCP2. Между последней проверкой и применением возможна параллельная
смена конфигурации. Для согласованного редактирования нужен один писатель.
После действия перечитайте снимок и поле `saved`.

Запись I²C синхронизирует RAM-модель; Flash меняется только по `save`.
Успешная запись MDIO означает передачу кадра, не подтверждение PHY.
Чтение может иметь побочные эффекты у latch и read-clear регистров.

## Журналы наблюдений

`GET /api/ui/observe?bus=mdio&channel=telemetry&address=1`
возвращает до 32 записей ограниченного журнала RAM. Допустимы
`bus=i2c|mdio`, `channel=telemetry|events`. Необязательный `address`
ограничивает записи адресом 0–127 для I²C, 0–31 для MDIO.
Без адреса видны наблюдения всей шины, в том числе неизвестных PHY.
GET не обращается к физическим регистрам, PUT не поддерживается.

Первый запрос без `after` получает начало сохранённой истории. В следующем
запросе передайте `after=<next>` предыдущего ответа. Курсоры `next`, `head`
и номера `records[].id` — десятичные строки без потери точности 64 бит.
`after=0` — конкретная позиция перед первой записью, не запрос истории.
`more` сообщает о следующей порции. Курсор двигается и мимо записей других
адресов. Чтение не удаляет записи и не изменяет курсоры других клиентов.

`lost` — десятичная строка с числом перезаписанных записей между курсором
клиента и старейшей доступной записью. Это потери программного журнала
всей шины и канала до фильтра адреса, не потери аппаратных кадров.
`capacity=256`; `reset=true` означает курсор за концом журнала: история
читается заново. Уменьшение `uptime_ms` также требует начать без `after`.
Курсор и uptime не являются уникальным идентификатором загрузки: после
длительного отключения клиента для новой сессии начинайте без `after`.

Запись содержит `id`, `time_us` (время PS), `type`, `status`, `source`,
`operation`, `address`, `reg`, `value`. Источники: 0 консоль, 1 внешний
мастер, 2 DCP2, 3 внутренний сервис, 4 Web. Операция: 0 чтение, 1 запись.
Статусы сервиса: 0 OK, 1 malformed, 2 unsupported, 3 denied, 4 busy,
5 timeout, 6 range, 7 not-ready, 8 not-found, 9 IO, 10 internal.
Типы событий: 1 попытка, 2 завершение, 3 отказ политики, 4 состояние,
5 ошибка. Типы телеметрии:

| Type | Наблюдение |
|---|---|
| 257 | Внешняя запись, потреблённая PS |
| 258 | Результат физического чтения master |
| 259 | Результат физической записи master |
| 260 | Установка указателя регистра I²C slave |
| 261 | Запрос чтения I²C slave, без значения данных |
| 262 | Подготовленный байт ответа I²C slave, не подтверждённое чтение |

Для ошибочного master-чтения `value=0` — заполнитель без достоверных данных.
Для типа 260 значение — байт указателя, не запись содержимого регистра.
Тип 262 не означает, что внешний мастер фактически прочитал этот байт.
Ограничения покрытия приведены в [руководстве UI](../operations/web-ui.md#телеметрия-и-события).

## Тома и SD-PL

`GET /api/ui/volumes` возвращает `volumes` в порядке `flash`, `sd`,
`sd-pl`. Каждая запись содержит `name`, `ready`, `fat_bits`,
`total_bytes`, `free_bytes`, `format_allowed:false`.
Неизвестные размеры равны `null`, неизвестный тип FAT — `0`.
Статистика Flash и PS SD кэшируется до 30 секунд. Для SD-PL указывается
размер FAT-тома, не полная ёмкость карты; `free_bytes` всегда `null`.
Чтение не инициирует монтирование или форматирование.

`GET /api/ui/sd-pl` возвращает `ready`, `mounted`, `filesystem_owned`,
`ocr`, `block_addressed`, `last_lba`, `last_error`, `format_allowed:false`.
Если описание тома доступно, присутствуют `fat_bits`, `volume_lba`,
`volume_sectors`. Это состояние существующего драйвера, не команда
повторной инициализации или сырого теста секторов.

## Каталоги и файловые операции

Все файловые запросы требуют `volume=flash|sd|sd-pl` и `path` —
абсолютный путь внутри тома, например `/config/mdio/lan8720.json`.
Предел пути — 120 байт UTF-8, компонента — 63 байта UTF-8. Не допускаются
компоненты `.` и `..`, пустые компоненты, завершающие пробелы или точки,
обратный слеш, двоеточие, управляющие и зарезервированные FAT-символы.
Корень `/` разрешён для чтения каталога, но не для изменяющих операций.
Том должен быть уже смонтирован; автоматического remount нет.

`GET /api/ui/files?volume=sd-pl&path=%2F` возвращает:

```json
{"entries":[{"name":"example.txt","directory":false,"size":123,"date":0,"time":0}],"ok":true,"error":0,"next":null}
```

`offset` по умолчанию 0, максимум 100000; `limit` по умолчанию 64,
диапазон 1–128. `next` — смещение следующей порции либо `null`.
Размер — байты, `date` и `time` — упакованные поля FAT, ноль означает
неизвестное время. Между страницами список не блокируется: при внешних
изменениях каталога нужно начать перечисление заново.
С `action=stat` возвращается одна запись объекта без `entries`.

PUT `/api/ui/files` требует `confirm=true` и `action`:

- `mkdir`: создать один каталог, родитель должен существовать.
- `remove`: удалить файл или пустой каталог, без рекурсии.
- `rename`: `dst_volume`, `dst`; только внутри одного тома, без перезаписи.
- `copy`: `dst_volume`, `dst`; копирование одного файла, в том числе
  между томами, без перезаписи и без создания родителей.

## Содержимое файла

`GET /api/ui/file?volume=sd-pl&path=%2Fexample.txt` передаёт бинарное
содержимое с `Content-Length`. Необязательный `max_bytes` ограничивает
размер до начала передачи; превышение возвращает 413. Браузерный редактор
использует 32768 байт. Ошибка чтения после заголовков обрывает ответ,
поэтому клиент должен проверять длину, а не только HTTP 200.

PUT по тому же пути требует `confirm=true`. По умолчанию создаётся
новый файл, существующий даёт 409. `overwrite=true` разрешает усечение
и замену существующего файла. Тело передаётся потоково, блоками 1024 байта;
предельный размер — `UINT32_MAX`, также действуют ограничения носителя.
Успех после синхронизации и закрытия: `{"ok":true,"bytes":123}`.

Файловые ошибки: 400 — неверное имя или параметры; 403 — запрет записи;
404 — отсутствующий объект; 409 — существующая цель; 423 — занятый том;
503 — том или файловая система не готовы; 500 — другие ошибки FatFs.
Число FatFs включается в описание ошибки. При сетевом обрыве ответ может
отсутствовать; частичный целевой файл сохраняется для проверки. Операции
не транзакционные и не откатывают уже записанные данные. Повторы не
выполняются автоматически. Форматирование этим API не предоставляется.
