# Подсистема MDIO

В FreeRTOS MDIO — штатная часть BVSTK: собирается вместе с приложением,
запускается после загрузки конфигурации и обслуживает ESP32 ↔ LAN8720 без
процесса-посредника на компьютере. Подсистема использует существующий
аппаратный интерфейс PL. RMII и REF_CLK соединены напрямую; через Zynq
проходят только MDC/MDIO.

## Слои

- [Драйвер](../../../src/drivers/pl/mdio/bvstk_mdio_core.c): MMIO, FIFO, BRAM,
  таймауты, подтверждение завершений. Не зависит от ОС.
- [Сервис](../../../src/services/mdio/bvstk_mdio_service.c): единая политика
  записи, кэш с признаком достоверности, настройки, счётчики, обработка
  входных записей и ограниченный шаг фоновой работы.
- [Конфигурация и политика](../../../src/shared/config/bvstk_mdio_config_codec.c):
  строгий ограниченный JSON и правила по 16-битным значениям.
- [Адаптер FreeRTOS](../../../src/ports/freertos-xilinx/os/mdio/bvstk_mdio_freertos.c):
  задача mdio, точные часы аппаратного драйвера, уступка CPU между проходами.
- [Shell](../../../src/apps/freertos/console/mdio_shell.c): общий обработчик
  для UART, TCP и SSH; общая грамматика дополнения команд.
- DCP2, shell и входные записи PL вызывают один сервис. Сервис и драйвер
  имеют разные mutex; операции с PHY не выполняются в ISR.

В Нейтрино переносимые компоненты компилируются, но bvstkd пока не
запускает MDIO-worker. Общие исходники не означают готовый MDIO runtime
для этой ОС.

## Неизменяемый аппаратный контракт

| Окно | Адрес / назначение |
|---|---|
| Master | 0x43C10000, размер 0x10000 |
| Slave | 0x43C20000, размер 0x10000 |
| BRAM | 0x42000000, размер 0x4000 |
| BRAM + 0x0000 | Результаты физических чтений master |
| BRAM + 0x1000 | Последние записи ESP32 по каждому PHY/регистру |
| BRAM + 0x2000 | Ответы slave из кэша |

Индекс слова: ((phy << 5) | reg) * 4, PHY/регистр 0..31.
В FIFO master по +0x0C записывается
(write << 26) | (phy << 21) | (reg << 16) | value.

Чтение ожидает bit 0 CSR **master**, проверяет адрес результата через
MEM_ADDR +0x10 и забирает 16-битное значение из BRAM. Подтверждение:
сначала чтение MEM_ADDR, затем запись 1 в IRQ +0x08. Чтение самого
IRQ-регистра не заменяет эту последовательность. На ошибке сбрасывается
только master; незавершённая запись автоматически не повторяется.

Запись ждёт завершения кадра. У текущего ядра нет доступного PS
подтверждения приёма записи самим PHY. OK означает отправленный кадр,
а не гарантированное применение значения. Сервис обновляет кэш чтением
реального регистра, а не записанной командой: RESET/RESTART могут
самостоятельно сбрасываться.

В XSA аппаратные экземпляры имеют имена SMI. Эти внешние
XPAR_SMI_* используются только для проверки аппаратного контракта;
PS-команды, типы, функции, каталоги и DCP2-клиент называются mdio.
PS-адрес I²C slave — 0x43C50000; его окно не пересекается с MDIO master.

## Обработка входных записей и ограничения PL

Worker просматривает банк последних записей, пропускает только
сконфигурированные PHY и проверяет политику перед каждой передачей.
За шаг обрабатываются не более четырёх записей и один элемент опроса
(проверка идентификатора требует двух чтений).

После потребления слово помечается 0x00010000. PL записывает только
нулевое расширение 16-битного значения, поэтому следующая запись того же
значения тоже обнаруживается. Это не FIFO: повторные записи до
потребления, гонка между чтением и установкой метки, порядок между
разными регистрами могут теряться. Счётчик observed считает потреблённые
ячейки; точное число потерь и всех кадров на проводе неизвестно.

Отказ политики не передаётся ESP32 как ошибка MDIO: у Clause 22 write
нет такого ответа в имеющемся интерфейсе. PHY не получает запрещённую
запись, кэш не заменяется запрещённым значением, отказ виден в shell
и уведомлениях DCP2.

## Политики, кэш и настройки

Правило {reg,val,mask} совпадает при одинаковом номере регистра и
(value & mask) == (val & mask). По умолчанию mask=65535 — точное
16-битное значение. Mask=0 — любые значения указанного регистра.
Whitelist разрешает совпадения, blacklist запрещает их. Пустой whitelist
запрещает все записи; неизвестный режим и недопустимая конфигурация
не принимаются. Наборы правил независимы; режим задаётся через policy set.

Кэш хранит значение, valid, источник (PHY или settings) и время обновления.
Недействительный ответ публикуется в slave как 0xFFFF. На ошибке чтения
прежнее значение не выдаётся как свежее. При reg_count >= 4 ID-регистры проверяются при старте
и примерно раз в секунду; отсутствие PHY вызывает очистку кэша и повторную
проверку. Это действует и при autopoll off. Остальные регистры обновляются
по списку и задержкам конфигурации. При нескольких PHY и загрузке задержка
может увеличиваться; это не точное зеркало PHY и не гарантия реального
времени. Регистры с latch/read-clear семантикой сохраняют свои особенности;
список опроса выбирает администратор.

Settings — явные начальные значения **кэша**, не команды физическому PHY.
Изменение settings обновляет кэш; физические записи и опрос не записывают
туда RESET, RESTART или текущий статус. Опрос заменяет начальные значения
реальными. Изменения shell применяются в RAM; save сохраняет снимок
в flash:/config/mdio/<device>.json.

При первом запуске импортируются прежние config/smi и configs/smi,
без удаления исходных файлов и без замены существующих MDIO-конфигов.
Старые write_allow_regs/write_deny_regs преобразуются в правила с mask=0;
save записывает новый формат. Маркер .initialized предотвращает
повторный импорт старых SMI-файлов. Существующие задержки опроса сохраняются,
даже если отличаются от встроенных новых настроек.

Некорректный/нечитаемый конфиг, дублирующий PHY или недоступная QSPI
отключают forwarding; ошибочный файл не заменяется разрешающими defaults.
При сохранении остаётся предыдущая версия .json.bak, восстанавливаемая,
если основной файл отсутствует при загрузке. Это не защита от произвольной
порчи всей FAT или привилегированного редактирования файлов.

Политика защищает **обычные MDIO-пути**, а не весь доступ к SoC.
Привилегированные mem, DCP2 MEM и JTAG могут обходить сервис и мешать
его владению MMIO. Не предоставляйте эти интерфейсы недоверенным клиентам.
Отдельная HTTP-диагностика MDIO не добавляется.

## Команды и проверка

    mdio status
    mdio list
    mdio lan8720 r 2
    mdio lan8720 r 3
    mdio lan8720 r 1
    mdio lan8720 cache show
    mdio lan8720 policy show rules
    mdio lan8720 autopoll cycle_delay 50
    mdio lan8720 save

Идентификаторы PHY читаются из регистров 2 и 3 и сравниваются с
документацией выбранного PHY. Адрес задаётся полем phy_addr конфигурации.
Bit 2 BMSR (регистр 1) показывает link; это только одно из условий
работающего Ethernet. Для проверки разрешённой записи выбирайте
документированный обратимый регистр и восстанавливайте его значение.
Не используйте RESET или неизвестные регистры как безобидный тест.

    ./build.sh check
    ./build.sh freertos
    python3 scripts/dcp2/dcp2_client.py <адрес-BVSTK> --mdio-read <PHY> 2
    python3 scripts/dcp2/dcp2_client.py <адрес-BVSTK> --mdio-read <PHY> 3
    python3 scripts/dcp2/dcp2_client.py <адрес-BVSTK> --buses mdio

В командах замените `<адрес-BVSTK>` и `<PHY>` фактическими сетевым адресом
системы и адресом PHY.

[Host-тесты](../../../tests/host/test_mdio.c) покрывают MMIO/ACK, устаревший
ответ, таймаут и восстановление, политики, повторные одинаковые записи,
кэш, строгий JSON и дополнение.

Аппаратная проверка включает:

1. Автономную инициализацию PHY со стороны ESP32, установление link и
   получение IP-адреса по DHCP при наличии DHCP-сервера в сети.
2. Чтение через shell и DCP2, обратимую запись разрешённого регистра
   с восстановлением исходного значения и проверку запретов обеих политик.
3. Публикацию, очистку и обновление кэша ответов slave.
4. Сохранение конфигурации и её загрузку после перезапуска, а также
   отключение передачи записей при некорректной конфигурации.

Аппаратные ограничения PL этими тестами не устраняются.

Синтаксис — в [консольном справочнике](../../reference/console-commands.md),
JSON — в [конфигурации](../../reference/configuration.md).
