# Проверки и свидетельства

Проверка должна соответствовать изменению. Для правки документации не
нужна перезагрузка платы; для смены IRQ недостаточно компиляции на
компьютере. В отчёте отдельно указывают, что выполнено, что только
сверено с исходниками и что осталось непроверенным на оборудовании.

## Проверки на компьютере

```sh
./scripts/check_docs.sh
./tests/host/run.sh
./build.sh check
```

Последняя команда уже включает две первые и архитектурные проверки;
запускать все три подряд обычно не требуется. Документальная проверка
проходит по корневому README, `docs`, Markdown в `scripts` и `third_party`,
проверяет локальные пути и известные устаревшие формулировки. Она не
доказывает истинность текста, корректность каждого якоря или читаемость SVG.

`tests/host/run.sh` компилирует C11 с предупреждениями как ошибками и
запускает общие тесты, дополнение I²C, редактор строки и Python-проверку
DCP2 FS с тестовым сервером. Временные исполняемые файлы удаляются
сценарием после завершения. Набор включает модели PL, кэш, политику,
сервисы и кодеки, но не реальное тактирование AXI и внешних линий.

Архитектурная проверка запрещает зависимости общего кода от ОС/BSP,
подключения `apps` нижними слоями, перекрёстные зависимости портов,
`../` в include и выбор цели через `__QNXNTO__`.

## Сборка целевых программ

После изменения общего C-кода проверяют обе цели:

```sh
./build.sh freertos
./build.sh neutrino
```

Изменение состава образа Нейтрино требует также `neutrino-image`.
SSH-вариант FreeRTOS проверяют с включёнными зависимостями и секретом
из защищённого окружения. Не используйте опубликованный тестовый пароль
для постоянно подключённого устройства.

Фиксируйте код завершения и наличие ожидаемого ELF/IFS. Успех компиляции
означает совместимость исходников с выбранными инструментами, но не
работоспособность периферии.

## Испытание платы

До JTAG сохраните ревизии и контрольные суммы входов, остановите записи
на носители. После загрузки выполните
[первое подключение](../operations/README.md), затем проверку изменённой
подсистемы. `pl list` — чтение таблицы, не аппаратное обнаружение;
`pl probe` может затрагивать выключенные регионы и не должен быть
обязательным безусловным тестом текущего профиля.

Для I²C отдельно проверяют ведущий обмен, ведомый IRQ/ответ, политику,
ошибочные диапазоны, тайм-аут и сохранение после перезапуска. Запись
выбирают по документации конкретного подключённого устройства. Для FS
проверяют пустой каталог, вложенное дерево, двоичный файл, TAR, повтор
блока, ошибку пути, обрыв и изменение исходника. Доступный тестовый поток
DCP2 не считается аппаратным тестом шины.

Интерактивное дополнение проверяют отдельно: в FreeRTOS UART/TCP/SSH
используют `i2c <Tab>`, `i2c axp15060 <Tab>`, `i2c axp15060 p<Tab>` и
`cd fl<Tab>`; в Нейтрино — те же сценарии для его терминала.
Проверка неинтерактивной команды по SSH не покрывает редактор терминала.

## Отчёт

Укажите дату, плату и подключённые устройства, ОС, ревизии двух
репозиториев, локальные изменения, версии инструментов и параметры сборки
без секретов. Для каждого теста сохраните команду, ожидаемый результат,
наблюдаемый ответ и итог. При отказе приложите достаточный участок журнала,
а не только вывод последней попытки.

Для документации дополнительно проверяют переход от главного оглавления
ко всем активным страницам, ссылки и якоря, изображения при масштабе
чтения, подписи и соответствие полей реализации. Исходники рисунков и
проверка их отображения перечислены в [указателе рисунков](../figures.md).
