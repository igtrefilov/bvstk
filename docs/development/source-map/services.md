# services

[Карта исходников](../source-map.md)

В [src/services](../../../src/services) находятся операции подсистем
и их рабочее состояние. Сервис связывает запрос с конкретным устройством,
проверяет условия выполнения, обращается к драйверу и обновляет состояние.
Один экземпляр сервиса может обслуживать несколько внешних интерфейсов.
Создание экземпляров и их подключение выполняет [приложение](apps.md).

## services/i2c

I²C разделён на реестр устройств, политику, кэш и два сервиса.
Ведущий сервис выполняет операции с устройством. Ведомый трактует
кадр внешнего ведущего и использует тот же ведущий сервис для
операций, которым нужен физический обмен. Благодаря этому проверка
записи сосредоточена в общем месте.

| Файл | Назначение |
|---|---|
| [bvstk_i2c_devices.h](../../../src/services/i2c/bvstk_i2c_devices.h) | Описывает устройство, его адрес и диапазон регистров; задаёт интерфейс реестра устройств. |
| [bvstk_i2c_devices.c](../../../src/services/i2c/bvstk_i2c_devices.c) | Создаёт реестр из конфигурации, проверяет записи и ищет устройство по имени или адресу. |
| [bvstk_i2c_policy.h](../../../src/services/i2c/bvstk_i2c_policy.h) | Определяет рабочие списки разрешений и запретов, режим политики и операции изменения правил. |
| [bvstk_i2c_policy.c](../../../src/services/i2c/bvstk_i2c_policy.c) | Проверяет допустимость записи пары «регистр, значение», изменяет режим и содержимое списков правил. |
| [bvstk_i2c_cache.h](../../../src/services/i2c/bvstk_i2c_cache.h) | Описывает сохранённые значения, их достоверность, происхождение из настроек и время обновления. |
| [bvstk_i2c_cache.c](../../../src/services/i2c/bvstk_i2c_cache.c) | Читает и обновляет кэш, загружает начальные значения, сбрасывает достоверность и уведомляет наблюдателя об изменениях. |
| [bvstk_i2c_master_service.h](../../../src/services/i2c/bvstk_i2c_master_service.h) | Определяет ведущий сервис, подключаемый источник аппаратных операций и интерфейс управления устройствами, кэшем и политиками. |
| [bvstk_i2c_master_service.c](../../../src/services/i2c/bvstk_i2c_master_service.c) | Проверяет запросы и политику, выполняет чтение или запись, обновляет кэш и доступность устройства, публикует события. |
| [bvstk_i2c_slave_service.h](../../../src/services/i2c/bvstk_i2c_slave_service.h) | Определяет выбранное устройство, указатель регистра и состояние подготовки ответа внешнему ведущему. |
| [bvstk_i2c_slave_service.c](../../../src/services/i2c/bvstk_i2c_slave_service.c) | Разбирает принятую запись, меняет указатель регистра и готовит окно чтения. При отсутствии нужного значения в кэше обращается к ведущему сервису. |

Изменение правил относится к `bvstk_i2c_policy.c`; момент их проверки
при записи определяется в `bvstk_i2c_master_service.c`. При работе
с кэшем важно различать сохранённое значение и признак его достоверности.
Связь этих модулей прослеживается на транзакции в
[главе сервисов I²C](../../system/pl-subsystem/i2c/services/services.md).

## services/mdio

Сервис MDIO хранит конфигурации PHY, политику, кэш и расписание опроса
в одном объекте. Его шаг обработки принимает записи ведомой стороны,
проверяет доступность устройств и обновляет выбранные регистры.
Проверка правил использует общую модель конфигурации MDIO.

| Файл | Назначение |
|---|---|
| [bvstk_mdio_service.h](../../../src/services/mdio/bvstk_mdio_service.h) | Определяет состояние PHY, кэш, статистику, аппаратные операции и интерфейс управления политиками и опросом. |
| [bvstk_mdio_service.c](../../../src/services/mdio/bvstk_mdio_service.c) | Обрабатывает запросы к PHY и записи внешнего ведущего, применяет правила, проверяет присутствие устройства и публикует обновления кэша в BRAM. |

Периодические вызовы этого сервиса организует порт ОС. В текущем
FreeRTOS для этого существует `ports/freertos-xilinx/os/mdio`.
Последовательность обработки описана в
[главе сервисов MDIO](../../system/pl-subsystem/mdio/services/services.md).

## services/sd

Сервис карты и описание FAT-тома выполняют разные части работы.
Первый управляет состоянием SD и командами по секторам. Второй находит
том и переводит его логические секторы в адреса секторов карты.
Файловые операции выше этой границы выполняет файловая система ОС.

| Файл | Назначение |
|---|---|
| [bvstk_sd_service.h](../../../src/services/sd/bvstk_sd_service.h) | Описывает состояние карты, результат операции и интерфейс блочного доступа, включая передачу владения файловой системе. |
| [bvstk_sd_service.c](../../../src/services/sd/bvstk_sd_service.c) | Инициализирует карту через ведущий драйвер, выбирает адресацию, выполняет чтение и запись с проверкой результата, согласует доступ к карте. |
| [bvstk_sd_volume.h](../../../src/services/sd/bvstk_sd_volume.h) | Определяет расположение FAT-тома и интерфейс поиска тома через переданную функцию чтения сектора. |
| [bvstk_sd_volume.c](../../../src/services/sd/bvstk_sd_volume.c) | Разбирает загрузочный сектор и таблицу разделов, находит поддерживаемый FAT-том и проверяет перевод запросов в физические LBA. |

Связь с драйвером и файловой системой показана в
[главе сервисов SD](../../system/pl-subsystem/spi/services/services.md).

## services/control

Общий вход к подключённым экземплярам подсистем. Он хранит ссылки
на доступные сервисы и драйверы, чтобы обработчик команды мог обратиться
к ним через единый объект управления. Состав объекта задаёт приложение.

| Файл | Назначение |
|---|---|
| [bvstk_control_api.h](../../../src/services/control/bvstk_control_api.h) | Определяет набор подключённых PL, I²C, MDIO и SPI и объявления операций управления ими. |
| [bvstk_control_api.c](../../../src/services/control/bvstk_control_api.c) | Проверяет наличие нужного экземпляра и передаёт ему запрос чтения, записи или обмена. |

## services/cache

Общий реестр кэша предоставляет внешним интерфейсам единое представление
разных подсистем: снимок устройства и последовательность изменений.
Кэш конкретной шины остаётся у её сервиса. Файлы `bvstk_cache_bridges`
связывают эти два представления через уведомления об изменениях.

| Файл | Назначение |
|---|---|
| [bvstk_cache.h](../../../src/services/cache/bvstk_cache.h) | Определяет реестр устройств, записи снимка, поколения конфигурации и журнал изменений. |
| [bvstk_cache.c](../../../src/services/cache/bvstk_cache.c) | Регистрирует устройства, принимает обновления, формирует согласованный снимок и выдаёт изменения после заданной позиции. |
| [bvstk_cache_bridges.h](../../../src/services/cache/bvstk_cache_bridges.h) | Описывает связи реестра с сервисами I²C и MDIO и операции их подключения. |
| [bvstk_cache_bridges.c](../../../src/services/cache/bvstk_cache_bridges.c) | Переводит регистры и изменения состояния I²C и MDIO в записи общего реестра, назначает им имена из профилей. |

Доступ по DCP2 реализует `protocols/dcp2/bvstk_dcp2_cache.c`.
Протокольные снимки и подписки объяснены в
[описании CACHE](../../reference/dcp2/07-cache.md).

## services/fs

Общий читатель получает операции файловой системы через таблицу функций.
Он может выдавать содержимое файла, описание дерева каталогов или
TAR-поток. Это позволяет обработчику DCP2 работать с файлами без
прямой зависимости от FatFs.

| Файл | Назначение |
|---|---|
| [bvstk_fs_reader.h](../../../src/services/fs/bvstk_fs_reader.h) | Задаёт интерфейс файлового адаптера и состояние последовательного чтения файла или каталога. |
| [bvstk_fs_reader.c](../../../src/services/fs/bvstk_fs_reader.c) | Проверяет путь и UTF-8, обходит каталоги, читает данные порциями и при необходимости формирует TAR. |

Конкретный адаптер FatFs находится в
`apps/freertos/storage/fs/fs_dcp2_backend.c`. Управление сеансом
чтения по сети выполняется в [protocols/dcp2](protocols.md).
