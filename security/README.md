# Материалы проверки подписей

Каталог `security/` хранит материалы проверки подписей для `flash:/security/`
(в Нейтрино — `/flash/security/`). При установке сохраняются относительные
пути файлов. Как и `configs/`, дерево явно
разрешено для отслеживания Git в корневом `.gitignore`.

```text
security/
├── trust/
│   ├── anchors/
│   └── crl/
└── signatures/
    └── uid/
```

`README.md` описывает комплект и не требуется на плате. Подписи других
типов объектов добавляются в `signatures/<тип>/`, например `firmware/`
или `config/`. Пустые каталоги заранее не создаются.

## Назначение файлов

| Путь | Содержимое и назначение |
|---|---|
| `trust/anchors/*.pem` | Заранее доверенные корневые сертификаты УЦ в PEM. |
| `trust/crl/*.crl` | Списки отзыва корневых и промежуточных УЦ в DER. |
| `signatures/<тип>/*.sig` | Отсоединённые подписи CMS/PKCS#7 в DER. Могут содержать сертификаты подписанта и промежуточных УЦ. |

UID при проверке читается физически из EEPROM P24C02A, адреса `0x00–0x0F`.
Подписанные конфигурации и образы также остаются на своих штатных местах;
в `signatures/` находятся только подписи. Сертификат, включённый в подпись,
сам по себе не является доверенным. Допустимые подписанты для UID,
конфигураций и образов должны задаваться политикой соответствующей проверки.

Подпись UID проверяется над исходными 16 байтами без консольного
оформления, перевода строки и завершающего NUL.

## Обновление и установка

Приватные ключи для проверки не нужны и в этот каталог не помещаются.
Текстовые файлы PEM хранятся с переводами строк LF.

При обновлении CRL проверяются подпись УЦ и сроки действия. Для проверки
сроков сертификатов и CRL требуется корректное время платы. Замена корня
в `trust/anchors/` меняет доверие системы и должна быть осознанной;
сама папка во flash не защищает файлы от подмены.

Изменение файлов в репозитории или сборка программы не обновляют файлы
на работающей плате автоматически. Установка выполняется отдельно,
с сохранением относительных путей и проверкой обратным чтением.
